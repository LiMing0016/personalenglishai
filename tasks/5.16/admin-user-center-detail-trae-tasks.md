# Admin 用户 360 详情页前端 Trae 题目

## 背景

用户 360 详情页用于深度排查单个用户。页面不应该是一屏长表单，而应该按账号、学习、订阅、作文、AI 和审计分模块组织。

设计稿：

<https://www.figma.com/design/etopP4oRFZh65MKkszGaR3>

目标路由：

```text
/admin/users/:id
```

主要文件：

- `web/src/pages/admin/AdminUserDetailPage.vue`
- `web/src/api/admin.ts`

---

## 题目 1：详情页顶部身份和 KPI 区

难度：中等

### Prompt

请改造 `/admin/users/:id` 顶部区域，使其接近 Figma 的用户 360 详情页。顶部需要包含返回入口、用户身份卡、状态标签和关键指标卡。

顶部内容：

- 返回用户中心。
- 用户昵称、邮箱或手机号、头像缩写。
- 用户状态、学段、管理员角色标签。
- 账号状态 KPI。
- 当前权益 KPI。
- 额度使用 KPI。
- 写作活跃 KPI。
- AI 使用 KPI。
- 治理记录 KPI。

### 验收标准

- 首屏能看清用户身份和关键状态。
- 返回按钮回到 `/admin/users`。
- 状态、学段、角色使用标签展示。
- KPI 卡片数量和布局在宽屏下稳定。
- 窄屏下 KPI 自动换行，不发生文字重叠。
- 空字段显示 `-`。

---

## 题目 2：详情页 Tabs 结构

难度：中等

### Prompt

请把用户详情页改造成标签页结构。Tabs 用于降低单页信息密度，并和 Figma 中“概览、账号资料、学习画像、订阅与额度、作文与评测、AI 使用记录、审计日志、原始数据”的组织一致。

Tabs：

- 概览。
- 账号资料。
- 学习画像。
- 订阅与额度。
- 作文与评测。
- AI 使用记录。
- 审计日志。
- 原始数据。

### 验收标准

- 默认进入“概览”。
- 点击 tab 不刷新页面。
- 当前 tab 有清晰高亮。
- tab 内容区域不嵌套多层卡片。
- 原始数据 tab 后续需要权限控制；当前至少不要展示敏感凭证。
- 窄屏下 tab 可横向滚动。

---

## 题目 3：概览 Tab 模块卡片

难度：中等

### Prompt

请实现详情页“概览”Tab，按 Figma 卡片结构展示 6 个模块：账号资料、学习画像、订阅与额度、作文与评测、AI 使用记录、审计日志。

### 验收标准

- 账号资料卡展示 ID、邮箱、手机号脱敏、状态、创建时间、最近活跃。
- 学习画像卡展示学段、AI 模式、样本数、画像置信度、最近更新时间。
- 订阅与额度卡展示套餐、订阅状态、周期、额度进度条、是否超额。
- 作文与评测卡展示最近 3-4 条评测摘要。
- AI 使用记录卡展示最近 3-4 条模型调用摘要。
- 审计日志卡展示最近 5 条操作摘要。
- 每个卡片都有空状态。
- 每个卡片都有进入对应 tab 或业务模块的轻量入口。

## 题目 4：账号治理操作保留

难度：中等

### Prompt

请在“账号资料”Tab 中保留现有用户治理能力，包括修改用户状态和管理员角色。改版不能破坏原有保存逻辑。

### 验收标准

- 可以切换用户状态：active、disabled。
- 可以保存管理员角色：super_admin、support_admin、content_admin。
- 保存成功显示成功提示。
- 保存失败显示错误提示。
- 保存后页面状态刷新或本地状态同步。
- 不允许普通字段编辑误触发治理请求。

---

## 题目 5：详情页原始数据和安全展示

难度：简单

### Prompt

请整理“原始数据”Tab 的展示方式。当前阶段只允许展示脱敏后的 JSON 或排查字段摘要，不能泄露密码、token、验证码、Cookie、Authorization 或数据库连接信息。

### 验收标准

- 原始数据使用 `<pre>` 或等效代码块展示。
- 敏感字段必须隐藏、删除或显示为 `***`。
- 页面有“复制原始数据”按钮时，复制内容也不能包含敏感字段。
- 无权限时隐藏原始数据 tab 或显示无权限说明。
- `npm run build` 通过。

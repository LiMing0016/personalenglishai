# 管理员数据清洗中心词典探查 Trae 题目

## 背景

当前项目需要建设一个管理员端“数据清洗中心”，用于把外部学习资料先纳入可治理、可审计、可逐步清洗的后台入口。第一版先只做词典相关内容，不要求全量解析 MDX/MDD 词条，也不要求把词典内容发布到用户单词页。

本轮目标是：

- 管理员可以登记词典数据源。
- 管理员可以创建词典探查任务。
- 后端可以读取 MDX/MDD header 和 XLSX 例句表基础元信息。
- 管理员端可以查看数据源、任务记录和最近探查结果。
- 数据库要有可持续扩展的清洗源表和任务表。

核心原则：

- 不新增生产鉴权绕过。
- 不在请求中做全量词条解析。
- 不引入不必要的大型依赖，优先用现有 Spring Boot / MyBatis / JDK 能力完成首版探查。
- 路径是后端服务器本地路径，不是浏览器本地文件上传。
- 未确认授权前，词典数据只能作为内部验证资产，不发布给用户侧。

## 题目 1：设计数据清洗中心词典表结构

难度：中等偏难

### A 小题：新增数据清洗源表

请新增 `data_cleaning_source` 表，用于登记外部词典文件来源。

字段至少包含：

- `id`
- `source_uid`
- `source_type`
- `source_code`
- `display_name`
- `license_status`
- `mdx_path`
- `mdd_path`
- `examples_path`
- `cover_image_path`
- `metadata_json`
- `status`
- `created_by`
- `created_at`
- `updated_at`

要求：

1. `source_uid` 唯一。
2. `source_code` 唯一。
3. `source_type` 首版支持 `dictionary`。
4. `license_status` 支持 `unknown`、`internal_only`、`licensed`、`blocked`。
5. `status` 支持 `registered`、`probed`、`imported`、`disabled`。

### B 小题：新增数据清洗任务表

请新增 `data_cleaning_job` 表，用于记录数据源探查、清洗、导入任务。

字段至少包含：

- `id`
- `job_uid`
- `source_uid`
- `job_type`
- `status`
- `progress_total`
- `progress_done`
- `result_json`
- `error_message`
- `created_by`
- `started_at`
- `finished_at`
- `created_at`
- `updated_at`

要求：

1. `job_uid` 唯一。
2. `source_uid` 关联 `data_cleaning_source.source_uid`。
3. `job_type` 首版支持 `dictionary_probe`。
4. `status` 支持 `pending`、`running`、`completed`、`failed`。
5. 提供单独 migration SQL，并同步更新 `schema.sql`。

### 给 Trae 的 Prompt

请为管理员数据清洗中心新增词典相关数据库表。第一张表 `data_cleaning_source` 用来登记词典数据源，第二张表 `data_cleaning_job` 用来记录探查任务。请提供 migration SQL，并同步更新 `schema.sql`。注意字段要支持后续全量解析、清洗和发布扩展，但本题不要求实现全量词条表。

### 验收标准

- 存在 `data_cleaning_source` 和 `data_cleaning_job` 建表 SQL。
- `schema.sql` 和 migration 文件都包含这两张表。
- 关键唯一索引和外键约束存在。
- 表注释和字段注释能说明用途。
- 不修改现有核心业务表结构。

## 题目 2：实现后端词典数据源与探查任务 API

难度：困难

### A 小题：新增词典数据源接口

请新增管理员端接口，用于创建和查询词典数据源。

建议接口：

- `GET /api/admin/data-cleaning/overview`
- `GET /api/admin/data-cleaning/sources?sourceType=dictionary`
- `POST /api/admin/data-cleaning/dictionary-sources`

创建词典源的 body 至少包含：

- `sourceCode`
- `displayName`
- `licenseStatus`
- `mdxPath`
- `mddPath`
- `examplesPath`
- `coverImagePath`

要求：

1. 需要管理员权限。
2. `sourceCode` 和 `displayName` 必填。
3. `mdxPath`、`mddPath`、`examplesPath` 至少填写一个。
4. 创建后默认 `source_type=dictionary`、`status=registered`。

### B 小题：新增词典探查任务接口

请新增词典探查任务接口。

建议接口：

- `GET /api/admin/data-cleaning/jobs?jobType=dictionary_probe`
- `POST /api/admin/data-cleaning/dictionary-probe-jobs`
- `GET /api/admin/data-cleaning/jobs/{jobUid}`

要求：

1. `POST /dictionary-probe-jobs` 通过 `sourceUid` 创建任务。
2. 校验数据源存在且 `source_type=dictionary`。
3. 探查任务首版可以同步执行。
4. 探查成功后任务状态为 `completed`。
5. 探查失败后任务状态为 `failed`，写入 `error_message`。
6. 探查成功后更新数据源 `metadata_json` 和 `status=probed`。

### 给 Trae 的 Prompt

请实现管理员数据清洗中心后端 API。接口需要支持词典数据源创建、数据源列表、任务列表、创建词典探查任务、查看单个任务。按现有 admin controller -> service -> mapper 分层实现，并接入管理员权限校验。首版探查任务可以同步执行，不需要异步队列。

### 验收标准

- 管理员接口路径统一在 `/api/admin/data-cleaning` 下。
- 无权限用户不能访问读写接口。
- 创建词典源参数校验有效。
- 创建探查任务后能生成任务记录。
- 探查成功和失败都有明确状态。
- Controller 中不堆业务逻辑，核心逻辑在 Service。

## 题目 3：实现 MDX/MDD 与 XLSX 轻量探查

难度：困难

### A 小题：读取 MDX/MDD header 元信息

请实现 MDX/MDD 文件的轻量探查。

要求：

1. 不全量读取大文件。
2. 只读取前 4 字节 header 长度和 header 内容。
3. 支持 UTF-16BE / UTF-16LE header 解码。
4. 提取 header attributes。
5. 结果至少包含：
   - `kind`
   - `path`
   - `fileName`
   - `fileSizeBytes`
   - `headerLength`
   - `root`
   - `title`
   - `format`
   - `encoding`
   - `encrypted`
   - `creationDate`
   - `entryCount`
   - `attributes`

### B 小题：读取 XLSX 例句表元信息

请实现 XLSX 例句表轻量探查。

要求：

1. 不引入 Apache POI 等重依赖，优先用 JDK `ZipFile` 读取 XLSX 内部 XML。
2. 读取 `xl/workbook.xml` 获取 sheet 名称。
3. 读取第一张表的 dimension 获取行列数。
4. 读取第一行字段名，支持 sharedStrings。
5. 结果至少包含：
   - `kind`
   - `path`
   - `fileName`
   - `fileSizeBytes`
   - `sheets`
   - `rowCount`
   - `columnCount`
   - `headers`

### 给 Trae 的 Prompt

请为数据清洗中心实现词典文件轻量探查能力。MDX/MDD 只读取 header，不做全量词条解析；XLSX 只读取 workbook、worksheet 和 sharedStrings 元信息，不引入重型 Excel 依赖。探查结果写入任务 `result_json`，并同步更新数据源 `metadata_json`。

### 验收标准

- 大 MDX/MDD 文件不会被完整读入内存。
- MDX header 能解析出标题、格式、编码、词条数等字段。
- MDD header 能解析出标题和资源库信息。
- XLSX 能解析出 sheet、行数、列数和第一行表头。
- 文件不存在、扩展名不对、header 异常时任务进入 `failed`。
- 探查结果是结构化 JSON。

# 客户端写作看板横向菜单改版 Trae 题目

## 背景

当前 `/app/writing/dashboard` 把写作总览、成长激励、能力曲线、错误分析、主题风格、练习记录等板块纵向堆叠在一个长页面里。用户查看后面的内容时需要持续向下滚动，信息查找成本高。

本轮目标是把这些大板块改成类似管理员用户详情页的横向菜单：

```text
写作总览 / 成长激励 / 能力曲线 / 错误分析 / 主题风格 / 练习记录 / AI建议
```

用户点击菜单后，只展示当前板块内容，不再把所有模块纵向铺开。

参考文件：

- `web/src/pages/app/WritingPage.vue`
- `web/src/components/writing/dashboard/WritingOverviewCard.vue`
- `web/src/pages/app/writingDashboardMock.ts`
- `web/tests/writingDashboardPrototype.test.ts`
- `web/src/router/index.ts`
- `web/AGENTS.md`

核心原则：

- 只改写作 Dashboard，不影响写作编辑器主链路。
- 不改后端 API 契约，继续使用现有 `getWritingDashboard` 数据。
- 横向菜单要比普通文字 Tab 更精致：图标、胶囊高亮、细边框、轻阴影、sticky。
- 每次只展示一个主板块，减少纵向滚动。
- ECharts 图表必须在 Tab 切换后正确渲染，不能空白、错位或重复初始化。
- 移动端菜单横向滚动，内容不能横向溢出。

## 题目 2：实现精致横向菜单 UI

难度：中等偏难

### A 小题：新增横向菜单模板

请在 Dashboard 标题区和内容区之间新增横向菜单。

视觉要求：

1. 菜单位于一个浅色圆角容器中。
2. 容器有 `1px` 边框、轻阴影、半透明白色背景。
3. 每个菜单项包含一个小图标占位和中文标题。
4. 当前选中项使用深绿色胶囊背景，文字为白色。
5. 未选中项使用深色文字，hover 时有浅绿色背景。
6. 菜单在页面滚动时 sticky 到顶部。

### B 小题：补齐响应式与可访问性

请补齐菜单的响应式和可访问性行为。

要求：

1. 桌面端菜单横向完整展示。
2. 窄屏时菜单横向滚动，不换成多行导致高度过大。
3. 使用 `button` 而不是纯 `div`。
4. 当前 Tab 有 `aria-selected="true"`。
5. 菜单容器有清晰的 `aria-label`。
6. 点击菜单后更新 `activeDashboardTab`。

### 给 Trae 的 Prompt

请为写作 Dashboard 实现一个精致的横向 Tab 菜单，位置在 Dashboard 标题和内容之间。菜单要有图标、胶囊高亮、轻阴影、sticky 和移动端横向滚动。点击 Tab 只更新当前选中状态，本题暂不拆分内容渲染。

### 验收标准

- 页面可见横向菜单，菜单文案完整。
- 当前 Tab 高亮明显，样式接近“精致管理端详情页 Tab”。
- 菜单 sticky 生效。
- 移动端宽度下不出现页面整体横向滚动。
- `npm run build` 不因模板或类型错误失败。

## 题目 3：把纵向模块拆成按 Tab 显示的内容面板

难度：困难

### A 小题：重组模板区域

请将原本纵向堆叠的 Dashboard 内容拆成多个 Tab 面板。

建议分组：

1. `overview`：`WritingOverviewCard`、总览 AI 建议。
2. `growth`：单篇得分趋势、分布分析、成长激励摘要。
3. `ability`：能力成长曲线、高频错误、词汇与句式。
4. `errors`：高频错误、错误类型解释、下一步修正建议。
5. `topic`：写作主题和风格、常练主题、体裁分布、推荐下一篇。
6. `practice`：最近作文、练习入口、继续写作。
7. `ai`：AI 建议、训练计划、推荐动作。

### B 小题：处理复用模块与空状态

部分内容可能同时适合多个 Tab，例如高频错误既适合能力分析，也适合错误分析。

要求：

1. 不要简单复制大段模板造成维护困难。
2. 可以抽出局部小块或使用同一数据渲染不同容器。
3. 每个 Tab 都要有空状态或说明文案。
4. 用户没有评分数据时，仍然能看到明确的下一步动作。
5. 页面整体纵向长度显著缩短。

### 给 Trae 的 Prompt

请把 `/app/writing/dashboard` 的长页面改成 Tab 面板：用户点击横向菜单后只显示对应板块内容。保留现有数据来源和视觉风格，不要改 API。注意复用内容不要大段复制，并为没有评分数据的状态保留清晰提示。

### 验收标准

- 默认只展示 `写作总览` 相关内容。
- 点击 `成长激励` 后不再显示 `写作总览` 的大图表。
- 点击 `主题风格` 后能看到主题、体裁和推荐下一篇。
- 页面不再把所有大模块连续纵向铺开。
- 没有数据时每个 Tab 都有可理解的空状态。

## 题目 4：修复 Tab 切换后的 ECharts 生命周期

难度：困难

### A 小题：梳理图表实例与可见性

请梳理当前 Dashboard 的 ECharts 初始化逻辑。

至少确认：

1. 写作总览图表实例。
2. 单篇得分趋势图表实例。
3. 分布分析图表实例。
4. 能力成长曲线图表实例。
5. 图表对应 DOM 在 Tab 切换时是否存在。

### B 小题：实现稳定的图表重绘

请调整图表生命周期，让图表在 Tab 切换后正确渲染。

要求：

1. 切换 Tab 后使用 `nextTick` 再初始化或 resize 当前可见图表。
2. 不对不存在的 DOM 初始化 ECharts。
3. 避免重复初始化造成内存泄漏。
4. 离开 Dashboard 或组件卸载时仍正确 dispose。
5. 浏览器窗口 resize 时当前可见图表尺寸正常。

### 给 Trae 的 Prompt

请修复写作 Dashboard 改成 Tab 后的 ECharts 生命周期。重点处理隐藏面板切换到可见时图表空白、尺寸错误、重复初始化和组件卸载释放问题。不要改图表业务数据，只改初始化、resize、dispose 的时机。

### 验收标准

- 在 `写作总览`、`成长激励`、`能力曲线` 间来回切换，图表都不空白。
- 控制台没有 ECharts 重复初始化警告。
- 刷新页面后默认 Tab 图表正常。
- 切换窗口尺寸后当前 Tab 图表自适应。
- 组件卸载时没有明显残留定时器或监听器。

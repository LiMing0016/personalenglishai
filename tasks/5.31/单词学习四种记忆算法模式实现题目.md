# 单词学习四种记忆算法模式实现题目

## 背景

当前 `/app/vocabulary` 已经具备单词搜索、本地词典详情、收藏、查询次数和学习模式静态入口。下一步需要把单词学习系统升级为“可选择记忆算法”的完整学习平台，让用户可以在不同记忆算法模式下学习单词，并比较不同算法的学习效果。

本题目要求同时设计并实现四种主流学习算法模式：

1. `simplified_srs`：简化 SRS / SM-2 风格间隔重复。
2. `fsrs`：FSRS 风格记忆状态模型。
3. `half_life_regression`：Half-Life Regression 半衰期预测模型。
4. `knowledge_tracing`：Knowledge Tracing 掌握度追踪模型。

这些算法都要接入统一的单词学习流程，用户可以选择算法模式，系统根据当前算法生成复习队列、更新记忆状态、展示算法解释，并沉淀训练数据。AI Agent 负责每天判断学习情况、解释算法建议和给出学习计划，但 Agent 不直接覆盖底层算法状态。

## 总体目标

1. 建立统一的记忆算法抽象层。
2. 支持四种算法模式并存。
3. 用户可以选择默认算法，也可以在学习 session 中选择算法。
4. 每种算法都能生成复习队列、更新状态、解释推荐原因。
5. 前端展示算法选择、算法说明、复习队列、学习结果和效果对比。
6. 后端保存算法状态、算法参数、预测结果和实验指标。
7. AI Agent 基于算法结果判断用户每天学习情况。

## 非目标

- 不要求第一版就达到商业级算法效果。
- 不要求真实训练深度学习模型上线。
- 不要求跨用户共享模型参数。
- 不要求给用户展示复杂数学公式。
- 不允许算法直接绕过用户隔离或读取其他用户数据。

## 题目 4：实现 Half-Life Regression 模式

题目类型：0-1代码生成

难度：高

### A 小题：实现 HLR 特征抽取和半衰期预测

#### 题目 Prompt

请实现 `half_life_regression` 模式的第一版。首版不要求训练真实机器学习模型，但必须建立完整的特征抽取、参数配置和预测结构。

特征至少包含：

- `reviewCount`
- `correctCount`
- `wrongCount`
- `elapsedHours`
- `lastIntervalDays`
- `spellingWrongRate`
- `wordLength`
- `wordFrequencyRank`，没有则为空。
- `difficultyScore`
- `sourceType`

预测输出：

- `halfLifeDays`
- `recallProbability`
- `recommendedReviewAt`
- `confidence`

首版可以使用可配置线性权重模拟 HLR：

```text
half_life = exp(w0 + w1*correctCount - w2*wrongCount + w3*log(reviewCount+1) ...)
recall_probability = 2 ^ (- elapsedDays / half_life)
```

#### 题目难度

高

#### 验收标准

- HLR 能抽取特征并生成半衰期预测。
- 权重可配置。
- recallProbability 会随 elapsedDays 增大而下降。
- 错误次数多会降低 halfLifeDays。
- 单测覆盖不同特征组合。

### B 小题：记录 HLR 预测效果并支持后续训练

#### 题目 Prompt

请为 HLR 模式记录预测效果，便于后续训练真实模型。

要求：

2. 用户实际答题后回填 `actual_result`。
3. 统计预测偏差：
   - 预测能记住但答错。
   - 预测会忘但答对。
4. 后端提供 HLR 效果摘要接口。

建议接口：

```http
GET /api/vocabulary-learning/algorithms/half-life-regression/evaluation
```

#### 题目难度

困难

#### 验收标准

- prediction log 能回填实际结果。
- 能统计 HLR 预测偏差。
- 前端或后台能看到 HLR 效果摘要。
- 不需要训练真实模型也能沉淀训练数据。

## 总体验收标准

完整实现后应满足：

1. 用户可以在四种记忆算法之间选择。
2. 四种算法都能生成复习队列。
3. 每种算法都有独立状态、预测记录和解释。
4. 学习 session 绑定算法和队列快照。
5. 答题结果能更新对应算法状态。
6. HLR 能记录预测偏差，KT 能更新 skill 掌握概率。
7. 前端能展示算法说明、单词级推荐原因和效果对比。
8. Vocabulary Learning Agent 能读取四种算法结果，判断用户每天学习情况，并建议是否切换算法。
9. 数据不足时系统保持保守，不误导用户。
10. 所有数据按用户隔离。
11. 前后端测试、文档和上线风险控制完整。

# 学习广场社区与每日打卡完整实现题目

## 背景

当前项目已经覆盖写作、单词、词典、学习资产等个人学习能力，但缺少用户之间的交流空间。下一步希望新增“学习广场”，让用户可以每天拍照上传自己的学习记录，也可以阅读别人分享的英语学习经验贴，形成学习打卡、经验交流、互相鼓励和内容沉淀。

这个功能不是简单页面，而是一个局部 0-1 社区模块，需要完整考虑：

- 发帖和图片上传。
- 学习打卡。
- 经验贴。
- 信息流。
- 评论、点赞、收藏。
- 标签和搜索。
- 内容审核、举报、屏蔽。
- 管理员后台治理。
- 图片安全和隐私。
- AI 识别学习照片。
- 数据统计和推荐。

## 产品定位

学习广场不是泛社区，而是英语学习社区。首版围绕两类内容：

1. **学习打卡**
   用户上传学习记录照片，例如笔记、单词本、作文草稿、阅读材料、听力记录，并记录今天学了什么。

2. **经验贴**
   用户分享英语学习方法，例如背单词经验、考研英语复盘、写作提分、听力训练、资料推荐。

## 首版核心目标

1. 用户可以发布学习打卡和经验贴。
2. 用户可以上传图片并在帖子中展示。
3. 用户可以浏览学习广场信息流。
4. 用户可以查看帖子详情、点赞、收藏、评论、举报。
5. 用户可以查看自己的打卡记录和连续打卡天数。
6. 管理员可以审核、下架和处理举报。
7. AI 可以对学习照片做 OCR/摘要/学习类型识别，作为后续增强。

## 非目标

- 不做私信。
- 不做复杂关注关系第一版。
- 不做直播、群聊、语音房。
- 不做公开排名刺激。
- 不做未经用户同意的人脸识别。
- 不把用户上传图片直接用于训练模型。

## 题目 1：学习广场领域建模与数据库总设计

题目类型：0-1代码生成

难度：高

### A 小题：设计核心帖子表

#### 题目 Prompt

请为学习广场新增核心帖子表 `learning_square_post`。字段至少包含：

- `id`
- `post_uid`
- `user_id`
- `post_type`：`checkin`、`experience`
- `title`
- `content`
- `visibility`：`public`、`followers`、`private`
- `status`：`draft`、`published`、`pending_review`、`hidden`、`deleted`
- `review_status`：`none`、`pending`、`approved`、`rejected`
- `tag_json`
- `ai_summary`
- `ai_detected_type`
- `like_count`
- `comment_count`
- `favorite_count`
- `view_count`
- `report_count`
- `published_at`
- `created_at`
- `updated_at`

要求：

1. `post_uid` 全局唯一。
2. 所有查询按 `user_id` 和 `status` 有合理索引。
3. `post_type` 要支持后续扩展，例如 `resource_share`。
4. 删除采用软删除，不物理删除。

#### 题目难度

高

#### 验收标准

- migration 和 `schema.sql` 都包含 `learning_square_post`。
- 字段、索引、枚举注释完整。
- 软删除状态可用。
- 不影响现有用户表。

### B 小题：设计媒体、互动、评论和举报表

#### 题目 Prompt

请补充学习广场相关表：

1. `learning_square_media`
   - 保存图片文件、缩略图、尺寸、大小、审核状态。
2. `learning_square_comment`
   - 支持帖子评论和一级回复。
3. `learning_square_reaction`
   - 支持点赞，唯一键 `user_id + post_uid + reaction_type`。
4. `learning_square_favorite`
   - 支持收藏。
5. `learning_square_report`
   - 支持举报帖子或评论。

要求：

1. 所有表都必须有 `uid` 字段。
2. 所有用户行为都按当前用户隔离。
3. 举报要记录 `reason_code`、`reason_text`、处理状态。
4. 评论支持软删除。

#### 题目难度

高

#### 验收标准

- 五张表结构完整。
- 点赞和收藏不会重复。
- 举报记录可追踪。
- 图片和帖子能通过 `post_uid` 关联。

## 题目 4：学习广场信息流 API

题目类型：feature迭代

难度：高

### A 小题：实现广场首页信息流

#### 题目 Prompt

请新增信息流接口：

```http
GET /api/learning-square/feed?tab=latest&page=1&size=20
```

支持 tab：

- `latest` 最新
- `hot` 热门
- `checkin` 学习打卡
- `experience` 经验贴
- `mine` 我的发布
- `favorites` 我的收藏

返回列表项包含：

- 作者基础信息
- 帖子摘要
- 图片缩略图
- 标签
- 点赞/评论/收藏数量
- 当前用户是否点赞/收藏

#### 题目难度

困难

#### 验收标准

- latest 按发布时间排序。
- hot 按热度排序。
- mine 只返回当前用户帖子。
- favorites 只返回当前用户收藏。
- 分页和总数正确。

### B 小题：实现热度排序和游标分页

#### 题目 Prompt

请为信息流实现热度分数和游标分页。热度分数可以按：

```text
score = like_count * 2 + comment_count * 3 + favorite_count * 4 + view_count * 0.2 - time_decay
```

要求：

1. 支持 `cursor` 分页，避免深分页性能问题。
2. hot 排序要考虑时间衰减，不能永久霸榜。
3. latest 可以继续使用 page/size 或 cursor。

#### 题目难度

困难

#### 验收标准

- hot 信息流排序稳定。
- cursor 下一页不会重复大量数据。
- 新帖能进入 latest。
- 老帖热度会自然下降。

## 总体验收标准

完整实现后应满足：

1. 用户可以发布学习打卡和经验贴。
2. 用户可以上传学习照片并展示在帖子中。
3. 用户可以浏览最新、热门、打卡、经验贴、我的、收藏信息流。
4. 用户可以点赞、收藏、评论、回复和举报。
5. 用户可以查看今日打卡、打卡日历和连续打卡天数。
6. 管理员可以审核帖子、评论、图片和举报。
7. 系统具备基础内容安全、隐私保护、速率限制和重复内容检测。
8. AI 可以异步识别学习照片并生成学习摘要和候选学习资产。
9. 学习广场有用户侧统计和管理员运营统计。
10. 前后端测试、文档和上线开关完整。

# 管理员后台数据地图与 ER 图可视化改造题目

## 一、设计方案

### 1. 目标

把当前管理员后台的“数据地图”从简单的表清单，升级为一个可用于研发、运营和排障的数据库可视化中心。升级后应能覆盖以下能力：

1. 展示完整的数据库表清单，而不是只展示部分业务表。
2. 补齐词典相关表的中文名、业务归属、敏感级别、说明和后台入口。
3. 在表详情页展示结构化数据字典，包括字段、类型、默认值、主键、索引、外键和敏感标记。
4. 提供 ER 图视图，用图形化方式展示表与表之间的关系。
5. 支持按模块筛选，例如用户中心、作文与评测、词典与词汇学习、订阅与权益、数据治理。
6. 后续支持导出 DBML 或 Mermaid，便于文档沉淀和进一步扩展。

### 2. 推荐落地方案

结合当前项目现状，推荐采用“自定义后台 + information_schema + YAML 元数据增强 + Mermaid ER 图”的方案。

#### 方案结构

1. 数据真实来源：
   - MySQL `information_schema.tables`
   - MySQL `information_schema.columns`
   - MySQL `information_schema.statistics`
   - MySQL `information_schema.key_column_usage`

2. 业务元数据增强：
   - 继续使用 `backend/src/main/resources/admin-data-catalog.yml`
   - 为每张核心表补充：
     - 中文标题
     - 所属模块
     - 敏感级别
     - 后台入口
     - 时间字段
     - 表说明
     - 敏感字段
     - 安全说明

3. 前端可视化方式：
   - 列表页继续保留表格
   - 表详情页增加“数据字典 / 索引与外键 / 关系图”视图
   - 新增独立“ER 图”页面或数据地图内的图形 Tab
   - 第一阶段使用 `Mermaid erDiagram`

### 3. 页面信息架构

#### 页面 1：数据地图总览

路径建议：`/admin/data-catalog`

展示内容：

1. 表清单
2. 关键筛选：
   - 关键词
   - 模块
   - 敏感级别
   - 是否有后台入口
   - 是否有外键关系
3. 支持展示词典相关表，例如：
   - `dictionary_library`
   - `dictionary_entry`
   - `dictionary_pronunciation`
   - `dictionary_sense`
   - `dictionary_example`
   - `dictionary_phrase`
   - `dictionary_resource`
   - `dictionary_import_job`
   - `user_dictionary_word_state`

#### 页面 2：表详情页

路径建议：`/admin/data-catalog/:tableName`

展示内容：

1. 基础信息：
   - 表名
   - 中文名
   - 所属模块
   - 行数
   - 敏感级别
   - 最近更新时间
   - 后台入口
   - 业务说明

2. 数据字典：
   - 字段名
   - 中文说明
   - 类型
   - 是否可空
   - 默认值
   - 是否主键
   - 是否敏感
   - 字段备注

3. 索引与约束：
   - 主键
   - 普通索引
   - 唯一索引
   - 外键

4. 关系视图：
   - 当前表指向哪些表
   - 哪些表引用当前表

#### 页面 3：ER 图视图

路径建议：`/admin/data-catalog/erd`

展示内容：

1. 全库 ER 图
2. 按模块过滤的 ER 图
3. 支持“以某张表为中心”的局部关系图
4. 节点点击后跳转表详情页

### 4. 词典模块的元数据建议

建议新增模块：`词典与词汇学习`

建议归类：

1. `dictionary_library`：词典库信息
2. `dictionary_entry`：词条主表
3. `dictionary_pronunciation`：词条发音
4. `dictionary_sense`：词义明细
5. `dictionary_example`：例句
6. `dictionary_phrase`：短语与搭配
7. `dictionary_resource`：词典资源文件
8. `dictionary_import_job`：词典导入任务
9. `user_dictionary_word_state`：用户单词状态

### 5. 技术取舍

#### 为什么先用 Mermaid，不直接上复杂图库

原因：

1. 当前项目已经有后台页面和数据地图接口，Mermaid 接入成本最低。
2. 第一阶段目标是“能看清关系”，不是做大型交互式建模平台。
3. Mermaid 适合先跑通：
   - 后端关系聚合
   - 模块筛选
   - 表跳转
   - 文档复用

后续如果全库关系过于复杂，再升级为 `Cytoscape.js` 或 `AntV X6/G6`。

### 6. 本次改造的完成定义

1. 管理员能在数据地图页面看到词典相关表。
2. 表详情页能看到完整字段字典、索引和外键信息。
3. 能看到全局或按模块过滤的 ER 图。
4. 词典域关系能从图上看出：
   - `dictionary_entry` 与发音、释义、例句、短语、资源的关联
   - `user_dictionary_word_state` 与用户和单词状态的关联
5. 文档同步更新，说明数据地图的元数据来源和 ER 图生成方式。

## 二、Trae 题目拆分

## 题目 1：补齐数据地图中的词典模块元数据

### A 小题

#### Prompt

请补齐 `backend/src/main/resources/admin-data-catalog.yml`，把词典相关表和用户单词状态表接入管理员后台数据地图。要求为每张表增加中文标题、所属模块、敏感级别、后台入口、时间字段、业务说明、敏感字段和安全说明。模块统一归类到“词典与词汇学习”或“数据治理”。

#### 难度

中

#### 验收标准

1. `admin-data-catalog.yml` 中新增以下表的配置：
   - `dictionary_library`
   - `dictionary_entry`
   - `dictionary_pronunciation`
   - `dictionary_sense`
   - `dictionary_example`
   - `dictionary_phrase`
   - `dictionary_resource`
   - `dictionary_import_job`
   - `user_dictionary_word_state`
2. 每张表都包含非空的 `title`、`module`、`sensitivity`、`description`。
3. 对应字段语义与当前业务一致，不能乱填后台入口。
4. 敏感字段标注合理，例如用户状态表中的用户标识、来源字段、行为时间字段要有明确说明。

### B 小题

#### Prompt

请检查并修正管理员后台数据地图后端逻辑，确保即使某张表没有配置项，也仍然可以被扫描出来并显示基础信息；已配置表则优先展示中文标题、模块、说明、敏感级别和更新时间。

#### 难度

中

#### 验收标准

1. `GET /api/admin/data-catalog/tables` 仍然基于 `information_schema.tables` 扫描当前数据库。
2. 未配置表不会从接口结果中消失。
3. 已配置表会覆盖显示中文标题、模块、说明和敏感级别。
4. 至少补 1 个后端测试，验证配置表和未配置表都能正常返回。

### A 小题

#### Prompt

请改造数据地图表详情页接口和页面展示，把当前表详情升级为结构化数据字典。要求清晰展示字段名、字段类型、是否可空、默认值、主键、敏感标记和字段说明，并对词典相关表的字段展示做适配。

#### 难度

中

#### 验收标准

1. 表详情接口返回字段字典结构完整。
2. 页面能展示：
   - 字段名
   - 类型
   - 可空
   - 默认值
   - 主键
   - 敏感字段标记
   - 字段说明
3. 词典相关表字段展示无明显错位或缺列。
4. 字段较多的表支持基本可读性，不出现严重拥挤或溢出。

### B 小题

#### Prompt

请在表详情页补充“索引与外键”区块，展示当前表的主键、唯一索引、普通索引、外键约束和关联目标表，并增强表详情页的信息层级。

#### 难度

中

#### 验收标准

1. 页面能区分主键、唯一索引和普通索引。
2. 页面能展示外键：
   - 外键名

## 题目 3：新增 ER 图接口与模块关系聚合

### A 小题

#### Prompt

请在后端新增管理员数据地图 ER 图接口，基于 `information_schema.key_column_usage` 和现有数据地图配置，输出适合前端绘图的节点和边结构。接口需要支持按模块过滤和按表名聚焦。

#### 难度

偏高

#### 验收标准

1. 新增独立 ER 图接口，例如：
   - `GET /api/admin/data-catalog/graph`
2. 返回的数据至少包含：
   - 节点：表名、中文名、模块、敏感级别
   - 边：源表、源字段、目标表、目标字段、关系说明
3. 支持按 `module` 参数过滤。
4. 支持按 `tableName` 参数返回局部关系图。
5. 接口对没有外键的表也能返回孤立节点。

### B 小题

#### Prompt

请为 ER 图接口增加面向词典域的关系增强逻辑。如果物理外键缺失，但业务上存在稳定主从关系，可通过配置补充“逻辑关系”，用于前端图展示，但不能伪造数据库真实外键。

#### 难度

高

#### 验收标准

1. 支持“数据库真实外键”和“配置化逻辑关系”并存。
2. 逻辑关系在返回数据中有明确标记，例如 `relationType = physical | logical`。
3. 词典域至少能表达出以下关系：
   - `dictionary_entry -> dictionary_pronunciation`
   - `dictionary_entry -> dictionary_sense`
   - `dictionary_sense -> dictionary_example`
   - `dictionary_entry -> dictionary_phrase`
   - `dictionary_entry -> dictionary_resource`
4. 前端可据此区分真实外键和逻辑关系展示样式。

## 题目 4：实现管理员后台 ER 图页面

### A 小题

#### Prompt

请在管理员后台实现“ER 图”页面，优先使用 Mermaid 渲染。页面支持全库模式、按模块筛选模式和按单表聚焦模式，并能跳转回表详情页。

#### 难度

偏高

#### 验收标准

1. 新增 ER 图页面或数据地图内 ER 图 Tab。
2. 页面至少支持：
   - 全部表关系图
   - 按模块过滤
   - 按表聚焦
3. 节点文字优先展示中文名，次级展示表名。
4. 点击节点后能跳转到对应表详情页。
5. 图加载失败时有明确错误提示，不出现空白无反馈页面。

### B 小题

#### Prompt

请优化 ER 图页面的可读性和交互，要求对节点按模块着色，对敏感级别做视觉区分，并提供图例说明。对于关系复杂的图，应提供缩小范围的交互入口。

#### 难度

中

#### 验收标准

1. 不同模块有可区分的节点样式。
2. 高敏和低敏表在视觉上能区分。
3. 页面包含图例，解释颜色或线型含义。
4. 当全图过于复杂时，用户能通过模块筛选或单表聚焦缩小范围。
5. 页面在常见桌面宽度下不出现大面积重叠导致完全不可读。

## 五、新增补充要求

以下内容为本题目的新增补充约束，Trae 实现时必须一并满足，不能只做静态数据地图或只做单独 ER 图页。

### 1. 自动发现新表

1. 数据地图列表必须基于当前数据库自动扫描表结构。
2. 新增表只要已经建到当前连接数据库里，就应自动出现在数据地图列表中。
3. 不允许把数据地图做成“只有 YAML 配置里的表才显示”。
4. 如果某张表没有业务配置，页面也必须展示该表，而不是静默忽略。

### 2. 未配置表的基础展示回退

对于未在 `admin-data-catalog.yml` 配置的表，至少要回退展示以下信息：

1. 表名
2. 行数
3. 最近更新时间

补充说明：

1. 最近更新时间优先使用配置的时间列。
2. 未配置时，允许自动推断常见时间字段，例如：
   - `updated_at`
   - `occurred_at`
   - `last_lookup_at`
   - `created_at`
   - `finished_at`
3. 如果完全没有可用时间列，可以显示 `-`，但不能报错。

### 3. 已配置表的增强展示

如果表在 `admin-data-catalog.yml` 中已有配置，则必须增强展示以下业务信息：

1. 中文标题
2. 所属模块
3. 敏感级别
4. 后台入口
5. 说明
6. 敏感字段
7. 安全说明

并且页面需要明确区分：

1. `自动发现`
2. `配置增强`

建议在列表页用 badge 或状态列表达。

### 4. ER 图关系规则

ER 图必须同时支持两类关系：

#### 4.1 真实外键

1. 从数据库外键元数据中自动读取。
2. 在图上使用实线展示。
3. 在关系明细中标记为 `physical` 或“物理关系”。

#### 4.2 逻辑关系

1. 当数据库中没有真实外键，但业务上存在稳定关系时，允许通过配置补充。
2. 逻辑关系只能用于数据地图展示和导出，不能伪装成真实外键。
3. 在图上使用虚线展示。
4. 在关系明细中标记为 `logical` 或“逻辑关系”。

### 5. 词典域必须补齐的逻辑关系

词典域至少要能在图上表达出以下关系：

1. `dictionary_library -> dictionary_entry`
2. `dictionary_library -> dictionary_resource`
3. `dictionary_library -> dictionary_import_job`
4. `dictionary_entry -> dictionary_pronunciation`
5. `dictionary_entry -> dictionary_sense`
6. `dictionary_sense -> dictionary_example`
7. `dictionary_entry -> dictionary_example`
8. `dictionary_entry -> dictionary_phrase`
9. `user_dictionary_word_state -> dictionary_entry`

### 6. 页面交互补充要求

1. 数据地图总览页除了表格视图外，应支持 ER 图视图。
2. ER 图视图至少支持：
   - 全部表
   - 按模块筛选
   - 按单表聚焦
3. 表详情页应展示“以当前表为中心”的局部关系图。
4. 管理员点击图中的表节点后，应能跳转到对应表详情页。

### 7. 导出补充要求

1. Mermaid 导出和 DBML 导出必须与当前筛选范围一致。
2. 按模块查看时，导出当前模块范围。
3. 按单表聚焦时，导出该表的一跳局部关系图。
4. 导出内容应可直接用于文档系统或外部可视化工具。

### 8. 新增补充验收标准

在原有验收标准之外，再追加以下统一验收项：

1. 新建一张未配置的新表后，刷新数据地图列表能看到它。
2. 未配置表不会因为缺失中文名、模块或说明而被隐藏。
3. 已配置词典表会显示完整中文业务语义。
4. ER 图中能区分实线物理关系和虚线逻辑关系。
5. 表详情页不仅能看字段，还能看到当前表的上下游关系。
6. 导出 Mermaid / DBML 后，词典域关系没有丢失。

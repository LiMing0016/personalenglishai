# AI 精读工作台完整功能实现题目

## 背景

我们要把翻译模块从普通翻译页面升级为“AI 精读工作台”。

产品主链路：

```text
上传文章 / PDF / 题目
→ 高质量 PDF 解析 / OCR / 文档结构化
→ AI 生成段落级精读材料
→ 用户在左侧阅读原文和译文
→ 右侧 Agent 围绕当前段落回答问题、整理笔记、沉淀知识点
→ 自动生成生词、短语、句型、语法、复习卡、文章学习报告
→ 回到 Hub 持续复习
```

参考文档：

- `docs/product/AI精读工作台完整产品方案.md`
- `docs/superpowers/plans/2026-06-08-translation-hub-implementation.md`
- `web/src/pages/app/TranslationPage.vue`
- `web/src/pages/app/TranslationWorkspacePage.vue`
- `web/src/pages/app/translationWorkspaceData.ts`
- `web/src/router/index.ts`
- `web/AGENTS.md`
- `backend/AGENTS.md`

总体原则：

1. 统一为一个 AI 精读工作台页面，不为外刊、考试、技术文档分别做三套页面。
2. 左侧是结构化精读材料，右侧是翻译学习 Agent，底部是学习资产沉淀栏。
3. PDF、OCR、AI 翻译、Agent、学习资产、复习计划、学习报告、学习画布都要接入完整主链路。
4. 可分阶段实现，但每个阶段都必须能独立验证。
5. 不要破坏写作页现有翻译面板和作文主链路。

## 题目 1：重做 AI 精读工作台统一页面

题目类型：feature 迭代

难度：中等偏难

### A 小题：实现统一工作台布局

#### Prompt

请重做 `/app/translation/workspace/:id` 的页面结构，将当前骨架页升级为统一 AI 精读工作台。

页面必须包含：

- 顶部工具栏：材料名、AI 解析状态、当前模式、学习进度、全局操作。
- 模式切换：沉浸精读 / 外刊精读 / 考试精读 / 技术文档。
- 左侧精读材料区：结构化展示文章或 PDF 解析结果。
- 右侧翻译学习 Agent：围绕当前段落和选区回答问题。
- 底部学习资产栏：生词、短语、句型、语法、复习卡、笔记数量。

要求：

1. 同一个页面布局支持所有模式，只改变右侧 Agent 能力模块。
2. 不要做成普通聊天页，也不要做成三套不同页面。
3. 页面应适合长文阅读，左侧材料区可滚动，右侧 Agent 保持可用。
4. 保持现有 AppLayout 与左侧导航兼容。

#### 难度

中等偏难

#### 验收标准

- 打开 `/app/translation/workspace/:id` 后能看到统一工作台布局。
- 顶部显示材料名、模式、解析状态、进度和操作按钮。
- 左侧显示结构化文档，右侧显示翻译学习 Agent。
- 底部显示学习资产统计。
- 切换模式时页面布局不变，右侧 Agent 模块内容变化。
- 窄屏下布局不重叠、不溢出。

### B 小题：实现当前段落选中与右侧 Agent 联动

#### Prompt

请实现左侧段落与右侧 Agent 的上下文联动。

要求：

1. 左侧每个段落都有唯一 block id。
2. 点击段落后，该段落高亮为当前段落。
3. 右侧 Agent 顶部显示当前上下文，例如：`当前段落 P3 · 沉浸精读`。
4. 当前段落下方展开该段译文、短语、生词、语法点和笔记入口。
5. 右侧 Agent 的快捷操作基于当前段落工作。

#### 难度

中等

#### 验收标准

- 点击不同段落后，左侧高亮段落会变化。
- 右侧 Agent 上下文会同步更新。
- 当前段落可展开学习层。
- 没有选中段落时有合理默认状态。
- 段落切换不会丢失已经输入的本地笔记草稿。

## 题目 2：建立文档结构化数据模型

题目类型：工程化

难度：中等偏难

### A 小题：设计 Document / DocumentBlock / Insight 前端类型

#### Prompt

请为 AI 精读工作台建立清晰的数据模型，至少包含：

- `IntensiveReadingDocument`
- `DocumentBlock`
- `TranslationInsight`
- `LearningAsset`
- `AgentMessage`
- `ReviewCard`

字段至少支持：

- 文档 id、标题、来源类型、模式、解析状态、进度。
- block id、block 类型、顺序、原文、页码、bbox、父级 block。

- 学习资产类型、来源文档、来源 block、复习状态。

#### 难度

中等

#### 验收标准

- 类型集中维护，不散落在 Vue 模板里。
- 字段能覆盖 PDF、OCR、AI 翻译、Agent、资产和报告需求。
- 类型命名清晰，后续可映射真实后端 DTO。

### B 小题：实现 mock service 和状态读取边界

#### Prompt

请实现 AI 精读工作台的 mock service，模拟后续真实接口。

至少包含函数：

- 获取文档详情。
- 获取文档 block 列表。
- 获取段落 insight。
- 保存学习资产。
- 获取学习资产统计。
- 获取 Agent 消息。

要求：

1. 页面通过 service 获取数据，不直接依赖散落 mock 数组。
2. service 先使用本地 mock 或 localStorage。
3. 函数命名要便于后续替换真实 API。

#### 难度

中等

#### 验收标准

- 工作台页面的数据读取经过统一 service。
- mock service 能返回完整文档、段落和资产数据。
- 后续接后端时不需要重写页面主体结构。
- 有基础单元测试覆盖关键过滤和读取逻辑。

## 题目 3：高质量 PDF 解析

题目类型：backend + frontend 集成

难度：困难

### A 小题：实现 PDF 上传与基础结构化解析

#### Prompt

请实现 PDF 上传与基础结构化解析能力。

后端需要支持：

- 上传 PDF 文件。
- 创建解析任务。
- 提取 PDF 文本。
- 按页码和段落生成 `DocumentBlock`。
- 保存原始文件和解析结果。
- 返回任务状态。

前端需要支持：

- 在新建精读中上传 PDF。
- 创建解析任务后进入解析进度页。
- 解析完成后进入工作台。
- 工作台展示解析后的段落。

#### 难度

困难

#### 验收标准

- 能上传普通文本 PDF。
- 后端能生成文档记录和段落 block。
- block 至少包含 id、type、text、pageNumber、order。
- 前端能展示解析进度。
- 解析完成后能进入工作台阅读段落。
- 解析失败能展示错误和重试入口。

### B 小题：优化 PDF 版面解析质量

#### Prompt

请优化 PDF 结构化解析质量。

需要尽量支持：

- 标题、小标题识别。
- 段落合并。
- 页眉页脚过滤。
- 双栏文章顺序修正。
- 列表识别。
- 题目和选项识别。
- bbox 位置信息保留。

要求：

1. 不要求一次性支持所有复杂 PDF，但要有可扩展解析管线。
2. 对无法识别的复杂结构保留原文本块，不要丢内容。
3. 输出结构仍统一为 `DocumentBlock`。

#### 难度

困难

#### 验收标准

- 标题和段落类型能被区分。
- 页眉页脚不会大量混入正文。
- 双栏 PDF 的阅读顺序明显优于简单全文拼接。
- 题目和选项能作为独立 block 展示。
- 解析结果能回溯到页码和 bbox。

## 题目 4：OCR 扫描版 PDF 支持

题目类型：backend + AI/OCR 集成

难度：困难

### A 小题：检测扫描版 PDF 并进入 OCR 流程

#### Prompt

请实现扫描版 PDF 检测和 OCR 流程入口。

要求：

1. 上传 PDF 后检测文本层是否足够。
2. 如果文本层缺失或质量过低，自动标记为需要 OCR。
3. 创建 OCR 任务并更新解析进度。
4. 前端解析进度页展示 `OCR 识别中` 状态。

#### 难度

困难

#### 验收标准

- 扫描版 PDF 不会直接得到空白文档。
- 系统能识别需要 OCR 的文件。
- OCR 状态能在前端展示。
- OCR 失败时有错误提示和重试入口。

### B 小题：将 OCR 结果转为 DocumentBlock

#### Prompt

请将 OCR 识别结果接入统一文档结构。

要求：

- OCR 结果包含文本、页码、bbox、置信度。
- 低置信度 block 需要标记。
- OCR 结果进入同一套 `DocumentBlock`。
- 前端对低置信度 block 展示提示。

#### 难度

困难

#### 验收标准

- OCR 结果能在工作台左侧展示。
- 每个 OCR block 能关联页码。
- 低置信度内容有可见提示。
- 用户可以继续对 OCR block 使用翻译、问 Agent、保存笔记。

## 题目 5：真实 AI 段落翻译与精读生成

题目类型：AI 功能

难度：困难

### A 小题：实现段落级 AI 翻译任务

#### Prompt

请实现对 `DocumentBlock` 的段落级 AI 翻译任务。

要求：

1. 支持按 block 批量生成译文。
2. 每个 block 生成结构化结果：
   - 中文译文。
   - 段落摘要。
   - 重点句。
   - 重点短语。
   - 生词。
   - 语法点。
3. 翻译任务可异步执行并保存结果。
4. 前端能展示每段的翻译状态：待翻译、生成中、已完成、失败。

#### 难度

困难

#### 验收标准

- 对一篇文档可批量生成段落译文。
- 每段翻译结果能保存并重复读取。
- 前端能展开当前段落查看译文和语言点。
- 单段失败不影响整篇其他段落展示。
- 可重新生成单段翻译。

### B 小题：按 Agent 模式生成不同精读内容

#### Prompt

请让段落精读生成支持不同模式：

- 沉浸精读。
- 外刊精读。
- 考试精读。
- 技术文档。

不同模式输出重点不同：

- 外刊：表达迁移、可用于写作的句型。
- 考试：题干定位、同义替换、答案依据。
- 技术：术语解释、中文技术译法、段落逻辑。
- 沉浸：普通段落翻译、短语、生词、语法。

#### 难度

困难

#### 验收标准

- 切换模式后新生成的 insight 结构不同。
- 考试模式能输出定位依据或同义替换字段。
- 技术模式能输出术语字段。
- 外刊模式能输出表达迁移字段。
- UI 能根据模式展示对应内容，而不是硬编码一套字段。

## 题目 6：翻译学习 Agent 多轮问答

题目类型：AI Agent 功能

难度：困难

### A 小题：实现基于当前段落和选区的 Agent 问答

#### Prompt

请实现右侧翻译学习 Agent 的真实问答能力。

Agent 请求需要带上：

- documentId。
- 当前 blockId。
- 当前选区文本。
- 当前 Agent 模式。
- 用户问题。
- 该段原文和已生成 insight。

Agent 回答需要能围绕当前段落解释：

- 翻译。
- 长难句。
- 短语。
- 语法。
- 考试依据。
- 技术术语。

#### 难度

困难

#### 验收标准

- 用户点击某段后能在右侧 Agent 提问。
- 用户选中一句话后，Agent 能基于选区回答。
- Agent 回答不是脱离文档的通用回答。
- 回答中能引用或提到当前段落内容。
- 请求失败有重试和错误提示。

### B 小题：实现 Agent 多轮上下文和快捷沉淀

#### Prompt

请实现 Agent 多轮对话和回答沉淀能力。

要求：

1. 同一文档内保留 Agent 消息历史。
2. 同一 block 的多轮追问能带上历史上下文。
3. Agent 回答下方提供快捷操作：
   - 加入笔记。
   - 加入短语库。
   - 加入语法点。
   - 生成复习卡。
4. 保存后进入学习资产库。

#### 难度

困难

#### 验收标准

- 多轮追问能看到上下文连续性。
- 刷新页面后历史消息仍可恢复。
- Agent 回答可一键保存为学习资产。
- 保存后的资产能关联 documentId 和 blockId。

## 总体验收标准

完成所有题目后，应满足：

1. 用户能从 Hub 新建精读任务。

10. 系统能生成文章学习报告并导出。
11. 系统能从学习资产生成学习画布 / 知识图谱。
12. Hub 能展示真实学习记录、资产统计和复习任务。
13. 所有核心流程刷新后数据不丢失。
14. 前端构建通过，后端相关测试通过。
15. 不破坏写作页和现有 AI 助手主链路。

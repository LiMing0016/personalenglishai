# 学习助手本地文件归档与数据库归档记录 Trae 实现题目

## 背景

当前学习助手已经有基础归档能力：点击“归档”后，对话可以从普通列表隐藏，并进入归档列表。但这个能力更像 UI 状态切换，不是真正的“保存归档”。

新需求是把归档做完整：

```text
用户点击归档
  ↓
后端读取对话和消息
  ↓
写入本地归档文件夹
  ↓
生成 conversation.md / conversation.json / metadata.json
  ↓
数据库写入归档记录
  ↓
assistant_conversation.archived_at 标记为已归档
  ↓
前端归档列表可查看、恢复、删除
```

目标是让学习助手归档不仅能在 UI 中隐藏，还能在本机 Documents 目录下留下可长期保存、可人工阅读、可校验的归档文件。

## 总体要求

默认归档目录：

```text
{user.home}/Documents/PEAI/assistant-archives
```

用户可以在学习助手侧边栏修改归档目录。

每次归档生成目录：

```text
Documents/PEAI/assistant-archives/
  2026-05/
    对话标题-20260523-205000-archive-xxx/
      conversation.md
      conversation.json
      metadata.json
```

数据库新增：

- `assistant_archive_setting`：用户归档目录配置。
- `assistant_conversation_archive`：每次归档生成的记录。

## 非目标

- 不做云端对象存储。
- 不做 ZIP 下载。
- 不做对归档文件的全文搜索。
- 不做系统原生文件夹选择器；第一版用路径输入框。
- 取消归档不删除已经生成的本地文件，只恢复 UI 可见性。

## 题 2：实现后端本地归档文件服务

### 发给 Trae 的 Prompt

请实现学习助手本地归档文件服务。归档时后端需要把当前对话导出成 Markdown、JSON 和元数据文件，写入用户配置的归档目录。要求文件名安全、目录按月份分组、写入尽量原子化，并计算 JSON 快照 checksum。完成后运行 `cd backend && .\mvnw.cmd -q -Dtest=AssistantArchiveFileServiceTest test`。

### 小题 A：生成归档目录和 Markdown 文件

#### 题目 Prompt

请新增 `AssistantArchiveFileService`，负责把对话和消息写成本地归档文件。

要求：

1. 新增文件：`backend/src/main/java/com/personalenglishai/backend/service/assistant/AssistantArchiveFileService.java`。
2. 提供方法：

```java
ArchiveFiles writeArchive(
    Path baseDir,
    String archiveUid,
    AssistantConversation conversation,
    List<AssistantMessage> messages,
    LocalDateTime archivedAt
)
```

3. 归档目录格式：

```text
{baseDir}/{yyyy-MM}/{safeTitle}-{yyyyMMdd-HHmmss}-{archiveUid}/
```

4. `safeTitle` 必须移除 Windows 非法文件名字符：
   - `\ / : * ? " < > |`
   - 控制字符
5. Markdown 文件名固定为 `conversation.md`。
6. Markdown 内容包含：
   - 对话标题
   - 对话 ID
   - 摘要
   - 归档时间
   - 消息数
   - 用户和助手消息正文

#### 题目难度

中等

#### 验收标准

- 能创建按月份分组的归档目录。
- 标题包含非法字符时不会写文件失败。
- `conversation.md` 可人工阅读。
- user 消息显示为“用户”。
- assistant 消息显示为“学习助手”。
- 单元测试覆盖普通标题和非法标题。

### 小题 B：生成 JSON 快照、元数据和 checksum

#### 题目 Prompt

请在 `AssistantArchiveFileService` 中补齐 JSON 快照和元数据文件。

要求：

1. 生成 `conversation.json`。
2. JSON 内容包含：
   - `archiveUid`
   - `archivedAt`
   - `conversation`
   - `messages`
3. 生成 `metadata.json`。
4. `metadata.json` 至少包含：
   - `archiveUid`
   - `conversationUid`
   - `title`
   - `messageCount`
   - `archivedAt`
   - `checksum`
5. `checksum` 使用 `conversation.json` 内容的 SHA-256。
6. 文件写入使用临时文件再 move 的方式，避免半写入。

#### 题目难度

中等

#### 验收标准

- `conversation.json` 是合法 JSON。
- `metadata.json` 是合法 JSON。
- `metadata.checksum` 长度为 64 位十六进制字符串。
- checksum 基于 JSON 快照内容计算。
- 写入失败时抛出可被业务层捕获的异常。
- 单元测试能读取生成的三个文件并校验内容。

## 题 3：实现归档编排 Service 和 API

### 发给 Trae 的 Prompt（完成）

请实现学习助手真实归档的后端编排逻辑。归档不是只更新 `archived_at`，而是先写文件，再写归档记录表，最后标记对话已归档。恢复时不删除本地文件，只把对话恢复到普通列表，并把最新归档记录标记为 `restored`。完成后运行 `cd backend && .\mvnw.cmd -q -Dtest=AssistantArchiveFileServiceTest,AssistantArchiveSchemaTest,AssistantControllerTest test`。

### 小题 A：实现归档编排服务

#### 题目 Prompt

请新增 `AssistantConversationArchiveService`，负责真实归档业务。

要求：

1. 新增文件：
   - `backend/src/main/java/com/personalenglishai/backend/service/assistant/AssistantConversationArchiveService.java`
2. 注入：
   - `AssistantConversationMapper`
   - `AssistantMessageMapper`
   - `AssistantArchiveSettingMapper`
   - `AssistantConversationArchiveMapper`
   - `AssistantArchiveFileService`
3. 实现：
   - `archiveConversation(Long userId, String conversationUid)`
   - `restoreConversation(Long userId, String conversationUid)`
   - `getArchiveSettings(Long userId)`
   - `updateArchiveSettings(Long userId, UpdateAssistantArchiveSettingsRequest request)`
4. 归档流程：
   - 校验对话属于当前用户。
   - 查询对话消息。
   - 解析归档目录，没有配置则使用默认目录。
   - 调用文件服务写入归档文件。
   - 插入 `assistant_conversation_archive`。
   - 更新 `assistant_conversation.archived_at`。
5. 如果数据库写入失败，已生成的归档目录要尽量清理。

#### 题目难度

困难

#### 验收标准

- 归档成功后生成本地文件。
- 归档成功后写入 `assistant_conversation_archive`。
- 归档成功后 `assistant_conversation.archived_at` 非空。
- 对话不存在或不属于当前用户时返回业务错误。
- 数据库写入失败时不会留下明显半成品目录，至少做 best-effort cleanup。
- 恢复时不会删除本地归档文件。

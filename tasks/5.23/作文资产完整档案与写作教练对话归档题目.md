# 作文资产完整档案与写作教练对话归档 Trae 实现题目

## 背景

当前作文已经支持归档到“作文资产”。下一步需要把“归档”升级为真正的长期资产沉淀：用户归档一篇作文时，系统需要把这篇作文的核心信息整理成一份可阅读、可刷新、可下载的完整档案。

第一版档案不依赖浏览器缓存，也不依赖远端 ChatKit transcript，只归档后端已经持久化的数据：

- 作文正文
- 题目和写作元数据
- 评分历史
- 已关联的写作教练会话消息
- 一份 Markdown 档案
- 一份结构化 JSON 快照

本题中的“归档”仍然是资产化标记，不是删除、隐藏或冻结。取消归档只恢复 `documents.status=1`，不删除历史快照。

## 总体要求

1. 继续复用 `documents.status=2` 表示已归档作文。
2. 新增作文资产快照能力，归档时同步生成或刷新快照。
3. 资产快照需要同时保存 Markdown 和 JSON。
4. 写作教练会话必须通过显式后端关联保存，不依赖浏览器本地状态。
5. 用户中心“作文资产”需要支持查看完整档案详情。
6. 资产详情需要包含作文正文、题目信息、评分摘要、教练对话和 Markdown 档案。
7. 不修改生产登录逻辑。
8. 不通过 IP、User-Agent、浏览器特征、mock token 绕过鉴权。
9. 不新增 OpenAI API Key 或 SDK 配置路径。
10. 所有资产接口都必须校验当前用户 ownership。

## 非目标

- 不把归档作文从普通写作历史和 Dashboard 中移除。
- 不把归档作文改成只读。
- 不归档浏览器缓存中的临时素材、范文、翻译、润色内容。
- 不读取 OpenAI ChatKit 远端 transcript。
- 不改写现有评分、写作创建和生产鉴权主流程。

## 题 1：后端资产快照数据结构

### 发给 Trae 的 Prompt（完成）

请为作文资产库新增数据库级快照能力。归档作文时，系统需要能保存一份最新的 Markdown 档案和结构化 JSON 档案，并能记录作文与写作教练会话之间的归属关系。

### 小题 A：新增教练会话关联表

#### 题目 Prompt

请新增 `writing_document_conversation_link` 表，用于持久保存作文和写作教练会话的关联关系。

要求：

1. 字段至少包含：
   - `id`
   - `document_id`
   - `conversation_uid`
   - `user_id`
   - `created_at`
   - `updated_at`
2. 支持一篇作文关联多个教练会话。
3. 同一用户、同一作文、同一会话重复关联时必须幂等。
4. 表结构需要加入项目现有 schema 或迁移 SQL。
5. 不改变现有 `assistant_conversation` / `assistant_message` 的语义。

#### 题目难度

中等

#### 验收标准

- 数据库能创建 `writing_document_conversation_link`。
- 同一作文可以关联多个 `conversation_uid`。
- 重复关联不会产生重复数据。
- 不影响现有 assistant 会话和消息查询。

### 小题 B：新增作文资产快照表

#### 题目 Prompt

请新增 `writing_document_asset_snapshot` 表，用于保存每篇作文最新的一份资产快照。

要求：

1. 字段至少包含：
   - `id`
   - `document_id`
   - `user_id`
   - `snapshot_uid`
   - `markdown_content`
   - `snapshot_json`
   - `latest_revision`
   - `evaluation_count`
   - `coach_message_count`
   - `generated_at`
   - `created_at`
   - `updated_at`
2. 每篇作文只保留一份最新快照。
3. 再次归档或手动刷新时更新同一份快照。
4. 取消归档时不删除快照。

#### 题目难度

中等

#### 验收标准

- 数据库能创建 `writing_document_asset_snapshot`。
- 同一 `document_id` 不会生成多份最新快照。
- 快照能保存 Markdown 和 JSON。
- 取消归档后快照仍然存在。

## 题 2：后端作文资产快照服务

### 发给 Trae 的 Prompt

请实现作文资产快照生成服务。服务需要从后端已持久化的数据中读取作文、题目、评分历史和写作教练对话，生成固定结构的 Markdown 与 JSON 快照。

### 小题 A：生成 Markdown 快照（完成）

#### 题目 Prompt

请实现作文资产 Markdown 生成逻辑。

Markdown 固定包含以下章节：

1. 作文概览
2. 题目信息
3. 作文正文
4. 评分记录
5. 写作教练对话
6. 档案元信息

要求：

1. 作文正文来自最新文档版本。
2. 题目信息来自现有写作元数据。
3. 评分记录展示核心字段：
   - 分数
   - 等级
   - 维度分
   - 错误数
   - 评估时间
4. 写作教练对话从 `assistant_message` 读取。
5. 如果用户消息是内部 `[写作教练 Copilot 请求]` 格式，Markdown 中提取 `[用户本轮问题]` 之后的可读内容。
6. 没有关联教练会话时，Markdown 显示“暂无写作教练对话”。

#### 题目难度

困难

#### 验收标准

- Markdown 包含作文标题、正文和题目信息。
- Markdown 包含评分摘要。
- Markdown 包含写作教练对话。
- 内部教练 prompt 不直接整段暴露给用户。
- 无教练会话时有明确空状态文案。

### 小题 B：生成 JSON 快照并判断 stale

#### 题目 Prompt（完成）

请实现作文资产 JSON 快照和过期状态判断。

要求：

1. `snapshot_json` 保存完整结构化数据，包括：
   - 文档元数据
   - 最新正文
   - 评分记录
   - 完整 `result_json`
   - 教练会话和消息原文
   - 快照生成信息
2. 如果作文内容、最新 revision、评分数量或教练消息数量在快照生成后发生变化，资产详情返回 `stale=true`。
3. 如果没有变化，返回 `stale=false`。
4. JSON 快照不能替代权限校验，读取时仍要校验 owner。

#### 题目难度

困难

#### 验收标准

- `snapshot_json` 中能看到完整评分 `result_json`。
- `snapshot_json` 中保留教练消息原文。
- 作文更新后资产详情返回 `stale=true`。
- 刷新快照后 `stale=false`。

## 题 3：后端资产接口

### 发给 Trae 的 Prompt

请新增作文资产相关 API。所有接口必须基于当前登录用户校验作文 ownership，不允许查看、刷新或关联他人的作文资产。

### 小题 A：归档时生成快照与资产详情接口

#### 题目 Prompt（完成）

请扩展现有归档接口，并新增资产详情接口。

要求：

1. 扩展 `PATCH /api/docs/{docId}/archive`：
   - 校验 owner。
   - 设置 `documents.status=2`。
   - 同步生成或刷新作文资产快照。
2. 新增：

```http
GET /api/writing/documents/{docId}/asset
POST /api/writing/documents/{docId}/asset/refresh
```

3. `GET /asset` 返回：
   - 作文元数据
   - 最新正文
   - 评分历史摘要
   - 关联教练会话列表
   - Markdown 快照
   - `generatedAt`
   - `stale`
4. `POST /asset/refresh` 手动重新生成快照并返回最新资产详情。

#### 题目难度

中等

#### 验收标准

- 归档接口会生成 `writing_document_asset_snapshot`。
- 再次归档更新同一份快照。
- owner 可以读取资产详情。
- owner 可以手动刷新资产详情。
- 非 owner 访问资产详情返回 forbidden。

### 小题 B：教练会话关联与 Markdown 下载接口

#### 题目 Prompt（完成）

请新增作文与写作教练会话关联接口，并提供 Markdown 下载接口。

建议接口：

```http
POST /api/writing/documents/{docId}/coach-conversations
GET /api/writing/documents/{docId}/asset/markdown
```

要求：

1. `POST /coach-conversations` 请求 body 传 `conversationId`。
2. 必须校验作文属于当前用户。
3. 必须校验 assistant conversation 也属于当前用户。
4. 关联操作幂等。
5. `GET /asset/markdown` 以 `text/markdown` 返回同一份 Markdown。
6. 不新增任何测试环境鉴权绕过。

#### 题目难度

中等

#### 验收标准

- 可以把当前用户作文关联到当前用户教练会话。
- 不能把当前用户作文关联到其他用户会话。
- 重复关联不会报错或重复插入。
- Markdown 下载接口返回 `text/markdown`。

## 题 4：写作编辑器关联写作教练会话

### 发给 Trae 的 Prompt

请在写作编辑器中把当前作文和真实写作教练会话关联起来。用户使用写作教练后，资产归档时需要能看到这篇作文相关的教练对话。

### 小题 A：拿到真实会话 ID 后关联作文

#### 题目 Prompt（完成）

请修改写作编辑器中发送写作教练消息的流程。

要求：

1. 继续沿用现有 `assistantChatStream` / 写作教练会话创建逻辑。
2. 拿到真实 `conv-*` 会话 ID 后，调用：

```http
POST /api/writing/documents/{docId}/coach-conversations
```

3. 如果当前作文已经有 `docId`，直接关联。
4. 如果当前作文还没有创建，先沿用现有创建文档逻辑生成 `docId`，再关联。
5. 关联失败不能阻断用户继续使用写作教练，但需要记录错误日志。

#### 题目难度

中等

#### 验收标准

- 已保存作文使用写作教练后，后端能看到作文和会话关联。
- 新作文首次使用写作教练时，会先创建作文再关联会话。
- 关联失败时教练回复流程不崩溃。
- 不改变现有写作教练回复内容。

### 小题 B：归档后继续编辑和继续对话

#### 题目 Prompt（完成）

请确保已归档作文继续编辑或继续使用写作教练时，归档状态和资产状态正确。

要求：

1. 已归档作文继续编辑后仍保持 `status=2`。
2. 已归档作文继续使用写作教练后，新的对话消息仍能通过资产详情识别为可刷新。
3. 不因为保存作文而自动取消归档。
4. 不因为刷新资产而修改作文正文。

#### 题目难度

中等

#### 验收标准

- 已归档作文保存后仍是 archived。
- 已归档作文新增教练对话后，资产详情 `stale=true`。
- 点击刷新档案后 Markdown 包含最新对话。
- 现有保存作文流程不回归。

## 题 5：用户中心作文资产详情

### 发给 Trae 的 Prompt

请把用户中心“作文资产”从简单列表升级为资产库和资产详情。用户可以在个人中心内全面了解一篇归档作文，而不是跳转到新的一级页面。

### 小题 A：资产库卡片增加查看档案

#### 题目 Prompt（完成）

请扩展用户中心“作文资产”列表。

要求：

1. 继续只加载已归档作文。
2. 每张卡片展示：
   - 标题
   - 题目摘要
   - 最新分数
   - 提交次数
   - 更新时间
   - 已归档标识
3. 每张卡片提供：
   - 查看档案
   - 编辑
   - 取消归档
4. 点击“编辑”进入 `/app/writing/editor` 并打开对应 `docId`。

#### 题目难度

简单

#### 验收标准

- `/app/me?tab=assets` 能看到归档作文列表。
- 卡片有“查看档案”入口。
- 编辑按钮能打开对应作文。
- 取消归档后该作文从资产列表消失。

### 小题 B：资产详情展示与操作

#### 题目 Prompt

请在用户中心内实现作文资产详情视图。

要求：

1. 详情页不新增独立一级路由。
2. 详情页包含：
   - 概览
   - 题目信息
   - 作文正文
   - 评分记录
   - 写作教练对话
   - Markdown 档案
3. 提供操作：
   - 返回资产库
   - 刷新档案
   - 编辑作文
   - 取消归档
   - 复制 Markdown
   - 下载 Markdown
4. 如果 `stale=true`，显示“作文或教练对话已有更新，可刷新档案”。

#### 题目难度

中等

#### 验收标准

- 点击“查看档案”能打开详情。
- 详情中能看到作文正文和 Markdown。
- `stale=true` 时有刷新提示。
- 点击刷新后页面展示最新档案。
- 复制和下载 Markdown 可用。

### 发给 Trae 的 Prompt

请为作文资产完整档案能力补充必要测试，并确保生产鉴权、写作编辑、评分和普通写作历史不受影响。

测试至少覆盖：

1. 只有作文 owner 可以归档、查看资产、刷新资产。

中等

- 取消归档不删除快照有测试覆盖。

#### 题目难度

简单

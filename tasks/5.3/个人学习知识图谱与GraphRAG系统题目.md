# 个人学习知识图谱与 GraphRAG 系统 Trae 题目

## 背景

当前项目已经具备写作、单词、词典、翻译、学习助手、学习广场、数据地图等能力，但用户学习数据仍分散在不同模块里。新的目标是建设“个人学习知识图谱”，把用户的作文、评分反馈、写作教练对话、收藏单词、词典查询、翻译文档、学习打卡和后续错题资产统一沉淀为可查询、可推荐、可解释的学习知识网络。

该需求不是普通页面改造，而是一个跨数据库、后端服务、AI 抽取、RAG 检索、图谱可视化、权限、安全、评测和运营后台的系统级功能。题目应交给 Trae 拆分实现，避免单文件修改。每道题都必须至少涉及以下两类以上改动：

- 数据库 migration / schema / 索引
- 后端 controller / service / mapper / DTO / 测试
- AI 抽取、Embedding、GraphRAG、Agent 或评测链路
- 前端页面 / 组件 / 状态管理 / 可视化
- 管理后台 / 调试台 / 数据治理
- 文档、测试、回归脚本或观测指标

## 参考技术方向

- GraphRAG：先从结构化图谱关系召回，再结合向量召回和上下文重排生成答案。
- Hybrid Search：关键词检索、向量检索、图谱邻域扩展组合使用。
- Knowledge Graph：实体、关系、证据、来源、置信度、时间和用户隔离都要入库。
- RAG 评测：需要命中率、证据覆盖率、幻觉率、引用完整性、回答可追溯性。
- 可视化：优先使用可维护的图谱组件，例如 Cytoscape.js、React Flow、AntV G6 或 ECharts Graph。项目如已有图表库，优先复用现有技术栈。

## 题目类型范围

- 0-1代码生成
- feature迭代
- bug修复
- 工程化
- 代码测试

## 题目 1：个人知识图谱领域模型与数据库总设计

题目类型：0-1代码生成

### A 小题：设计图谱核心实体表

#### 题目 Prompt

请为个人学习知识图谱设计并实现核心数据库表，覆盖实体、关系、证据、来源和用户隔离。

至少新增：

- `learning_graph_node`
- `learning_graph_edge`
- `learning_graph_evidence`
- `learning_graph_source`
- `learning_graph_build_run`

核心要求：

- 每个节点必须归属用户，不能跨用户泄露。
- 节点类型至少覆盖 `word`、`phrase`、`sentence`、`grammar_point`、`writing_issue`、`translation_segment`、`document`、`essay`、`topic`、`learning_goal`。
- 关系类型至少覆盖 `appears_in`、`explains`、`similar_to`、`derived_from`、`confuses_with`、`improves`、`requires_review`、`used_in_writing`。
- 证据表必须记录来源模块、来源记录 ID、原文片段、AI 抽取置信度、人工确认状态。
- 所有表必须有合理唯一约束和索引。
- migration 和 `schema.sql` 必须同步。

#### 题目难度

高

#### 验收标准

- migration 和 `schema.sql` 都包含新增表。
- 同一用户下同类实体可去重，但不同用户同词不混用个人状态。
- 可以按用户、节点类型、来源模块、更新时间查询。
- 关系表支持有向关系和置信度。
- 单元测试覆盖节点去重、关系去重、证据写入。

### B 小题：设计图谱节点规范化与状态字段

#### 题目 Prompt

请实现知识图谱节点的规范化策略和生命周期状态。

要求：

- `normalized_key` 用于同一用户下实体归一。
- 英文单词统一小写，短语去除多余空格，句子保留原文但生成 normalized hash。
- 节点状态支持 `active`、`merged`、`archived`、`deleted`。
- 节点必须支持 `display_text`、`lang`、`summary`、`metadata_json`。
- 被合并节点需要保留 `merged_into_node_uid`。
- 后端提供规范化 service，不允许散落在 controller 中。

#### 题目难度

高

#### 验收标准

- 同义大小写单词不会重复生成多个 active 节点。
- 合并节点后旧节点不会出现在默认查询中。
- 节点规范化逻辑有独立单元测试。
- 不影响现有词典和写作表。

## 题目 2：跨模块学习来源接入

题目类型：feature迭代

### A 小题：接入写作资产和评分反馈

#### 题目 Prompt

请把用户作文、评分结果、写作教练对话和写作资产预览接入知识图谱来源体系。

要求：

- 作文生成 `essay` 节点。
- 评分反馈中的问题生成 `writing_issue` 节点。
- 写作教练提到的重点短语、句型、语法点生成对应节点。
- 作文与词句节点建立 `appears_in` 或 `used_in_writing` 关系。
- 评分反馈与问题节点建立 `explains` 或 `improves` 关系。
- 需要支持重复构建时幂等，不重复产生节点和边。

#### 题目难度

高

#### 验收标准

- 同一篇作文重复构建图谱不会重复写入。
- 能从作文评分记录看到至少一个 `writing_issue` 节点。
- 图谱证据能追溯到作文 ID 和评分 ID。
- 后端测试覆盖有评分、无评分、有教练对话、无教练对话。

### B 小题：接入单词、词典查询和收藏数据

#### 题目 Prompt

请把词典查询、收藏单词、查询次数、学习状态接入知识图谱。

要求：

- 收藏词生成或更新 `word` 节点。
- 查询词生成轻量节点，只有达到阈值后进入 active 图谱。
- 词典释义、例句、派生词、近义词可作为节点属性或关联节点。
- 用户收藏、掌握、查询次数等个人状态写入 `metadata_json` 或独立状态表。
- 节点证据必须能追溯到词典 entry 和用户行为记录。

#### 题目难度

高

#### 验收标准

- 收藏单词后可在知识图谱中搜索到。
- 查询次数变化后图谱节点状态可更新。
- 词典公共数据和用户个人数据不混淆。
- 测试覆盖收藏、取消收藏、重复查询、词典无结果。

## 题目 3：翻译文档与网页学习内容接入

题目类型：feature迭代

### A 小题：接入网页文档翻译结果

#### 题目 Prompt

请将网站文档翻译功能的结果接入个人知识图谱。

要求：

- 每篇网页或文档生成 `document` 节点。
- 文档分节生成 `translation_segment` 节点。
- AI 提取的关键词、术语、短语、长难句生成对应节点。
- 文档节点与术语节点建立 `appears_in` 关系。
- 翻译结果必须保留原文 URL、标题、抓取时间和分节证据。

#### 题目难度

高

#### 验收标准

- 一篇翻译文档能在图谱中看到文档节点和分节节点。
- 术语节点可以追溯到具体段落。
- URL、标题、原文片段、译文片段都可作为证据展示。
- 重复翻译同一 URL 时不产生无意义重复节点。

### B 小题：接入学习助手对话归档

#### 题目 Prompt

请把学习助手对话中用户明确收藏、追问或多次讨论的内容沉淀到知识图谱。

要求：

- 对话会话可以作为 `document` 或 `conversation` 类型来源。
- 用户追问过的词、短语、语法、写作问题生成节点。
- AI 回复中可复习内容作为证据，但必须标记来源为 AI。
- 需要避免把普通闲聊和低价值回答全部入图。
- 需要为后续人工确认保留状态。

#### 题目难度

高

#### 验收标准

- 对话归档后可生成图谱候选节点。
- AI 来源证据有明确标识。
- 不会把空对话、问候语、无学习价值内容入库。
- 有测试覆盖候选过滤和人工确认状态。

## 题目 4：AI 学习实体抽取 Pipeline

题目类型：0-1代码生成

### A 小题：实现多来源实体抽取任务

#### 题目 Prompt

请实现统一的学习实体抽取 Pipeline，用于从作文、翻译文档、对话、单词行为中抽取图谱节点和关系。

要求：

- 新增抽取任务表，例如 `learning_graph_extraction_run`。
- 支持来源类型、来源 ID、用户 ID、状态、错误信息、耗时、模型、token 用量。
- 抽取结果先进入候选区，不直接污染正式图谱。
- 支持本地规则抽取和 AI 抽取两种 extractor。
- 同一来源重复触发时幂等。

#### 题目难度

高

#### 验收标准

- 可以触发一次 extraction run 并记录状态。
- 成功、失败、跳过、重试都有明确状态。
- 不同来源可以共用同一 Pipeline。
- 单元测试覆盖本地 extractor 和 AI extractor 的分支。

### B 小题：设计结构化 AI 输出 Schema

#### 题目 Prompt

请为图谱抽取设计严格 JSON Schema，并实现解析、校验和降级逻辑。

Schema 至少包含：

- `nodes`
- `edges`
- `evidence`
- `confidence`
- `language`
- `source_spans`
- `review_reasons`

要求：

- AI 输出必须经过 schema parse。
- parse 失败时记录失败原因，不写入正式图谱。
- 置信度低于阈值的内容进入待确认。
- 不允许 AI 编造来源片段，必须引用输入文本中的 evidence。

#### 题目难度

高

#### 验收标准

- schema parse 成功后生成候选节点。
- schema parse 失败有可定位错误。
- AI 输出没有 source span 时不会自动入正式图谱。
- 测试覆盖合法 JSON、缺字段、错误类型、幻觉 evidence。

- 返回结果包含 `keywordScore`、`vectorScore`、`graphScore`。
- 测试覆盖用户隔离和召回融合。

## 题目 6：GraphRAG 问答链路

题目类型：0-1代码生成

### A 小题：实现个人知识图谱问答接口

#### 题目 Prompt

请实现基于个人学习知识图谱的 GraphRAG 问答接口。

新增接口建议：

- `POST /api/learning-graph/ask`
- `GET /api/learning-graph/ask/runs/{runUid}`

请求支持：

- 用户问题
- 可选模块范围
- 可选节点类型
- 是否允许 AI 总结
- 是否仅返回证据

回答要求：

- 先检索证据，再生成答案。
- 答案必须附带引用来源。
- 没有足够证据时必须明确说证据不足。
- 记录完整 run，包括检索结果、prompt、模型、token、耗时、错误。

#### 题目难度

极高

#### 验收标准

- 用户可以问“我最近常犯哪些写作错误？”并得到带证据的回答。
- 用户可以问“我收藏过哪些和创新相关的表达？”并召回词典和作文证据。
- 无证据时不编造。
- run 详情可在后台调试查看。
- 测试覆盖有证据、无证据、模型失败、检索失败。

### B 小题：实现 GraphRAG Prompt 和引用格式

#### 题目 Prompt

请设计 GraphRAG 的 Prompt 组装和引用格式。

要求：

- Prompt 中区分用户问题、检索证据、图谱关系、回答约束。
- 每条证据有 `citation_id`。
- AI 回答必须引用 citation id。
- 回答中不能出现未引用的具体学习事实。
- 如果证据冲突，需要说明冲突而不是强行合并。
- Prompt 版本需要可追踪。

#### 题目难度

极高

#### 验收标准

- 返回答案包含 citations。
- 引用能定位到原始作文、翻译文档或词典条目。
- Prompt 版本写入 run。
- 测试覆盖缺引用、证据冲突和证据不足。

## 总体验收标准

- 新增功能必须保持用户数据隔离，不允许跨用户召回、展示或生成答案。
- 所有 AI 生成内容必须可追溯到证据；证据不足时必须拒答或仅展示检索结果。
- 图谱构建必须幂等，重复运行不产生大量重复节点和边。
- GraphRAG run 必须可调试，至少记录检索、prompt、模型、引用和错误。
- 前端必须有空状态、加载态、错误态和无权限态。
- 所有高风险接口必须有后端测试。
- 不允许把复杂判断全部硬编码在前端。
- 不允许单文件完成题目；每题至少涉及跨层改动或配套测试。
- 文档必须同步说明数据模型、AI 链路、降级策略和上线开关。

6. 题目 16-18：补后台、评测、安全隔离。

8. 题目 25-28：做导出、测试、灰度和文档。

# Prompt 与 Rubric 自动化评测平台 Trae 题目

## 背景

当前项目已经有写作评分、翻译、单词解释、写作教练、学习建议、Agent Debug、AI 用量记录等能力。随着 Prompt、Rubric、模型和业务场景增多，需要建设一套自动化评测平台，用来评估不同 Prompt、Rubric、模型和参数组合在真实学习任务中的表现，避免每次改 Prompt 都只能靠人工体验。

本题单目标是建设“Prompt / Rubric 评测平台”，覆盖评测集管理、人工标注、模型对比、自动回归、评分维度、可视化看板、CI 检查和管理员治理。所有题目都应避免单文件修改，每题至少涉及数据库、后端、前端、AI 调用、测试或文档中的两类以上改动。

## 题目类型范围

- 0-1代码生成
- feature迭代
- bug修复
- 工程化
- 代码测试

## 题目 1：评测平台领域模型与数据库设计

题目类型：0-1代码生成

### A 小题：设计评测集、样例和运行表

#### 题目 Prompt（完成）

请为 Prompt / Rubric 自动化评测平台设计数据库模型。

至少新增：

- `ai_eval_dataset`
- `ai_eval_case`
- `ai_eval_case_input`
- `ai_eval_expected_output`
- `ai_eval_run`
- `ai_eval_run_case`
- `ai_eval_metric_result`

要求：

- 支持评测类型：`writing_score`、`translation`、`word_explanation`、`learning_advice`、`writing_coach`。
- 评测集支持版本、状态、负责人、说明、标签。
- 样例支持输入、期望输出、人工标注、禁用原因。
- 运行记录支持模型、Prompt 版本、Rubric 版本、参数、耗时、token、状态和错误。
- migration 和 `schema.sql` 同步。

#### 题目难度

高

#### 验收标准

- 新增表结构完整，字段覆盖评测集、样例、运行和指标。
- 关键查询有索引，例如按 dataset、run、case、status、eval_type。
- 支持同一评测集多版本。
- 后端测试覆盖创建评测集、添加样例、创建运行记录。

### B 小题：设计评测维度和指标口径

#### 题目 Prompt

请设计评测指标体系，并实现指标定义表和后端读取服务。

至少支持：

- `accuracy`
- `rubric_alignment`
- `citation_coverage`
- `format_validity`
- `hallucination_risk`
- `language_quality`
- `safety`
- `latency_ms`
- `token_cost`

要求：

- 每个指标包含名称、适用评测类型、分值范围、是否越高越好、说明。
- 指标定义可配置，不硬编码在前端。
- 不同评测类型可以启用不同指标组合。

#### 题目难度

高

#### 验收标准

- 后端能返回某类评测启用的指标。
- 前端能根据指标定义动态展示表头和说明。
- 修改指标定义不需要改前端代码。
- 测试覆盖指标启用、禁用和排序。

## 总体验收标准

- 不允许单文件完成题目；每题必须涉及跨层改动或配套测试。
- 评测结果必须可追溯到评测集、样例、Prompt 版本、Rubric 版本和模型配置。
- AI Judge 必须可关闭，规则评测必须能独立运行。
- 所有真实业务样例生成必须脱敏。
- 评测平台不得影响用户侧主链路。
- 评测失败原因必须可定位到 case、指标和模型输出。
- 管理后台所有写操作必须有权限和审计日志。
- CI / 本地运行必须支持 mock 模型，不依赖真实密钥。

## 推荐实现顺序

1. 题目 1-3：先完成评测数据模型、后台和样例标注。
2. 题目 4-5：接入真实业务数据和 Prompt / Rubric 快照。
3. 题目 6-10：实现 Runner、业务评测、Judge 和人工复核。
4. 题目 11-14：实现模型对比、门禁、看板和调试。
5. 题目 15-18：补权限、导入导出、成本控制、测试和文档。

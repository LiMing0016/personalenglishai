# 牛津词典全量入库与前端查询闭环 Trae 题目

## 背景

当前项目已经具备管理员数据清洗中心、词典包上传、词库元数据登记、本地词典优先查询的基础能力。但要让牛津词典真正进入用户侧单词页，还需要把链路从“词库已安装”推进到“正文内容已全量入库”。

本题目标是跑通完整闭环：

```text
上传词典包 -> Python 解析 MDX/MDD/XLSX -> Java 异步任务编排 -> 批量写入正式词典表 -> 后台查看进度和样例 -> 单词页查询展示
```

需要明确区分两类状态：

- `词库元数据已登记`：`dictionary_library` 有记录，表示项目知道这个词库包。
- `正文内容已入库`：`dictionary_entry / dictionary_sense / dictionary_example / dictionary_phrase / dictionary_resource` 有有效数据，表示用户侧可以查询词典正文。

## 总体要求

1. 不改生产登录逻辑，不绕过管理员鉴权。
2. 不通过 IP、User-Agent 或硬编码浏览器特征绕过权限。
3. 不把 MDX/MDD/XLSX/JPG/ZIP 等词典原始文件提交到 Git。
4. 默认做全量导入，`limit=0` 表示不限制词条数。
5. 大文件导入必须异步执行，不能阻塞 HTTP 请求。
6. Python 负责解析和清洗，Java 负责任务状态、权限、数据库写入和前端 API。
7. 如果 Python 缺少 `readmdict` 或 LZO 依赖，任务必须失败并显示可读错误，不能显示“已完成但 0 条入库”。
8. 用户侧单词页只展示正式表中已入库的数据，不允许写死 mock 结果。

## 题目 1：后台全量正文入库任务状态流转（完成）

### 题目 Prompt

请把管理员词库正文入库从同步小批量任务升级为异步全量任务。管理员在 `/admin/data-cleaning` 点击“开始全文入库”后，后端应创建 `dictionary_import_job`，初始状态为 `queued`，随后由后台线程执行 Python worker。接口应立即返回任务信息，页面通过轮询展示进度。

### A 小题：后端异步任务编排

实现要求：

1. 新增或复用专用异步 executor，例如 `dictionaryImportExecutor`。
2. `POST /api/admin/dictionaries/{dictionaryUid}/import-jobs` 默认 `limit=0`。
3. 创建任务时：
   - `status=queued`
   - `import_limit=0`
   - `processed/imported/failed` 计数初始化为 0
   - `dictionary_library.status=importing`
4. 后台执行时：
   - 状态改为 `running`
   - 写入 `started_at`
   - 调用 Python worker
   - 成功后进入 `completed` 或 `completed_with_warnings`
   - 失败后进入 `failed`
5. 任务失败时必须写入 `error_message` 和可读的 `result_json`。

#### 难度

困难

#### 验收标准

- 创建入库任务接口不会等待全量 MDX 解析完成。
- 任务状态能从 `queued -> running -> completed / failed / completed_with_warnings` 正确流转。
- Python 失败或 0 词条导入时，任务不会显示 `completed`。
- 后端测试覆盖 queued 返回、失败任务、部分成功任务。

### B 小题：后台页面展示入库中状态

实现要求：

1. `/admin/data-cleaning` 的“开始全文入库”按钮在任务 `queued/running` 时禁用。
2. 按钮文案显示 `入库中...`。
3. 页面每隔数秒刷新词库、任务和样例数据。
4. 最近任务展示处理数、成功数、失败数、例句数、短语数。
5. 任务失败时展示失败原因，不只展示通用错误。

#### 难度

中等

#### 验收标准

- 点击“开始全文入库”后页面不会卡住。
- 入库过程中按钮不可重复点击。
- 任务完成后页面显示最新统计。
- 失败原因能在后台页面看到。
- `npm run build` 通过。

## 题目 2：Python 全量解析批处理输出（完成）

### 题目 Prompt

请升级 Python 词典清洗 worker，使其支持真实 MDX/MDD/XLSX 全量解析，但不要一次性把全部词条放入内存或塞进返回 JSON。Python 应按批次写出结构化词条文件，并在结果 JSON 中返回 `entryBatchPaths`，由 Java 读取并入库。

### A 小题：MDX/MDD/XLSX 批处理解析

实现要求：

1. 使用 `readmdict` 读取 MDX/MDD。
2. 启动前检查 `readmdict` 和 LZO 支持。
3. 缺少依赖时返回明确错误，例如提示安装兼容 `python-lzo/lzo`。
4. MDX 解析字段至少包括：
   - 词头
   - 音标
   - 词性
   - 英文释义
   - 中文释义
   - 例句
   - 短语/习语
   - 原始 HTML
   - 清洗文本
5. MDD 输出资源索引：resource key、类型、文件名、大小、存储路径。
6. XLSX 例句按 headword 合并；不能匹配的例句进入 warning 或未匹配样例。

#### 难度

困难

#### 验收标准

- 能以 `python -m python.ai_orchestrator.workflows.dictionary_cleaning.cli --input request.json --output result.json` 运行。
- 输出 JSON 包含 `entryBatchPaths`、`summary`、`resources`、`warnings`。
- 大文件导入不会把所有词条放进 `entries`。
- 缺少依赖时失败信息可读。

### B 小题：牛津标签结构化清洗

实现要求：

1. 支持牛津 MDX 自定义标签：
   - `h`
   - `phon`
   - `pos`
   - `def`
   - `chn`
   - `x`
   - `unbox`
   - `idm-g`
2. `h` 映射词头。
3. `phon` 映射音标。
4. `pos` 映射词性。
5. `def/chn` 映射英中释义。
6. `x/chn` 映射英中例句。
7. `idm-g` 映射短语或习语。
8. `unbox` 映射用法说明。

#### 难度

中等偏难

#### 验收标准

- Python 单测覆盖上述标签解析。
- 解析结果能产出词条、释义、例句、短语。
- 例句 XLSX 能补充到对应词条。
- 未匹配例句不会导致整个任务失败。

## 题目 3：Java 批量写入正式词典内容表

### 题目 Prompt（完成）

请实现 Java 侧读取 Python worker 批次结果并写入正式词典内容表。正文必须进入数据库正式表，不能只停留在上传文件、数据源登记或临时 JSON。

### A 小题：批次结果读取与幂等写入

实现要求：

1. 从 worker 返回的 `entryBatchPaths` 逐个读取批次 JSON。
2. 写入：
   - `dictionary_entry`
   - `dictionary_pronunciation`
   - `dictionary_sense`
   - `dictionary_example`
   - `dictionary_phrase`
   - `dictionary_resource`
3. 同一词库重复导入时，按 `dictionary_uid + source_entry_id/headword` 幂等更新。
4. 更新词条前清理旧的 pronunciation/sense/example/phrase 子表数据，避免重复子记录。
5. 写入失败的词条进入任务 failures，不影响其它词条继续处理。

#### 难度

困难

#### 验收标准

- 正式内容表有真实词条数据。
- 重复导入同一词库不会产生重复词条。
- 子表不会因重复导入无限增长。
- 后端测试覆盖重复导入幂等。

### B 小题：任务统计与词库状态

实现要求：

1. 准确更新：
   - `processed_entries`
   - `imported_entries`
   - `failed_entries`
   - `imported_examples`
   - `imported_phrases`
2. 导入成功后 `dictionary_library.status=imported`。
3. 0 词条导入或 worker 失败时 `dictionary_library.status=failed`。
4. 有失败样例但成功导入部分词条时任务状态为 `completed_with_warnings`。
5. `result_json` 中保留 summary、样例词条、失败样例和资源计数。

#### 难度

中等偏难

#### 验收标准

- 后台任务统计与数据库实际入库数量一致。
- 失败任务有明确错误信息。
- 部分成功任务显示 `completed_with_warnings`。
- 管理员可以查看失败样例。

## 题目 4：用户侧单词页本地词典查询展示

### 题目 Prompt

请确保用户侧 `/app/vocabulary` 查询单词时优先读取已入库的本地词典内容。本地词典命中时展示牛津来源标识、音标、词性、释义、例句和短语；本地未命中时保留原有兜底逻辑。

### A 小题：后端本地优先查询

实现要求：

1. `GET /api/dictionary/lookup?word=home` 先查询正式词典表。
2. 只查询启用词库中的 active 词条。
3. 支持 `dictionary_library.status IN ('installed', 'imported', 'published')`。
4. 本地命中时返回 `source=local`。
5. 本地未命中时走原有 Oxford 或原有兜底逻辑。

#### 难度

中等

#### 验收标准

- 本地有 `home` 时接口返回本地词典内容。
- 本地命中时不会调用外部 Oxford。
- 本地未命中时原有兜底逻辑不受影响。
- 后端测试覆盖本地命中和兜底。

### B 小题：前端查询结果展示

实现要求：

1. `/app/vocabulary` 查询结果显示来源：
   - `source=local` 显示 `已安装本地词典`
   - `source=oxford` 显示 `Oxford Dictionaries`
2. 展示词性、音标、释义、例句和短语。
3. 如果词库还只是元数据登记、正文未入库，不显示假数据。
4. 空结果沿用原有空态或错误提示。

#### 难度

简单到中等

#### 验收标准

- 查询已入库单词时页面显示本地词典来源。
- 查询未入库单词时页面不展示假结果。
- `npm run build` 通过。

## 总体验收标准

1. 上传词典包后，后台能看到词库元数据。
2. 点击“开始全文入库”后，后台任务进入 `queued/running`，页面不阻塞。
3. Python 按批次解析 MDX/MDD/XLSX。
4. Java 将正文写入正式词典内容表。
5. 任务完成后后台展示处理数、成功数、失败数、例句数、短语数。
6. 失败任务有可读错误，不能静默成功。
7. 重复导入同一词库不会制造重复词条。
8. `/app/vocabulary` 查询已入库单词时，能展示本地牛津词典内容。
9. 生产登录逻辑不受影响。
10. 原始词典文件不进入 Git。

## 注意事项

- `dictionary_library` 有记录不代表用户能查到词典正文。
- 只有 `dictionary_entry` 等正式内容表有数据后，用户侧本地查询才会命中。
- Windows 环境下 `readmdict` 解析 MDX 可能依赖 LZO，缺失时要在任务中明确提示。
- 不要为了让页面好看而写死 `home/apple` 等 mock 结果。
- 未确认授权前，导入内容只能用于内部验证。

# 本地词典优先接入单词页查询 Trae 题目

## 背景

当前管理员数据清洗中心已经可以登记词典包，并把词典元信息写入 `dictionary_library`。后续 Python worker 会把 `.mdx/.mdd/.xlsx` 解析后的正文写入正式词典内容表：

- `dictionary_entry`
- `dictionary_pronunciation`
- `dictionary_sense`
- `dictionary_example`
- `dictionary_phrase`
- `dictionary_resource`

用户侧 `/app/vocabulary` 单词页已经有搜索框，并调用现有 `GET /api/dictionary/lookup`。但此前该接口主要依赖外部 Oxford API。为了让管理员导入的本地牛津词典真正服务用户，需要把查询链路改成“本地已安装词典优先，外部 Oxford 兜底”。

## 总体要求

1. 不新增复杂用户侧入口，优先复用现有 `GET /api/dictionary/lookup`。
2. 查询时先查本地词典内容表；本地命中时返回 `source=local`。
3. 本地未命中时继续走原有 Oxford 外部 API 兜底。
4. 前端单词页能够区分“已安装本地词典”和 “Oxford Dictionaries”。
5. 不改生产登录逻辑，不绕过鉴权。
6. 不把 MDX/MDD 原始词典文件提交到 Git。
7. 需要保留现有前端返回结构兼容，避免破坏单词页已有展示。

## 非目标

- 不做词典正文解析能力本身。
- 不做 Python worker 安装依赖或批处理导入。
- 不做用户收藏、复习、掌握状态的正式入库。
- 不做全文搜索、模糊搜索、联想搜索。
- 不做词典资源图片和音频的完整展示。

## 题目 1：后端实现本地词典优先查询

### 发给 Trae 的 Prompt

请在后端实现本地词典优先的单词查询链路。用户调用 `GET /api/dictionary/lookup?word=home&language=en-gb` 时，后端应先从正式词典内容表读取已安装词典的词条、音标、释义、例句和短语；如果本地没有命中，再走原来的 Oxford 查询服务。接口路径和基本响应结构保持兼容。

### 小题 A：新增只读词典内容 Mapper

#### 题目 Prompt

请新增一个面向用户查询的只读 Mapper，例如 `DictionaryContentMapper`，读取正式词典内容表。

至少支持：

1. 按 `normalized_headword` 查询启用词库中的 active 词条。
2. 按 `entry_uid` 批量读取音标。
3. 按 `entry_uid` 批量读取义项。
4. 按 `entry_uid` 批量读取例句。
5. 按 `entry_uid` 批量读取短语。

查询约束：

- 只读取 `dictionary_library.enabled = 1` 的词库。
- 只读取 `dictionary_library.status IN ('installed', 'published')` 的词库。
- 只读取 `dictionary_entry.status = 'active'` 的词条。
- 第一版可以精确匹配 `normalized_headword`，不要求模糊查询。

#### 难度

中等

#### 验收标准

- 新增 Mapper 接口和 XML SQL。
- SQL 不修改数据，只做查询。
- 查询结果字段能覆盖 `entryUid/headword/partOfSpeech/cleanText/definitionEn/definitionZh/textEn/textZh/phraseText/phonetic` 等核心展示字段。
- 空结果时返回空列表，不抛业务异常。

### 小题 B：新增本地优先查询 Service

#### 题目 Prompt

请新增本地优先查询服务，例如 `LocalFirstDictionaryLookupService`，实现现有 `DictionaryLookupService` 接口，并设置为优先 Bean。

行为要求：

1. 对用户输入单词做 trim 和小写标准化。
2. 先调用本地 Mapper 查询正式词典内容表。
3. 如果本地命中：
   - 返回 `DictionaryLookupResponse`
   - `source` 设置为 `local`
   - `word` 使用词典中的 `headword`
   - `language` 保留请求语言，缺省为 `en-gb`
   - `phonetics` 来自 `dictionary_pronunciation`
   - `entries` 按词条组装 `partOfSpeech/definitions/examples`
   - 英文释义和中文释义可以用 `；` 拼接
   - 英文例句和中文译文可以用空格拼接
   - 短语可追加到 definitions 中，格式为 `短语：xxx - 释义`
4. 如果本地未命中：
   - 调用原有 Oxford 查询服务
   - 保持原有错误映射逻辑不变

#### 难度

中等

#### 验收标准

- 本地有词条时不会调用 Oxford 服务。
- 本地无词条时会调用 Oxford 服务兜底。
- 返回结构与现有前端 `DictionaryLookupResponse` 兼容。
- 不改变 `DictionaryController` 的路由路径。
- 不破坏现有 Oxford 查询测试。

## 题目 2：前端单词页展示本地词典来源

### 发给 Trae 的 Prompt

请调整 `/app/vocabulary` 单词页，让用户查询单词时可以看到结果来自“已安装本地词典”还是 “Oxford Dictionaries”。不要重做页面，不新增复杂状态管理，只在现有查询结果展示区域做最小兼容改造。

### 小题 A：扩展前端词典 API 类型

#### 题目 Prompt

请修改 `web/src/api/dictionary.ts` 的类型定义，让 `DictionaryLookupResponse.source` 支持本地词典来源。

要求：

1. `source` 支持 `local`。
2. 继续兼容 `oxford`。
3. 不破坏现有 `lookupDictionary` 方法。
4. 不新增前端依赖。

#### 难度

简单

#### 验收标准

- `source` 类型不再只允许 `oxford`。
- `npm run build` 类型检查通过。

### 小题 B：单词页显示查询来源

#### 题目 Prompt

请修改 `web/src/views/VocabularyView.vue`，在查询结果区域根据 `result.source` 显示不同来源标题。

展示建议：

- `source === 'local'`：显示 `已安装本地词典`
- `source === 'oxford'`：显示 `Oxford Dictionaries`
- 其他未知来源：显示原始 `source` 或 `词典查询`

同时把页面中“接口接入状态”的说明更新为：顶部搜索框已调用真实后端词典接口，本地已安装词典优先。

#### 难度

简单

#### 验收标准

- 查询本地命中词条时，结果区域标题显示 `已安装本地词典`。
- Oxford 兜底时，结果区域标题仍显示 `Oxford Dictionaries`。
- 页面不存在写死 Oxford 的单一来源误导。
- `npm run build` 通过。

## 推荐测试计划

### 后端测试

1. 新增 `LocalFirstDictionaryLookupServiceTest`：
   - 本地词典命中时返回 `source=local`。
   - 本地词典命中时不会调用 Oxford。
   - 本地词典未命中时调用 Oxford 兜底。
2. 保留并运行现有 `DictionaryControllerTest`。
3. 运行：

```bash
cd backend
.\mvnw.cmd -q -Dtest=LocalFirstDictionaryLookupServiceTest test
.\mvnw.cmd -q test
```

### 前端测试

1. 运行：

```bash
cd web
npm run build
```

2. 手动验证：
   - 确认数据库中 `dictionary_entry` 有正文词条。
   - 进入 `/app/vocabulary`。
   - 搜索一个已入库词，例如 `home`。
   - 页面显示 `已安装本地词典`，并展示释义和例句。
   - 搜索一个本地没有的词时，仍能走 Oxford 兜底或显示原有错误提示。

## 注意事项

- “词库已安装”不等于“正文已入库”。只有 `dictionary_entry`、`dictionary_sense`、`dictionary_example` 等表有数据后，用户侧本地查询才会命中。
- 如果本地查询一直查不到，请先检查 Python worker 是否成功解析 MDX/MDD 并写入正式词典内容表。
- 不要为了让页面显示成功而写死前端 mock 数据。
- 不要通过 IP、User-Agent 或浏览器特征绕过任何鉴权。

# 管理员数据清洗中心词典上传与前端设计 Trae 题目

## 背景

当前管理员端已经有“数据清洗中心”的词典源登记与轻量探查能力。现阶段需要继续补齐“上传词典包”能力，并把前端页面从简单表单升级为更符合后台数据治理场景的工作台。

本轮目标：

- 管理员可以直接在浏览器上传词典文件或 ZIP 包。
- 后端把上传文件保存到受控目录，并自动登记为词典数据源。
- 上传后自动创建词典探查任务，复用现有 MDX/MDD/XLSX 轻量探查能力。
- 前端“词典源”工作台同时支持“上传词典包”和“服务器路径登记”两种方式。
- 页面设计需要符合后台中台产品规范，不做简陋表单堆叠。

核心原则：

- 不绕过管理员鉴权。
- 不把上传文件保存到代码目录。
- 不把词典文件提交到 Git。
- 不全量解析 MDX/MDD 正文。
- ZIP 解包必须防路径穿越。
- 未确认授权前，词典内容只能用于内部验证，不发布给用户侧。

## 题目 1：实现后端词典文件上传接口

难度：困难（完成）

### A 小题：新增上传接口与参数接收

请新增管理员端上传接口：

```http
POST /api/admin/data-cleaning/dictionary-uploads
Content-Type: multipart/form-data
```

表单字段：

- `sourceCode`
- `displayName`
- `licenseStatus`
- `files`

要求：

1. 必须校验管理员写权限。
2. `sourceCode` 和 `displayName` 必填。
3. `files` 至少包含一个非空文件。
4. 支持多文件上传。
5. 上传成功后返回本次自动创建的 `dictionary_probe` 任务响应。

### B 小题：上传后创建词典源并自动探查（完成）

上传完成后请复用现有 `data_cleaning_source` 和 `data_cleaning_job` 设计。

要求：

1. 上传文件保存成功后创建 `data_cleaning_source`。
2. `source_type` 固定为 `dictionary`。
3. `status` 初始为 `registered`。
4. 自动创建一次 `dictionary_probe` 任务。
5. 探查成功后数据源状态更新为 `probed`。
6. `metadata_json` 需要保留上传来源信息，例如 `createdFrom=admin_dictionary_upload`、`uploadDir`、`uploadedFiles`。

### 给 Trae 的 Prompt

请为管理员数据清洗中心新增词典文件上传接口。接口使用 `multipart/form-data`，接收 `sourceCode`、`displayName`、`licenseStatus` 和多个 `files`。上传成功后把文件保存到受控目录，创建词典数据源，并自动触发一次 `dictionary_probe` 探查任务。注意不要改生产登录逻辑，不要绕过管理员权限。

### 验收标准

- 存在 `POST /api/admin/data-cleaning/dictionary-uploads`。
- 无写权限管理员不能上传。
- 上传 `.mdx/.mdd/.xlsx` 后可以自动创建词典源。
- 上传后自动生成探查任务。
- 探查结果仍写入 `data_cleaning_job.result_json`。
- 数据源 `metadata_json` 保留上传元数据。

## 题目 2：实现安全的词典文件存储与 ZIP 解包

难度：困难（完成）

### A 小题：受控目录存储

请实现词典上传文件存储能力。

要求：

1. 默认存储目录为 `storage/data-cleaning/dictionaries`。
2. 支持通过环境变量 `DATA_CLEANING_DICTIONARY_UPLOAD_DIR` 覆盖。
3. 每个词典源独立目录，例如 `{sourceCode}-{sourceUid}`。
4. 文件名需要清洗，避免控制字符、路径分隔符和非法字符。
5. 重名文件需要安全处理，不能直接覆盖已有文件。
6. `storage/` 必须加入 `.gitignore`。

### B 小题：ZIP 白名单解包（完成）

请支持上传 `.zip` 词典包。

要求：

1. ZIP 内只保留 `.mdx`、`.mdd`、`.xlsx`、`.jpg`、`.jpeg`、`.png`。
2. ZIP 内的 `.zip` 不递归解包。
3. 必须防止 `../`、绝对路径、路径穿越。
4. 不允许把文件解包到目标目录外。
5. ZIP 内无有效词典文件时返回明确错误。

### 给 Trae 的 Prompt

请为词典上传实现安全文件存储和 ZIP 解包。所有文件必须写入受控目录，文件名必须清洗，ZIP 只允许词典相关扩展名，并防止路径穿越。不要把上传文件保存到代码目录，也不要让上传文件进入 Git。

### 验收标准

- 上传文件落在 `storage/data-cleaning/dictionaries` 或配置目录下。
- `.gitignore` 忽略 `storage/`。
- ZIP 解包不会写出目标目录。
- 不支持的扩展名会被拒绝或忽略，并有清晰错误。
- 上传后 `mdxPath/mddPath/examplesPath/coverImagePath` 能正确指向保存文件。

## 题目 3：调整后端上传配置与测试覆盖

难度：中等偏难

### A 小题：调整大文件上传配置（完成）

词典文件通常较大，请调整后端上传限制。

建议默认值：

- `SPRING_SERVLET_MULTIPART_MAX_FILE_SIZE=512MB`
- `SPRING_SERVLET_MULTIPART_MAX_REQUEST_SIZE=768MB`
- `SERVER_TOMCAT_MAX_HTTP_FORM_POST_SIZE=512MB`

要求：

1. 配置值必须可通过环境变量覆盖。
2. 不要把限制写死在业务代码里。
3. 文档中说明这些值需要按服务器磁盘、网关和内网环境调整。

### B 小题：补充后端测试

请补充 `AdminDataCleaningServiceTest` 或等价测试。

测试至少覆盖：

1. 上传 `.mdx/.mdd/.xlsx` 后生成词典源。
2. 上传后文件实际存在于受控目录。
3. 上传后自动生成探查任务。
4. 探查能读取上传文件元信息。
5. 上传 metadata 不会被探查 metadata 覆盖。
6. 非法扩展名或空文件会失败。

### 给 Trae 的 Prompt

请调整后端 multipart 上传配置以支持较大词典文件，并为词典上传补充单元测试。测试需要验证文件落盘、词典源创建、探查任务生成、元数据保留和异常场景。

### 验收标准

- 上传大小配置支持环境变量覆盖。
- 后端定向测试通过。
- 上传 metadata 和探查 metadata 能合并保留。
- 空文件、不支持扩展名、无有效词典文件时有明确失败。
- `.\mvnw.cmd -q test` 通过。

## 题目 4：实现前端上传词典包交互

难度：中等偏难

### A 小题：扩展 Admin API

请在 `web/src/api/admin.ts` 增加上传 API。

建议方法：

```ts
uploadDictionaryDataCleaningSource(payload, files)
```

要求：

1. 使用 `FormData`。
2. 提交 `sourceCode`、`displayName`、`licenseStatus`。
3. 支持多个文件。
4. 返回 `AdminDataCleaningJob`。
5. 保持已有路径登记 API 不变。

### B 小题：在词典源工作台增加上传区

请在 `/admin/data-cleaning` 的“词典源”工作台增加“上传词典包”模块。

页面要求：

1. 上传区展示在词典源登记表单内或附近。
2. 支持选择多个文件。
3. 支持扩展名提示：`.mdx/.mdd/.xlsx/.jpg/.png/.zip`。
4. 展示已选文件名和大小。
5. 上传按钮文案为“上传并探查”。
6. 上传成功后刷新数据源、任务和最近探查结果。
7. 上传失败时显示明确错误。

### 给 Trae 的 Prompt

请在管理员数据清洗中心前端加入“上传词典包”交互。管理员填写来源编码、显示名称和授权状态后，可以选择 MDX/MDD/XLSX/图片/ZIP 文件并点击“上传并探查”。上传成功后刷新页面数据。保留原来的服务器路径登记能力。

### 验收标准

- 页面出现“上传词典包”区域。
- `<input type="file" multiple>` 存在。
- 可显示选择的文件名和大小。
- 点击“上传并探查”会调用上传 API。
- 上传成功后展示成功提示并刷新列表。
- `npm run build` 通过。

1. 不要大面积堆纯白表单。

### 验收标准

# 词典清洗中心已安装词库与正文入库闭环 Trae 题目

## 背景

当前项目已经在管理员端规划了“数据清洗中心”，用于处理词典类数据资产。新的迭代目标不是只上传文件或登记路径，而是把词典包真正沉淀为项目可管理、可查看、可导入、可追踪的“已安装词库”，并进一步打通 Python worker 对 MDX/MDD/XLSX 的结构化解析，把词典正文写入正式词典内容表。

这个功能类似欧路词典的“词库管理”能力：管理员可以看到项目里已经有哪些词库、词库文件信息、授权状态、入库状态、词条样例、失败样例和导入进度。后续用户侧“查词、我的单词、作文资产提取词汇”等能力，都应基于正式词典内容表查询，而不是只依赖上传文件。

核心原则：

- Java / Spring Boot 负责管理员鉴权、文件上传、数据源登记、任务创建、状态流转、数据库写入、前端 API、审核与发布控制。
- Python worker 负责 MDX/MDD 深度解析、HTML 清洗、词条结构化、例句清洗对齐、短语搭配抽取、重复词合并、字段质量评分。
- 不通过 IP、User-Agent 或硬编码浏览器特征绕过鉴权。
- 不把大型 MDX/MDD/ZIP 词典文件提交到 Git。
- 首版允许同步小批量导入验证，但接口和表结构要能自然演进到异步批处理。
- 未授权词库只能用于内部验证，不能默认开放给用户侧生产查询。

## 题目 1：已安装词库注册表与词库信息落库

难度：中等

### A 小题：设计正式词库注册表

设计并新增 `dictionary_library` 表，用于保存项目中已安装或已登记的词库信息。字段至少包含词库 UID、来源编码、显示名称、格式、授权状态、导入状态、MDX/MDD/例句表/封面路径、文件名、文件大小、词条数量、例句数量、资源数量、最后探查时间、最后导入时间、创建时间、更新时间。

要求表结构能区分“已上传但未探查”“已探查”“已入库”“入库失败”“已禁用”等状态。

### B 小题：上传或探查成功后写入词库注册表

在管理员端上传词典包或手动创建探查任务成功后，将词库信息 upsert 到 `dictionary_library`。如果 `sourceCode` 已存在，不应直接数据库异常退出，而是返回明确错误或更新已有记录，前端要能展示“词库源编码已存在”。

### 给 Trae 的 Prompt

请在当前 Spring Boot 后端实现词典注册表落库能力。新增 `dictionary_library` 表和对应 Mapper/Service 方法，并在数据清洗中心上传词典包、保存草稿、创建探查任务的成功链路中写入或更新词库信息。要求保留管理员鉴权，不修改生产登录逻辑，不提交任何大型词典文件。重复 `sourceCode` 时要返回可读错误，不能只让 SQL 异常冒泡。

### 验收标准

- 数据库中存在 `dictionary_library` 表，并能保存词库元信息。
- 上传或探查成功后，管理员刷新页面仍能看到该词库。
- 重复上传同一 `sourceCode` 时，接口返回明确错误信息。
- 不提交 `.mdx`、`.mdd`、大型 `.zip` 文件到 Git。
- 后端相关测试通过，至少覆盖词库注册、重复编码、状态更新。

## 题目 2：管理员端已安装词库列表与词库详情

难度：中等

### A 小题：新增管理员词库查询接口

新增管理员接口：

- `GET /api/admin/dictionaries`
- `GET /api/admin/dictionaries/{dictionaryUid}`

列表接口返回所有已登记词库的核心信息，包括名称、编码、授权、状态、MDX/MDD 文件名、文件大小、词条数量、例句数量、资源数量、更新时间。详情接口返回单个词库的完整元数据和最近导入任务摘要。

### B 小题：前端展示“已安装词库”

在管理员数据清洗中心新增“已安装词库”区域，类似欧路词典词库管理界面，展示项目中已经有哪些词库。每个词库需要展示名称、格式、授权状态、本地/内置来源、MDX/MDD/例句表存在情况、导入状态、统计数量和最近更新时间。

### 给 Trae 的 Prompt

请补齐管理员端已安装词库展示能力。后端提供词库列表和详情 API，前端在数据清洗中心展示“已安装词库”模块。这个模块不是展示词典正文，而是展示词库管理信息，方便管理员判断项目里有哪些词典、文件是否齐全、是否已经入库、是否可以继续导入。

### 验收标准

- `/admin/data-cleaning` 页面能看到“已安装词库”列表。
- 上传或登记过的词库刷新页面后仍显示。
- 列表为空时有明确空状态，不显示误导性成功。
- 词库状态、授权状态、文件存在情况可读。
- 前端构建通过。

## 题目 3：正式词典内容表设计

难度：较高

### A 小题：设计词典正文核心表

新增正式词典内容表，至少包括：

- `dictionary_entry`：词条主表，保存 headword、slug、原始 HTML、纯文本、标签摘要、来源词库、质量分等。
- `dictionary_pronunciation`：音标和发音资源，支持英音/美音、多音标、多音频引用。
- `dictionary_sense`：释义义项，支持词性、英文释义、中文释义、义项序号、领域标签、用法标签。
- `dictionary_example`：例句，支持英文例句、中文译文、来源、关联义项、质量分。
- `dictionary_phrase`：短语、习语、搭配，支持 phrase、解释、例句、类型。
- `dictionary_resource`：MDD 图片、音频、CSS 等资源索引，保存资源路径、类型、大小、hash、存储位置。

### B 小题：设计导入任务表和失败记录

新增 `dictionary_import_job` 或扩展现有任务表，用于记录每次正式入库的状态。字段至少包含任务 UID、词库 UID、状态、导入限制、已处理数量、成功数量、失败数量、例句数量、短语数量、资源数量、错误信息、失败样例、结果 JSON、开始时间、结束时间。

### 给 Trae 的 Prompt

请设计并实现正式词典内容库表，让 MDX/MDD 解析后的内容可以真正入库并被后续业务查询。表结构要覆盖词条、音标、释义、例句、短语、资源和导入任务。要求有唯一约束避免重复导入，同一词库同一词条可更新，失败样例和导入摘要要能追踪。

### 验收标准

- 数据库 migration 包含正式词典内容表和导入任务表。
- 表结构能表达单词、释义、例句、短语、音标和 MDD 资源。
- 重复导入同一词库同一词条不会产生不可控重复数据。
- 导入任务能记录成功、失败、警告和样例。
- 有数据字典或文档说明关键字段含义。

## 题目 4：Python worker 解析 MDX/MDD 并输出结构化 JSON

难度：高

### A 小题：实现 MDX 正文解析与字段清洗

在 `python/ai_orchestrator` 中新增或完善词典清洗 workflow。读取 MDX 后输出结构化词条 JSON，至少包含 headword、rawHtml、plainText、pronunciations、senses、examples、phrases、labels、qualityScore、warnings。

要求能处理牛津类 HTML 标签，例如 `h`、`phon`、`pos`、`def`、`chn`、`x`、`unbox`、`idm-g` 等，未知标签保留在 rawHtml，不应导致任务整体失败。

### B 小题：解析 MDD 资源与 XLSX 例句表

扩展 Python worker 支持 MDD 资源索引和 XLSX 例句表读取。MDD 不要求首版完整存储二进制文件到数据库，但至少要能输出资源路径、类型、大小、hash。XLSX 例句表要能识别中英文例句列，并与词条按 headword 做弱关联。

### 给 Trae 的 Prompt

请在 Python 侧实现词典清洗 worker。输入为 JSON 请求，包含 sourceCode、mdxPath、mddPath、examplesPath、limit、outputPath；输出为结构化 JSON 文件，包含 entries、resources、summary、failures、warnings。要求支持小批量 limit 验证，MDX/MDD 解析失败时返回可读错误，不要让 Java 只能看到进程崩溃。

### 验收标准

- 可以用本地 MDX 文件解析出至少 10 条词条样例。
- 词条样例包含 headword、HTML、纯文本、至少部分释义或例句。
- MDD 能输出资源索引数量和资源样例。
- XLSX 例句表格式不匹配时给出明确错误和表头信息。
- Python 单元测试覆盖 MDX 样例、HTML 清洗、XLSX 表头识别。

## 题目 5：Java 调用 Python worker 并批量写入正式内容表

难度：高

### A 小题：新增 DictionaryImportWorker 抽象

在后端新增 `DictionaryImportWorker` 接口和 `PythonDictionaryImportWorker` 实现。Java 根据词库 UID 找到对应文件路径，构造 JSON 请求，调用 Python CLI，读取输出 JSON。Python 可执行路径、项目根目录、临时目录、导入 limit 需要可配置。

### B 小题：导入任务状态流转与批量写库

新增 `POST /api/admin/dictionaries/{dictionaryUid}/import-jobs?limit=100`。接口创建导入任务，调用 Python worker，小批量写入正式词典内容表，并更新导入任务状态。写库内容至少覆盖 entry、sense、example、phrase、resource。

### 给 Trae 的 Prompt

请打通 Java 后端到 Python worker 的正式入库链路。管理员点击“导入词库内容”后，后端创建导入任务，调用 Python 解析指定词库的小批量内容，将结构化结果批量写入正式词典内容表，并在任务中记录处理数量、成功数量、失败数量、词条样例、失败样例和警告信息。首版可以同步执行，但接口和状态字段要能迁移到异步任务。

### 验收标准

- 管理员可对某个已安装词库发起小批量导入任务。
- 导入成功后，正式词典内容表出现词条、释义、例句或资源记录。
- 任务表记录 processed/success/failed/exampleCount/phraseCount/resourceCount。
- Python worker 报错时，任务状态变为 failed，并保存可读错误。
- Java 后端测试覆盖成功导入、Python 失败、词库不存在、未授权访问。

## 题目 6：后台导入进度、词条样例和失败样例查看

难度：中等

### A 小题：新增样例与失败记录 API

新增管理员接口：

- `GET /api/admin/dictionaries/{dictionaryUid}/import-jobs`
- `GET /api/admin/dictionaries/{dictionaryUid}/entries/samples?limit=10`
- `GET /api/admin/dictionaries/import-jobs/{importJobUid}/failures`

接口用于查看某个词库最近导入任务、已入库词条样例和失败样例。

### B 小题：前端展示导入闭环

在数据清洗中心的“已安装词库”区域展示最近导入任务状态、导入计数、样例词条、失败样例。每个词库提供“导入 100 条样例”操作，点击后能看到进度结果，而不是只显示按钮无反馈。

### 给 Trae 的 Prompt

请完善管理员数据清洗中心的导入反馈体验。上传词库后，管理员应该能看到词库是否已经登记；点击导入后，应该能看到导入任务状态、成功数量、失败数量、词条样例和失败样例。失败时不要只显示“系统异常”，要展示后端返回的具体原因，例如 sourceCode 缺失、表不存在、Python 依赖缺失、XLSX 表头不匹配等。

### 验收标准

- 前端能展示最近导入任务的 running/success/failed 状态。
- 成功导入后能展示至少 3 条词条样例。
- 失败导入后能展示失败原因和失败样例。
- 上传失败、重复编码、缺少 `sourceCode`、数据库表缺失等错误都有可读提示。
- 不刷新页面也能看到本次操作结果。

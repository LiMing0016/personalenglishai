# 客户端写作教练审题主旨稳定返回 Trae 题目

## 背景

当前写作教练已经以 Copilot 形式放在写作窗口中，但进入写作教练后的第一轮能力还需要稳定：当用户已经选择考试题目后，第一轮应优先完成“审题”和“题目主旨沉淀”，让后续提纲、开头、段落、润色、偏题检查都围绕同一个题意工作。

本轮目标不是重做写作模块，也不是让 Agent 每轮都重新理解题目，而是把题目、材料、体裁、字数要求和已生成的题目主旨作为稳定上下文传入，让第一次生成主旨，后续复用主旨。

核心原则：

- 第一轮有题目时，优先输出题目主旨、中心任务、必答点、偏题风险、推荐结构。
- 一旦上下文中已有 `topic_brief`、`central_task`、`must_answer_points` 或 `topic_analysis_done=true`，后续轮次不得重新生成题意。
- 写作教练可以继续做提纲、开头、下一段、偏题检查、润色，但必须引用同一个题目主旨。
- 所有变更必须可验收：前端能传入题目上下文，后端能识别上下文，Agent 输出结构稳定。

```text

- action
- writing_mode
- task_type
- essay_question
- question_materials
- essay_genre
- min_words
- max_words
- essay_text
- selected_text
- include_draft
- topic_analysis_done
- topic_brief
- central_task
- must_answer_points
- risk_points
- recommended_structure

要求：
1. 保持现有 AI 助手接口兼容，不影响普通聊天和其他 Agent。
2. 字段命名要和后端约定一致，必要时在前端类型层做 camelCase/snake_case 映射。
3. 空字段不要污染请求，但用户已选择的作文题目、体裁和字数必须传入。
```

验收标准：

- `npm run build` 通过。
- 在浏览器 Network 中能看到写作教练请求包含作文题目、体裁、字数范围。

## 题目 2：第一轮审题稳定输出

难度：高

### A. Agent 输入组装中加入写作运行规则（完成）

给 Trae 的 Prompt：

```text
请在 python/ai_orchestrator/adapters/openai_input_items.py 中为写作教练请求注入结构化运行规则。

当 action=analyze，或有 essay_question 且 topic_analysis_done=false 时，必须告诉 Agent：
1. 本轮优先做审题。
2. 输出题目主旨、中心任务、必答点、偏题风险、推荐结构。
3. 不要直接替用户写完整作文。
4. 如果用户已有作文，只能基于题意指出是否偏题和下一步建议。

输出给模型的上下文必须清晰区分：
- 用户本轮输入
- 作文题目
- 题目材料
- 体裁
- 字数范围
- 当前草稿
- 已有题目主旨
```

验收标准：

- 构造 OpenAI input items 时能看到 `[写作教练运行规则]` 或等价结构。
- 有题目且第一次进入时，规则明确要求先审题。
- 没有题目时，写作教练会要求用户先选择或输入题目。
- 新增测试覆盖“第一次审题”输入组装。

### B. Prompt 中固化题目主旨输出格式（完成）

给 Trae 的 Prompt：

```text
请更新 python/ai_orchestrator/prompts/agent_instructions/prompt_design.md 中写作教练相关说明，让 Agent 第一轮稳定返回可被前端识别的审题结构。

第一轮有题目时，输出必须包含：
- 题目主旨
- 中心任务
- 必答点
- 偏题风险
- 推荐结构
- 下一步建议

要求：
1. 输出给用户的内容自然，不要暴露内部字段名。
2. 但文本中要有稳定标题，方便前端或后端识别 topic_analysis_done。
3. 不要每次都重新解释题目。
```

验收标准：

- Prompt 文档明确写出“第一轮审题”和“后续复用”规则。
- Agent 测试或结构检查能验证 Prompt 包含这些关键规则。
- 手工测试输入 IELTS 题目时，第一轮回复不直接写作文，而是审题。

## 题目 3：后续轮次复用题目主旨

难度：高（完成）

### A. 前端识别并持久化本轮题目主旨状态

给 Trae 的 Prompt：

```text
请在写作窗口前端实现题目主旨状态复用逻辑。

要求：
1. 当写作教练回复中包含题目主旨、中心任务、必答点、偏题风险等信息后，前端能把这些信息纳入后续 writing_coach_context。
2. 后续点击“搭提纲 / 写开头 / 写下一段 / 检查偏题 / 润色表达”时，必须传入 topic_analysis_done=true。
3. 如果切换作文题目，必须清空旧的 topic_brief、central_task、must_answer_points、risk_points。
4. 不要依赖页面刷新后的内存状态完成核心功能，至少本会话内要稳定。
```

验收标准：

- 第一轮审题后，第二轮请求包含 `topic_analysis_done=true`。
- 第二轮请求包含已有 `topic_brief` 或 `central_task`。
- 切换题目后不会继续使用旧题目主旨。
- UI 行为不影响原有写作输入、选中文本、按钮操作。

### B. 后端规则禁止重复生成题意

给 Trae 的 Prompt：（完成）

```text
请在后端输入组装或 Agent Prompt 中增加强约束：

如果 writing_context 中已经存在 topic_brief、central_task、must_answer_points，或 topic_analysis_done=true，则 Agent 不能重新生成题意，不能改写题目主旨，只能引用已有主旨继续完成当前 action。

当前 action 可能是：
- outline
- opening
- next
- polish
- topic_check
- draft

要求：
1. 后端规则优先级要高于普通写作建议。
2. 如果用户明确要求“重新审题”，才允许重新分析。
3. 测试要覆盖已有 topic_analysis_done=true 的情况。
```

验收标准：

- 后端生成的模型输入明确包含“不要重新生成题意”的规则。
- action=outline 时不会重新输出完整题目分析。
- action=topic_check 时会基于已有中心任务判断偏题。
- 新增测试覆盖 topic_analysis_done=true。

## 题目 4：写作教练路由与结构化输出

难度：中高（完成）

给 Trae 的 Prompt：

```text
要求：
1. first_draft_coach / writing_coach 类型请求要稳定路由到能处理写作规划、审题和表达建议的 Agent。
2. 不要误路由到普通聊天或词典解释 Agent。
```

验收标准：

### B. 输出结构适配前端展示

给 Trae 的 Prompt：（完成）

```text
请统一写作教练输出结构，保证前端既能展示自然语言，也能拿到后续动作需要的结构化信息。

建议输出结构包含：
- intent
- action
- stage
- title
- display_text
- plan_patch
- safe_apply
- next_actions
- needs_approval

要求：
1. display_text 用于聊天气泡展示，不要把 JSON 原文直接显示给用户。
2. plan_patch 用于保存题目主旨、必答点、偏题风险、推荐结构。
```

- 审题结果能自然分段展示。

## 题目 5：题目、材料、体裁、字数约束贯通

难度：中（完成）

### A. 作文题目选择后自动进入写作教练上下文

给 Trae 的 Prompt：

```text
请打通作文题目选择和写作教练上下文。

当用户从题库选择题目后，写作教练应能拿到：
- essay_question
- question_materials
- essay_genre
- min_words
- max_words
- task_type

要求：
1. 这些字段来自真实题目数据，不要硬编码。
2. 写作教练面板首次打开时即可使用这些字段。
3. 如果没有选择题目，写作教练要提示用户先选择题目或手动输入题目。
```

验收标准：

- 选题后第一轮点击“审题”，请求中包含题目完整信息。
- 未选题时不会生成虚假的题目主旨。
- 切换题目后上下文同步更新。

### B. 体裁和字数影响 Agent 建议

给 Trae 的 Prompt：

```text
请确保 essay_genre、min_words、max_words 会影响写作教练建议。

例如：
- IELTS Task 2 议论文：建议 introduction、body paragraphs、conclusion。
- 应用文：建议称呼、目的、主体信息、结尾。
- 字数较短时：建议更紧凑的结构。

要求：
1. 不同体裁不要给出同一套模板。
2. 字数限制要体现在推荐结构中。
3. 当前没有体裁时可以使用默认学术写作建议，但要说明假设。
```

验收标准：

- 输入不同 `essay_genre`，推荐结构不同。
- `min_words/max_words` 会影响段落数量或建议长度。
- 单元测试或手工验收样例覆盖至少两种体裁。

## 总体验收口径

完成后，产品侧按下面流程验收：

1. 打开写作页面，选择一个真实考试题目。
2. 打开右侧写作教练，点击“审题”。
3. 第一轮必须返回题目主旨、中心任务、必答点、偏题风险、推荐结构。
4. 点击“搭提纲”，第二轮不得重新解释题目，只能基于第一轮主旨生成提纲。
5. 输入一段可能偏题的正文，点击“检查偏题”，系统能基于中心任务判断风险。
6. 切换题目，再点击“审题”，必须重新生成新题目的主旨，不得沿用旧题。

本需求完成后，写作教练才算具备稳定的“题目理解记忆”，后续才能继续做作文评分、自动改写、范文生成和学习资产沉淀。

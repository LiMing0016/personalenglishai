# 数据资产详情页工作台升级题目

## 背景

当前管理员后台数据地图已经支持自动发现数据库表、表详情、字段字典、索引、外键和局部关系图。但详情页仍然采用长页面平铺布局：字段字典、局部关系图、索引、外键等模块同时展示，字段一多就需要向下滚动很久才能看到其他模块，排查效率低。

下一步需要把表详情页升级为“数据资产详情工作台”，吸收 OpenMetadata / DataHub 类数据资产页的轻量信息架构，但不接入外部平台。目标是让管理员能快速理解：

- 这张表是干什么的。
- 字段分别代表什么业务含义。
- 这张表和哪些表有关。
- 哪些字段或元数据还没有补齐。

核心原则：

- 不接 OpenMetadata / DataHub。
- 不把中文说明硬编码在前端。
- 基础 schema 信息继续来自 `information_schema`。
- 中文名、业务说明、敏感级别、逻辑关系继续由 `admin-data-catalog.yml` 增强。
- 优先解决页面信息架构和字段字典可读性问题。

- 返回数据地图按钮。
- 中文表名。
- 物理表名。
- 所属模块。
- 行数。
- 最近更新时间。
- 敏感级别。
- 元数据完整度。

要求：

1. 顶部区域只做摘要，不堆叠过多卡片。
2. 中文表名和物理表名要形成清晰主次。
3. 没有配置中文名时，优先展示物理表名，并标记“未配置业务名称”。
4. 保持现有返回入口和数据加载失败处理。

#### 题目难度

中等

#### 验收标准

- 表详情页顶部不再占用大半屏。
- 能看到中文表名、物理表名、模块、行数、更新时间、敏感级别。
- 未配置元数据的表有明确提示。
- 页面刷新后摘要信息能正常恢复。

### B 小题：引入详情页 Tab 工作区

#### 题目 Prompt（完成）

- 概览

要求：

1. 默认打开“概览”。
2. 字段字典、关系图、索引、外键不要再全部平铺在同一个长页面里。
3. Tab 切换不重新请求不必要的数据。

#### 题目难度

中等偏难

#### 验收标准

- 刷新后能保持当前 Tab，或至少不会回到错误状态。

## 题目 3：扩展字段级元数据配置

难度：困难

### A 小题：扩展 `admin-data-catalog.yml` 字段元数据结构

#### 题目 Prompt（完成）

请扩展 `admin-data-catalog.yml`，支持字段级业务元数据。建议结构：

```yaml
dictionary_entry:
  title: 词条主表
  description: 存储词条头词、标准化头词、词性、清洗文本和排序信息。
  columns:
    entry_uid:
      title: 词条唯一标识
      description: 词条在本地词典库中的稳定业务 ID，用于关联释义、例句、发音和短语。
      relation: 被 dictionary_sense、dictionary_pronunciation、dictionary_phrase 等表引用。
    normalized_headword:
      title: 归一化词头
      description: 用于搜索、去重和用户词汇状态关联。
      sensitive: false
```

字段级元数据至少支持：

- `title`：中文字段名。
- `description`：业务说明。
- `relation`：关联说明。
- `sensitive`：是否敏感。
- `enumValues`：枚举说明，可选。

#### 题目难度

困难

#### 验收标准

- YAML 可以配置字段中文名和业务说明。
- 未配置字段不影响数据地图正常展示。
- 已有表级配置保持兼容。
- 至少为 `dictionary_entry` 补充一批字段级中文说明。

### B 小题：后端读取并返回字段级元数据

#### 题目 Prompt

请扩展后端数据地图配置加载和表详情接口，让字段字典返回字段级元数据。返回字段至少包含：

- `name`
- `type`
- `nullable`
- `defaultValue`
- `comment`
- `businessTitle`
- `businessDescription`
- `relationDescription`
- `sensitive`
- `enumValues`
- `metadataConfigured`

要求：

1. 技术字段继续来自 `information_schema`。
2. 业务字段来自 `admin-data-catalog.yml`。
3. 字段没有配置时，`metadataConfigured=false`。
4. 不破坏现有前端字段展示。

#### 题目难度

困难

#### 验收标准

- 表详情接口能返回字段中文名、业务说明、关联说明和敏感标记。
- 未配置字段仍正常展示基础技术信息。
- 后端测试覆盖配置字段和未配置字段两种情况。
- 原有数据地图列表、ER 图接口不受影响。

## 总体验收标准

完成后，数据资产详情页应满足：

1. 不再依赖长页面平铺展示所有模块。
2. 顶部资产摘要清晰、紧凑。
3. 主体内容按 Tab 分层组织。
4. 字段字典支持中文名、业务说明、关联说明和筛选。
5. 关系图独立展示，并支持上游、下游、真实外键和逻辑关系过滤。
6. 索引、外键和依赖影响集中展示。
7. 治理信息能展示元数据完整度、敏感字段和待补充项。
8. 字段级元数据来自 `admin-data-catalog.yml`，不硬编码在前端。
9. 已配置表和未配置表都能正常展示。
10. 文档和验证清单同步更新。

# 单词学习模式完整系统实现题目

## 背景

当前 `/app/vocabulary` 已经完成单词搜索、本地牛津词典详情、收藏、查询次数和“我的收藏 / 生词本”真实数据。页面中“背词模式”已经有静态入口，包括：

- 智能复习
- 新词学习
- 拼写训练

下一步如果做完整版本，不应只做静态卡片，而要把前端学习流程、后端学习状态、复习算法、AI 个性化推荐和训练结果沉淀打通。本文档按“复杂完整版本”出题，供 Trae 实现或拆分执行。后续如果自己做轻量版，可以从这些题目中裁剪。

## 总体目标

1. 建立用户维度的单词学习状态模型。
2. 支持新词学习、智能复习、拼写训练三种模式。
3. 支持学习 session、单题结果、复习调度和统计。
4. 引入 Vocabulary Learning Agent，判断用户每天的学习情况、生成学习诊断、调整复习重点。
5. 前端形成从模式选择到训练完成的完整闭环。

## 非目标

- 不做多人班级词表。
- 不做付费权益限制。
- 不做移动端 App。
- 不做复杂游戏化系统。
- 不要求一次性实现科学严谨的 SuperMemo 算法，首版可以采用可解释的简化 SRS。

## 题目 3：实现简化 SRS 智能复习算法

题目类型：0-1代码生成

难度：困难

### A 小题：定义复习调度规则

#### 题目 Prompt

请实现可解释的简化 SRS 复习调度服务。根据用户答题结果更新：

- `learning_status`
- `mastery_level`
- `review_stage`
- `next_review_at`
- `last_review_at`
- `correct_count`
- `wrong_count`
- `consecutive_correct_count`
- `last_result`

建议规则：

- 新词首次认识：`review_stage=1`，`next_review_at=1天后`

- 连续答对达到阈值：进入 `mastered`
- 标记掌握：直接 `mastered`，但保留低频复查时间

#### 题目难度

困难

#### 验收标准

- 答对、答错、跳过、标记掌握都有明确状态流转。
- 复习间隔可测试、可解释。
- 不同模式的结果都能复用同一调度服务。

## 题目 6：设计 Vocabulary Learning Agent

题目类型：0-1代码生成

难度：困难

### A 小题：定义 Agent 职责、输入输出 schema 和 Prompt

#### 题目 Prompt

请新增 `Vocabulary Learning Agent` 设计与实现骨架。这个 Agent 不是普通聊天 Agent，而是专门用于判断用户每天的单词学习情况，并输出结构化学习诊断和下一步计划。

Agent 职责：

1. 判断用户今天学习状态：`no_data`、`too_light`、`on_track`、`overloaded`、`needs_review`、`spelling_weak`。
2. 判断今天是否应该继续学习、复习、拼写训练或休息。
3. 从用户学习数据中找出主要问题，例如复习逾期、错词集中、拼写不稳、新词过多。
4. 生成克制、具体、可执行的建议。
5. 生成明天或下一次学习计划。

Agent 输入 schema 至少包含：

- 最近查询词。
- 收藏词。
- 错词。
- 复习逾期词。
- 拼写错误词。
- 掌握度分布。
- 最近 session 结果。
- 今日学习分钟数。
- 今日完成 session 数。
- 今日正确率。
- 近 7 天趋势。
- 用户目标，例如“考研英语 / 四六级 / 日常提升”，可为空。

输出结构：

```json
{
  "dailyStatus": "needs_review",
  "confidence": 0.82,
  "summary": "今天新词学习完成度可以，但逾期复习词偏多，建议先处理复习队列。",
  "riskLevel": "medium",
  "primaryIssue": "overdue_review",
  "recommendations": [
    {
      "type": "review_focus",
      "title": "优先复习 8 个逾期词",
      "reason": "这些词已经超过计划复习时间。",
      "action": "start_smart_review"
    }
  ],
  "tomorrowPlan": {
    "newWords": 8,
    "reviewWords": 12,
    "spellingWords": 5,
    "estimatedMinutes": 25
  },
  "wordInsights": [
    {
      "word": "innovative",
      "issue": "释义能识别，但拼写不稳定",
      "suggestion": "先做一次拼写训练"
    }
  ]
}
```

要求：

1. Agent 可优先用 OpenAI Agents SDK，也可先通过现有 Python ai_orchestrator 的结构化 Agent 方式实现。
2. 输出必须是结构化 JSON。
3. 不输出夸大判断，例如“已达到官方等级”“词汇能力优秀”等绝对化表达。
4. Agent 不能直接修改学习状态，只能返回建议和计划。
5. Agent prompt 需要独立存放，不能散落在业务 service 字符串中。

#### 题目难度

困难

#### 验收标准

- 存在独立 Vocabulary Learning Agent prompt 或 instructions。
- 输入输出 schema 明确。
- Agent 输出包含 dailyStatus、summary、recommendations、tomorrowPlan、wordInsights。
- Agent 不直接写数据库状态。
- Prompt 中明确禁止夸大、官方认证、等级断言。

### B 小题：实现 Agent Runner 和规则兜底

#### 题目 Prompt

请实现 Vocabulary Learning Agent Runner。它负责：

1. 组装用户近 7 天单词学习数据。
2. 调用 Vocabulary Learning Agent。
3. 解析结构化输出。
4. 失败时使用规则兜底诊断。
5. 返回统一 DTO 给后端业务接口。

规则兜底至少覆盖：

- 无数据：提示先完成一次学习。
- 今日学习词数为 0：`no_data` 或 `too_light`。
- 逾期复习词超过阈值：`needs_review`。
- 拼写错误率高于阈值：`spelling_weak`。
- 今日新词过多且正确率下降：`overloaded`。
- 最近 3 天稳定完成计划：`on_track`。

要求：

1. Agent 调用失败不能影响学习主流程。
2. JSON parse 失败必须降级为规则建议。
3. 所有输入必须按当前用户隔离。
4. 记录 Agent run 元数据，便于后续进入 Agent Debug。

#### 题目难度

困难

#### 验收标准

- Agent 成功时返回结构化诊断。
- Agent 失败或输出不合法时返回规则兜底。
- 不泄露其他用户数据。
- 有 mock 测试覆盖 Agent 成功、Agent 失败、parse 失败、无数据、逾期复习、拼写薄弱。

```http
GET /api/vocabulary-learning/daily-diagnosis?date=2026-05-30
```

- `recommendations`
- `wordInsights`
- `tomorrowPlan`

1. 只能读取当前用户数据。
2. 默认 date 为今天。
3. 同一天允许缓存最近一次诊断结果，避免频繁调用 Agent。

#### 题目难度

困难

#### 验收标准

- 登录用户能获取当天学习诊断。

### B 小题：新增刷新诊断和计划确认接口

#### 题目 Prompt

请新增两个接口：

```http
POST /api/vocabulary-learning/daily-diagnosis/refresh

```

`refresh` 用于重新运行 Agent 诊断。

`accept` 用于用户确认 Agent 生成的下一次学习计划。请求示例：


要求：

1. 确认计划不等于立即创建 session，只保存用户接受的计划。
2. 后续模式页推荐应优先参考已确认计划。
3. refresh 要有频率限制或基本防抖，避免无限调用 Agent。

#### 题目难度

中等偏难

#### 验收标准

- 用户可以刷新每日诊断。
- 用户可以确认明日计划。
- 已确认计划能影响模式页推荐理由。
- 频繁刷新不会无限创建 Agent 调用。

## 总体验收标准

完整实现后应满足：

1. 用户可以进入背词模式页，看到三种模式的真实可用数量和推荐理由。
2. 用户可以完成新词学习、智能复习和拼写训练。
3. 每次学习 session、单题结果和复习状态都会入库。
4. 答题结果会影响掌握度和下次复习时间。
5. AI 可以生成个性化建议，失败时有规则兜底。
6. Vocabulary Learning Agent 可以判断用户每天的学习情况，并输出 dailyStatus、风险等级、建议、词级 insight 和明日计划。
7. 用户可以刷新每日诊断，也可以接受明日学习计划。
8. Agent 调用有可观测记录，可关联 runId 或 traceId。
9. 学习统计页展示真实趋势和掌握度分布。
10. 刷新、退出、异常和未登录状态都有明确处理。
11. 所有数据按当前用户隔离。
12. 前后端测试和文档同步补齐。

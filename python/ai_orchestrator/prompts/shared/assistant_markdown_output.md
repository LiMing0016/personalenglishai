# Markdown 输出规范

所有面向用户的学习助手回复都要像英语学习讲义，而不是普通聊天文本。

通用要求：
- 优先使用清晰 Markdown 结构，不要输出大段无标题长文本。
- 英语关键词、搭配、语法结构使用 `**加粗**` 或行内代码标记。
- 原句、识别到的图片文字、用户选中文本优先使用 `>` 引用块。
- 最终可直接复制的译文、润色版本或优化版本可以使用 `text` 代码块。
- 对比、翻译处理、润色修改说明、批改建议优先使用 Markdown 表格。
- 输出需要兼容流式渲染；生成过程中可以逐步发送 `message.delta`，但最终内容必须是合法 Markdown。

对比类问题：
- 触发词包括：对比、区别、差异、compare、difference、vs。
- 回复开头优先给 Markdown 表格，然后再分点解释和给例句。

```md
### 快速对比

| 词 | 核心含义 | 重点 | 常见中文 |
|---|---|---|---|
| important | ... | ... | ... |
| significant | ... | ... | ... |
```

讲解类问题：
- 建议包含：这句话的意思、重点表达、例句、你来练一下。

翻译类问题：
- 建议包含：推荐译文、关键词、更自然的表达。
- 图片翻译必须先说明“我识别到的内容”，再给翻译。

润色类问题：
- 建议包含：修改后、修改说明表格、可复用表达。

批改或评分类问题：
- 建议包含：总体反馈、主要问题表格、优化版本、下一步练习。

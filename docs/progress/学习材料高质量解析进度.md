# 学习材料高质量解析进度

## 当前目标

把沉浸式学习平台从“能上传和粗略解析 PDF”推进到“PDF 原文可稳定预览、目录可导航、内容可定位、Agent 可基于 source chunks 回答并返回引用”。

短期不追求一次性达到 NotebookLM / Acrobat AI 的完整能力，先把主链路做成可验收闭环。

## 功能能力拆分

### 1. PDF 原文持久化

当前状态：✅ 已完成

已实现：

- 后端已有原始文件保存链路。
- 已有 `/api/translation/documents/{id}/file` 文件访问入口。
- 前端已有 PDF 文件加载入口。
- 导入成功后，知识快照保存稳定 `fileUrl`。
- 前端刷新或重新进入工作台时，优先从后端知识快照恢复 PDF URL。
- 后端文件接口已覆盖成功返回、Content-Type、Content-Length、inline 文件名和文件丢失 404。

后续增强：

- 云端对象存储。
- 用户级文件权限和跨设备书库。

### 2. PDF 目录体系

当前状态：✅ 已完成

已实现：

- 读取 PDF bookmarks / outline。
- 保留真实目录层级、页码和来源。
- 知识管线优先使用真实目录，不再被规则标题覆盖。
- PDF 无内置目录时，自动识别目录页并生成 `toc_page` 来源的大纲。
- 目录页识别支持跨行目录项合并、常见出版信息和广告文本过滤。
- 前端继续使用 `outlineItems` 渲染左侧目录导航。

待补齐：

- 复杂多栏目录。
- 印刷页码和 PDF 页码存在偏移时的校准。

### 3. 文档元素标准化

当前状态：◐ 部分完成

已实现：

- 有 element / bbox 基础。
- 前端能展示部分页码和元素上下文。
- 后端知识管线统一生成和清洗 elements。
- 文本层 PDF 与 OCR 结果共用 `TranslationDocumentElementDto`。
- 元素类型归一为 `paragraph / heading / title / list / table / image / formula / caption` 等稳定类型。
- source 统一写入 metadata，文本层为 `pdf_text_layer`，OCR 为 `paddle_ocr`。
- source elements 会按 `pageNumber -> 原始 order` 重新排序。
- 低质量乱码元素会在进入 chunk 前被过滤。
- 前端 PDF 选区会通过统一数据层函数映射到 `documentId / pageNumber / blockId / elementId / bbox`，并进入右侧 Agent 上下文。

待补齐：

- 图片、表格、公式真实区域提取。
- 更精细的版面分类和 bbox 质量校验。

### 4. Agent 基于资料回答

当前状态：◐ 部分完成

已实现：

- 解析后已生成 source chunks。
- 后端新增 source-grounded answer 接口，会基于当前文档、当前选区、页码和 elementId 检索相关 chunks。
- 回答返回 citations，包含 `documentId / chunkId / pageNumber / elementId / bbox / quote`。
- 前端工作台调用真实后端接口，不再只生成本地占位回答。
- 前端展示引用，点击引用可跳回 PDF 对应页、恢复右侧上下文，并用 citation bbox 在画布上标出引用位置。

待补齐：

- embedding / rerank。
- 真正 LLM 讲解 Prompt。
- 多引用体验和低质量 chunk 降级说明。

## 推荐实施顺序

| 顺序 | 阶段 | 目标 | 验收重点 |
| --- | --- | --- | --- |
| 1 | PDF 原文持久化 | 刷新和重新进入后仍能显示 PDF 原貌 | 上传、刷新、重新进入、权限、文件丢失兜底 |
| 2 | PDF 目录体系 | 左侧导航优先显示真实目录 | 内置目录、目录页识别、标题兜底、页码兜底 |
| 3 | 文档元素标准化 | 所有解析结果都变成统一元素 | pageNumber、elementId、bbox、type、source |
| 4 | OCR 质量诊断 | 阻止乱码和低质量内容污染知识库 | 乱码、重复、低置信、空白页、warning |
| 5 | Source Chunk 检索 | Agent 能检索当前文档资料 | chunk 生成、检索、当前选区优先 |
| 6 | Agent 引用回答 | 回答基于资料并返回引用 | 页码、元素、bbox、引用列表 |
| 7 | PDF 选区联动 Agent | 左侧选择内容，右侧基于选区回答 | 选区上下文、讲解、跳转、高亮 |
| 8 | 图片 / 表格 / 公式增强 | 提升复杂学习材料解析质量 | 图片资产、结构化表格、公式 LaTeX |

## 当前需求点：文档元素标准化

### 目标

把 PDF 文本层、OCR 结果、目录结果都统一成稳定的文档元素，保证后续 chunk 检索、引用定位和 Agent 问答都使用同一种 source 结构。

### 验收清单

- [x] 每个元素都有稳定 `pageNumber`、`elementId`、`order`、`type`、`source`。
- [x] 文本层元素和 OCR 元素进入同一套 DTO。
- [x] 标题、正文、图片、表格、公式有明确类型枚举和降级规则。
- [x] 元素顺序能反映真实阅读顺序。
- [x] 低质量元素不会污染目录和 source chunk。
- [x] 前端选区能稳定映射到元素。

## 下一步

1. 继续增强 source chunk 检索质量，引入 embedding / rerank 或更稳定的关键词召回。
2. 接入真正 LLM 讲解 Prompt，让回答不只是规则拼接，而是基于引用资料解释。
3. 优化多引用体验和跨页引用展示。
4. 主链路稳定后再补图片、表格、公式真实区域提取。

## 阻塞和风险

| 风险 | 影响 | 当前处理 |
| --- | --- | --- |
| PDF 文本层质量差 | Agent 可能拿到乱码或错误内容 | 需要增强 OCR 质量诊断和降级策略。 |
| 左侧导航不是目录 | 用户很难按书籍结构学习 | 优先做 PDF 内置目录和目录页识别。 |
| 只做 OCR 不做 source chunk | Agent 无法可靠基于资料回答 | 需要在解析稳定后接入 chunk 检索。 |
| 图片、表格、公式过早投入 | 容易拖慢主链路闭环 | 放到主链路稳定后增强。 |

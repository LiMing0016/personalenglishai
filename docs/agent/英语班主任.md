# Hermes 长期英语学习班主任接入方案

## 1. 目标

将 Hermes 接入 Personal English AI，作为用户的长期英语学习班主任，负责长期跟踪、复盘、规划和提醒。

Hermes 不替代现有学习 Agent，而是补充长期管理能力。

## 2. 角色分工

| 模块 | 职责 |
| --- | --- |
| PEAI 学习 Agent | 写作批改、句子润色、词汇讲解、翻译反馈、练习生成 |
| Hermes 长期班主任 | 学习画像维护、每日任务、每周复盘、反复错误追踪、长期规划 |
| PEAI 后端 | 用户鉴权、学习数据读取、摘要生成、建议保存 |
| PEAI 前端 | 展示学习画像、今日任务、周复盘、历史建议 |

核心原则：

```text
PEAI = 学习产品主系统
Hermes = 长期班主任 Provider
```

## 3. 总体架构

```text
用户学习数据
  ↓
PEAI 后端 LearningSummaryService
  ↓
生成学习摘要
  ↓
Python ai_orchestrator
  ↓
LearningTeacherProvider
  ├─ HermesTeacherProvider
  ├─ OpenAITeacherProvider
  └─ MockTeacherProvider
  ↓
生成班主任建议
  ↓
PEAI 后端保存
  ↓
前端展示
```

## 4. 为什么不让 Hermes 直接读数据库

Hermes 不直接访问数据库，原因：

1. 保持用户数据边界清晰。
2. 防止外部 Agent 直接修改核心数据。
3. 便于后续替换 Provider。
4. 方便调试和验收。
5. PEAI 保留产品控制权。

Hermes 只接收 PEAI 生成的学习摘要。

## 5. 第一版 MVP 功能

第一版只做 5 个能力。

### 5.1 学习画像

记录：

- 目标考试
- 当前水平
- 目标分数
- 薄弱项
- 常见错误
- 最近进步
- 下阶段重点

### 5.2 今日学习任务

根据最近学习数据生成当天任务。

示例：

```text
今天任务：
1. 复习 5 个健康类表达。
2. 写 3 个 cause-effect 句子。
3. 润色 1 个 IELTS Task 2 主体段。
```

### 5.3 每周复盘

总结：

- 本周练习内容
- 高频错误
- 明显进步
- 下周重点
- 建议训练安排

### 5.4 反复错误追踪

识别用户反复出现的问题：

- 论证展开不够
- 原因句重复
- 连接词单一
- 中式表达
- 词汇笼统
- 例子不具体

### 5.5 历史建议保存

每次 Hermes 生成的建议都保存到 PEAI，方便查看历史变化。

## 6. 输入数据结构

PEAI 给 Hermes 的输入不是原始数据库，而是学习摘要。

```json
{
  "userProfile": {
    "userId": 29,
    "targetExam": "IELTS",
    "targetScore": "6.5",
    "currentLevel": "postgrad",
    "mainWeaknesses": ["论证展开", "词汇多样性", "句子连接"]
  },
  "recentActivities": [
    {
      "type": "writing_polish",
      "topic": "online learning",
      "date": "2026-06-07",
      "issues": ["health problem 表达笼统", "原因句重复", "例子不够具体"]
    }
  ],
  "recentErrors": [
    "because/so 使用过多",
    "观点展开太直接",
    "抽象表达缺少具体例子"
  ],
  "recentImprovements": [
    "开始使用 concern, affect, lead to 等表达"
  ],
  "requestType": "daily_plan"
}
```

## 7. 输出数据结构

Hermes 返回结构化结果，PEAI 保存。

```json
{
  "teacherSummary": "你最近的主要问题仍然是论证展开不够具体，但健康类表达比之前更自然。",
  "currentWeaknesses": ["论证展开", "原因结果句", "具体例子"],
  "todayTasks": [
    "写 3 个关于 online learning 的 cause-effect 句子",
    "复习 eye strain, sedentary lifestyle, physical discomfort",
    "润色 1 个 Task 2 主体段"
  ],
  "reviewPoints": [
    "少用 because/so",
    "多使用 lead to / result in / contribute to",
    "每个观点后补一个具体影响"
  ],
  "nextFocus": "健康类和教育类话题的论证展开",
  "confidence": 0.86
}
```

## 10. Provider 策略

通过环境变量控制：

```env
LEARNING_TEACHER_PROVIDER=hermes
HERMES_ENABLED=true
HERMES_COMMAND=hermes
```

可选值：

```text
mock     本地假数据，方便前端和后端开发
openai   使用 OpenAI SDK 生成建议
hermes   使用 Hermes 生成长期班主任建议
```

## 12. MVP 验收标准

第一版验收标准：

1. 能基于用户最近学习数据生成学习摘要。
2. 能调用 Hermes Provider 生成今日任务。
3. Hermes 输出必须是结构化结果。
4. 结果能保存到 PEAI 后端。
5. 前端能展示今日任务和历史建议。
6. Hermes 不可用时，系统可以降级到 MockProvider。
7. 原有写作、词汇、AI 助手功能不受影响。

## 13. 分阶段实施

### 阶段 A：项目内 MVP

目标：先让功能跑通。

内容：

- 新增学习摘要结构
- 新增 MockProvider
- 新增后端保存表
- 新增前端展示页

### 阶段 B：接入 Hermes

目标：验证 Hermes 是否适合作为长期班主任。

内容：

- 新增 HermesTeacherProvider
- 调用 Hermes CLI 或本地服务
- 保存 Hermes 返回结果
- 对比 MockProvider 和 HermesProvider 输出质量

### 阶段 C：长期记忆增强

目标：让 Hermes 真正长期跟踪用户。

内容：

- 每日学习摘要自动生成
- 每周复盘自动生成
- 反复错误趋势追踪
- 学习画像周期更新

## 14. 风险控制

1. Hermes 不直接读写数据库。
2. Hermes 只通过 PEAI 摘要获取信息。
3. 所有结果先保存为建议，不自动修改用户计划。
4. 敏感操作必须由 PEAI 后端校验。
5. 保留 MockProvider，防止 Hermes 不稳定影响产品。

## 15. 最终定位

Hermes 在 PEAI 中的定位：

```text
长期英语学习班主任
```

它负责：

- 看长期趋势
- 发现反复问题
- 安排每日任务
- 做每周复盘
- 维护学习画像

它不负责：

- 直接批改作文
- 直接管理数据库
- 直接修改用户权限
- 替代 PEAI 原有学习 Agent

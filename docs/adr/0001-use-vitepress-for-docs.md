# ADR 0001：使用 VitePress 做文档治理

## 状态

Accepted

## 背景

仓库里同时存在当前文档、旧状态说明、实施计划、任务拆解、mockup、验收报告和资料提取中间产物。缺少统一入口和生命周期规则时，很难判断哪些文档仍然可信。

项目已经使用 Vue 和 Vite，现有文档也主要是 Markdown。让文档跟代码一起走 Git 审查，符合当前项目的维护方式。

## 决策

使用 VitePress 作为项目文档站。VitePress 工程放在 `docs/` 内，当前有效文档整理到主栏目，历史和中间产物移动到 `docs/archive/`。

## 影响

当前文档更容易浏览和搜索，历史材料仍然保留，但不会污染主导航。后续文档变更可以和代码一起审查。

代价是增加了一个小型 Node 文档工具链。维护者需要在新增或移动文档时同步更新导航和文档状态。

## 备选方案

- 继续只保留普通 Markdown：工具成本最低，但不能解决导航和可信度问题。
- 使用 Notion、飞书或语雀：更适合非工程协作，但会让文档和代码审查、Git 历史分离。
- 使用 Docusaurus：能力完整，但对当前 Vue/Vite 项目来说偏重。

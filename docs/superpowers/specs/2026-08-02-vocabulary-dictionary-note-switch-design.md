# 单词词典与沉淀笔记切换设计

## 背景与目标

单词搜索页当前只展示词典结果，用户已经沉淀到数据库中的单词卡只能去“单词沉淀”页面查看。目标是在不离开搜索页的情况下，把同一个词的词典释义与用户笔记组织成两个可切换视图。

本功能不创建新的笔记格式，也不使用新的模板重新生成内容。“我的笔记”必须展示当前用户数据库中该单词卡的当前有效版本，包括当时使用的主题模板、章节结构、用户后续编辑和来源记录。

## 已确认的产品规则

- 默认展示词典释义。
- 只有当前用户存在规范化词形完全匹配的单词卡时，才显示“词典释义 / 我的笔记”切换。
- “我的笔记”在当前搜索页原位置展示，保持只读。
- 用户搜索另一个词后，视图自动恢复到词典释义。
- “打开完整笔记”进入现有单词卡详情页，继续编辑、重新生成、查看修订历史或删除。
- 若用户编辑过卡片，内联视图展示最新保存的当前有效版本；最初版本只在现有修订历史中查看。
- 设计预览中的“核心理解、我的语境、易混辨析”等章节仅用于说明布局，不是新的固定模板。

## 方案选择

### 采用：内联只读笔记与完整详情入口

搜索页负责发现匹配卡片和切换内容；新的只读预览组件负责渲染卡片当前有效内容；完整编辑能力继续由现有 `VocabularyCardInspector` 承担。这样既保留连续查词体验，也不会把编辑、删除、重新生成和冲突处理塞进搜索页。

### 未采用：直接嵌入完整单词卡编辑器

功能完整，但会把复杂工具栏、弹窗、修订和删除操作引入搜索页面，增加状态冲突与视觉负担。

### 未采用：跳转到单词卡详情页

实现成本最低，但不能满足“在同一单词详情位置切换”的体验目标。

## 数据与组件边界

### 精确解析接口

现有列表接口是面向“单词沉淀”页面的模糊检索，并按最近沉淀时间排序。用它的第一页判断同词卡片会有漏匹配风险，因此不改变数据库模型，但在现有单词卡服务上增加一个只读解析接口：

`GET /api/vocabulary/cards/resolve?term=<word>&language=en`

接口按“当前用户 + 语言 + 规范化词形”精确查找未删除卡片，并只返回稳定身份：

- 找到时：`{ found: true, cardUid: "card_..." }`；
- 未找到时：`{ found: false, cardUid: null }`；
- 鉴权、数据库或服务器异常仍使用现有错误响应，不能被误判为“没有笔记”。

接口复用现有词形规范化和卡片身份唯一约束，不创建第二套详情读取模型。前端命中 `cardUid` 后继续复用 `GET /api/vocabulary/cards/{cardUid}` 读取当前有效详情。词典的 `en-gb`、`en-us` 在请求单词卡时统一映射为英语卡片语言 `en`。

### 前端查询边界

新增一个面向搜索页的查询封装，先调用精确解析接口，再按命中的 `cardUid` 调用现有详情接口。输入为当前词典结果词形和词典语言，输出为：

- 精确匹配的卡片详情或 `null`；
- 精确解析与详情读取各自的加载状态；
- 可恢复错误和重试方法。

查询使用 TanStack Query 缓存，查询键包含规范化词形和语言。迟到的旧词响应不能覆盖当前搜索词。组件不增加新的 `localStorage`、`sessionStorage` 或 Pinia 镜像状态。

### 只读笔记组件

新增 `VocabularyCardNotePreview`，只接收 `VocabularyCardDetail` 并负责：

- 显示单词、卡片状态、主题名称和主题版本、最近更新时间；
- 复用 `VocabularyCoreSummary` 渲染 Lexical Core；
- 有 `cardBlocks` 时复用 `VocabularyCardBlocks`；否则复用 `VocabularyMarkdownRenderer` 渲染历史 Markdown；
- 展示卡片现有来源与语境；
- 发出“打开完整笔记”事件。

该组件不编辑、不保存、不重新生成，也不复制一套固定章节。现有 `VocabularyCardInspector` 保持完整详情和编辑职责，第一阶段不对它做大规模重构。

## 页面交互

1. 词典查询成功后，页面并行检查当前用户是否存在精确匹配的沉淀卡片。
2. 未匹配到卡片时，页面保持现状，不显示空的“我的笔记”入口。
3. 匹配到卡片后，在搜索框与详情内容之间显示 `词典释义 / 我的笔记` 分段切换。
4. 切换到“我的笔记”后，用只读笔记替换词典详情，但保留搜索框和顶部四个模块。
5. 点击“打开完整笔记”进入现有 `/app/vocabulary/cards/{cardUid}` 路由。
6. 再次搜索或选择新的词形时，立即回到词典释义，并使用新词作为新的笔记匹配键。

切换控件使用 `tablist`、`tab`、`tabpanel` 语义，支持键盘左右方向键切换和清晰的焦点状态。

## 加载、异常与边界状态

- 笔记检查期间不阻塞词典详情，也不显示抖动的空切换条。
- 精确解析失败时词典照常可用，在详情顶部显示轻量的“我的笔记暂不可用 · 重试”，不覆盖词典错误。
- 已找到卡片但详情读取失败时保留两个切换项；“我的笔记”面板显示重试状态。
- 卡片仍在生成或处于 `needs_review` 时，显示真实卡片状态和现有可读核心；没有可读内容时提示“笔记内容正在生成”并保留“打开完整笔记”。
- 卡片被软删除或不再可见时，重新检查后移除切换，继续展示词典释义。

## 测试与验收

### 自动化测试

- 精确解析接口按当前用户、语言和规范化词形命中，且不会返回软删除卡片或仅包含关键词的其他卡片。
- 有匹配卡片时显示切换，无匹配卡片时不显示。
- 切换后渲染 API 返回的真实 `cardBlocks` 或历史 Markdown，而不是固定模板。
- 用户编辑后的当前有效版本能够显示。
- 搜索新词会重置到词典释义并发起新的匹配。
- 笔记接口失败不影响词典内容，重试可恢复。
- “打开完整笔记”进入正确的持久化卡片路由。
- 运行现有单词搜索与单词卡回归测试以及前端生产构建。

### 浏览器验收

- 在 1150px 桌面宽度验证分段切换、长笔记阅读、滚动和空白层级。
- 验证无笔记、有笔记、生成中、加载失败四种状态。
- 验证键盘切换和移动端单列布局。

## 非目标

- 不在搜索页内编辑、删除、重新生成或查看修订历史。
- 不从词典搜索结果自动创建单词卡。
- 不改变现有词典收藏与查询次数的数据边界。
- 不增加新的模板、卡片字段或数据库表；除精确解析接口外，不改变现有列表与详情接口语义。

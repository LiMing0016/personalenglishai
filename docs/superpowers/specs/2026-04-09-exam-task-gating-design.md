# 考试模式前置 Task 选择设计

## 1. 目标

在考试模式下，用户应先明确当前作文属于 `Task 1` 还是 `Task 2`，系统再据此整理右侧题单。

这次设计只解决页面交互和题单约束来源，不扩展到：

- AI 题目资源落库
- 右侧画布编辑
- 题单持久化时机调整

## 2. 问题定义

当前考试模式题单预览顶部最左侧优先展示的是题型标签，例如 `Picture-based Essay`。这会带来两个问题：

1. 用户无法先声明评分维度对应的考试任务类型。
2. 右侧题单的字数、分值和后续评分标准缺少稳定锚点。

对于考试作文，`picture/material/general` 只能说明题目表现形式，不能替代 `Task 1 / Task 2` 这种评分语义。

## 3. 核心决策

### 3.1 `task_type` 前置

考试模式下，将 `task_type` 提升为右侧题单的首要约束条件。

可选值当前限定为：

- `Task 1`
- `Task 2`

### 3.2 题目形式降级

原本放在右侧顶部最左侧的题型标签，例如：

- `Picture-based Essay`
- `Material-based Essay`
- `Expository`

改为辅助标签，不再承担评分标准含义。

### 3.3 重新整理时机

用户在考试模式下选择或切换 `Task 1 / Task 2` 后，系统立即重新整理右侧题单，不要求用户再次点击整理按钮。

## 4. 页面行为

### 4.1 考试模式初始态

当用户切换到考试模式后：

- 如果尚未选择 `Task 1 / Task 2`，右侧保持空态或提示态。
- 提示文案应明确要求用户先选择考试任务。

### 4.2 选择任务后的行为

当用户选择 `Task 1` 或 `Task 2` 后：

1. 将 `task_type` 作为强约束写入当前整理请求。
2. 基于左侧现有输入、图片、材料、历年真题参考重新整理右侧题单。
3. 右侧顶部标签即时更新。

切换任务时：

- 保留左侧文本输入
- 保留图片或材料附件
- 保留已插入的历年真题参考
- 只覆盖右侧题单结果

### 4.3 顶部标签顺序

右侧题单顶部标签顺序调整为：

1. `Task 1 / Task 2`
2. 题目形式标签，例如 `Picture-based Essay`
3. 字数标签
4. 分值标签

`Task 1 / Task 2` 必须位于最左侧。

## 5. 约束来源

### 5.1 评分相关约束

对考试模式而言，以下约束应优先由 `task_type` 决定：

- 字数范围
- 分值
- 后续评分标准选择

这里不要求用户手动反复指定这些值。

### 5.2 题目形式相关约束

以下信息仍由用户输入和整理结果决定：

- 是否图片题
- 是否材料题
- 题干正文
- 附件说明

因此页面语义应明确区分：

- `task_type` 决定评分标准
- `prompt_type` 决定题目表现形式

## 6. 组件交互建议

### 6.1 新增控件

在考试模式下，为右侧题单区新增一个 `Task 1 / Task 2` segmented control。

交互要求：

- 视觉优先级高于题目形式标签
- 点击后立即切换选中态
- 点击后立即触发题单重整

### 6.2 整理请求

考试模式下的整理请求应显式携带：

- `task_type`
- 左侧用户输入
- 当前附件上下文
- 当前历年真题参考

如果没有 `task_type`，不应生成正式题单。

## 7. 实现边界

这次设计只约束前端页面行为和整理入口，不要求同步完成：

- 数据库存储新字段
- AI 题目资源表落库
- 当前作文 metadata 绑定

这些属于后续实现阶段。

## 8. 验证标准

完成实现后至少需要验证：

1. 进入考试模式时，右侧提示先选择 `Task 1 / Task 2`
2. 选择 `Task 1` 后，右侧即时生成对应题单
3. 切换到 `Task 2` 后，右侧即时刷新，不要求再次点击整理
4. 左侧输入、图片、材料、真题参考在切换 task 时不丢失
5. 顶部标签顺序正确，`Task 1 / Task 2` 位于最左侧
6. `Picture-based Essay` 等标签只作为题目形式展示，不再表达评分标准

# 学习助手页面设计稿

## 1. 目标

在现有站内导航中新增一个独立的 `学习助手` 一级入口，作为写作页之外的通用英语学习聊天空间。

第一版目标是提供一个接近 GPT 使用习惯的聊天体验，让用户可以在站内直接发起纯文本英语学习对话，同时保持现有写作页内 `AI Chat` 能力不受影响。

该页面的核心目标是：

- 让用户在 `写作` 之外拥有独立的学习型对话入口
- 建立“PEAI 也有自己的学习助手工作区”的产品心智
- 为后续接入多 agent 编排预留页面结构，但第一版前端不暴露复杂编排概念

## 2. 范围

### 2.1 第一版纳入范围

- 顶部导航新增 `学习助手` 一级入口
- 新增独立页面路由，例如 `/app/assistant`
- 页面采用 `左侧会话栏 + 右侧聊天主区` 的双栏结构
- 支持新建会话
- 支持展示会话列表
- 支持纯文本消息发送与消息流展示
- 支持聊天空态欢迎区与 4 个 starter 卡片
- 支持最基础的加载态、失败态与重试交互

### 2.2 第一版不纳入范围

- 不改造当前写作页右侧 `AI Chat`
- 不把当前作文、历史作文、题目要求自动带入聊天上下文
- 不支持图片、文件、语音、引用文档
- 不支持前端暴露多 agent 切换条
- 不支持复杂工具栏、模型切换、附件槽位
- 不支持会话收藏、置顶、标签、文件夹
- 不支持多端同步细节优化

## 3. 产品定位

### 3.1 页面定位

`学习助手` 是一个独立的学习工作区，不是写作页侧边工具，也不是当前 dashboard 里的嵌入式卡片。

它服务的场景包括：

- 评价一段英文表达
- 润色句子或短文
- 设计英语写作练习题
- 翻译与单词讲解

### 3.2 与写作页 AI Chat 的关系

现有写作页中的 `AI Chat` 继续保留，用于“边写边问”的局部场景。

新页面 `学习助手` 负责更通用的英语学习对话。

两者边界如下：

- 写作页 `AI Chat`：依附当前作文上下文
- 学习助手页：独立会话空间，第一版只处理纯文本聊天

第一版不尝试统一这两套前端交互和状态源。

## 4. 方案选择

### 4.1 备选方案

本次讨论过的方案包括：

- 方案 1：极简 GPT 复刻
- 方案 2：GPT 骨架 + 学习助手首屏引导
- 方案 3：GPT 骨架 + 顶部 agent 切换条

### 4.2 最终采用方案

采用方案 2：`GPT 骨架 + 学习助手首屏引导`。

原因如下：

- 保留成熟聊天产品的使用心智
- 首屏即可体现英语学习定位，而不是通用问答页
- 不需要在第一版前端暴露多 agent 编排复杂度
- 后续可平滑接入路由 agent 和专职 agent

## 5. 导航与路由设计

### 5.1 导航位置

当前导航为：

- `写作`
- `单词`
- `听力`
- `口语`

建议改为：

- `写作`
- `学习助手`
- `单词`
- `听力`
- `口语`

`学习助手` 放在 `写作` 后面，原因是它与当前产品主线最接近，且可以强化“写作之外还有一个通用学习空间”的认知。

### 5.2 路由建议

建议新增业务路由：

```text
/app/assistant
```

页面作为 `AppLayout` 下的普通业务页，沿用现有登录态、学段校验和顶部导航。

## 6. 页面结构

### 6.1 总体布局

页面采用双栏结构：

- 左侧：会话栏
- 右侧：聊天主区

推荐宽度关系：

- 左侧会话栏约 `260px ~ 300px`
- 右侧主区自适应填满剩余空间

### 6.2 左侧会话栏

左侧从上到下包括：

- `新建对话` 按钮
- 会话搜索框
- 会话分组列表
- 底部轻量功能区

底部区域第一版可以只放：

- 返回主站或辅助说明
- 用户区占位

不要求第一版做复杂设置入口。

### 6.3 右侧聊天主区

右侧主区包括：

- 页面标题区
- 消息流区域
- 底部输入框

空态时在消息区中部展示欢迎语与 starter 卡片；
进入对话后则切换为标准消息流。

## 7. 左侧会话栏设计

### 7.1 新建对话

会话栏顶部放置一个明确的主按钮：

- `+ 新建对话`

点击后新建一条空会话，并将右侧切换到聊天空态或首条消息输入态。

### 7.2 搜索框

搜索框用于筛选本地已有会话。

第一版只要求前端列表筛选能力，不要求复杂搜索高亮或远程检索。

placeholder 建议为：

- `搜索历史对话`

### 7.3 会话分组

建议分为三组：

- `今天`
- `最近 7 天`
- `更早`

这套结构足够接近主流聊天产品，也能避免第一版引入过细分类。

### 7.4 会话项信息

每条会话展示：

- 会话标题
- 最近一条摘要
- 更新时间

第一版标题可由首条用户消息自动截断生成；
若暂无首条消息，可用：

- `新对话`

### 7.5 当前选中态

当前激活会话需要有清晰高亮，但不应过于抢眼。

建议使用：

- 浅绿色或浅灰高亮底
- 左侧轻量强调条或边框

避免出现过重的卡片边框堆叠。

## 8. 聊天主区设计

### 8.1 空态

空态时展示：

- 标题：`学习助手`
- 欢迎语：`今天想练什么？`
- 副标题：`我可以陪你做英语评价、表达润色、题目设计和词句讲解。`
- 4 个 starter 卡片

starter 建议为：

- `评价这段英文表达是否自然`
- `帮我把这句话润色得更高级`
- `给我设计一道英语写作训练题`
- `解释这个单词在语境里的用法`

### 8.2 starter 交互

点击 starter 后，第一版推荐行为是：

- 将内容填入输入框
- 不自动发送

原因：

- 给用户二次确认机会
- 降低误触导致的无效消息发送
- 实现更稳，风险更低

### 8.3 对话态

进入对话后，主区展示标准消息流：

- 用户消息靠右
- 助手消息靠左
- 消息宽度控制在舒适阅读范围
- 支持段落、列表和较长回复

第一版不要求实现复杂富文本渲染，只需保证换行、段落和基础列表可读。

### 8.4 加载态

发送消息后，插入一条助手占位消息，例如：

- `正在思考...`

该占位消息应在返回成功后替换为真实内容，而不是另起一条独立消息。

### 8.5 失败态

当发送失败时：

- 不清空用户输入
- 不弹侵入式全局错误框
- 在当前消息区域内提供轻量失败提示与 `重试`

错误处理目标是：不中断对话阅读，不破坏聊天心流。

## 9. 输入区设计

### 9.1 第一版输入能力

输入区只支持：

- 纯文本输入
- 回车发送
- 多行输入

不支持：

- 附件上传
- 语音输入
- 图片输入
- 上下文引用
- 模型切换

### 9.2 输入区结构

建议使用底部固定的大输入框，包含：

- 输入文本区域
- 发送按钮

第一版不需要暴露复杂操作按钮栏，避免让页面显得像“半成品工具台”。

## 10. 视觉方向

### 10.1 整体风格

整体采用“GPT 结构 + PEAI 品牌色”的方向，而不是完全照搬通用黑色聊天产品。

建议：

- 左侧栏使用浅灰或白灰背景
- 主区保留大面积留白
- 重点按钮与激活态沿用现有绿色体系
- starter 卡片使用轻绿色或米白色块

### 10.2 视觉目标

该页面要传达的是：

- 专注
- 清晰
- 学习产品感

而不是：

- 通用 AI 平台感
- 复杂控制台感

## 11. 前端架构建议

### 11.1 推荐页面拆分

建议新增独立页面组件：

- `web/src/pages/app/AssistantPage.vue`

建议拆分子组件：

- `AssistantSidebar.vue`
- `AssistantConversationList.vue`
- `AssistantChatView.vue`
- `AssistantComposer.vue`
- `AssistantStarterCards.vue`

### 11.2 状态边界

第一版前端状态建议控制在页面级或单一 store 中，避免提前设计复杂多源状态。

建议管理的核心状态包括：

- 当前会话 id
- 会话列表
- 当前会话消息列表
- 输入框内容
- 请求中状态
- 当前错误状态

### 11.3 不与写作页状态耦合

必须避免：

- 复用写作页 `draft` 相关状态作为学习助手输入源
- 直接依赖当前作文文档 id
- 在学习助手页读取写作页右侧面板状态

学习助手页应保持独立的状态边界。

## 12. 实施边界

### 12.1 第一版应优先完成

- 顶部导航新增 `学习助手`
- 新页面双栏布局
- 会话栏基础结构
- 聊天主区空态与对话态
- 纯文本输入与发送
- 基础加载态与错误态

### 12.2 第一版应明确延后

- 历史会话持久化细节优化
- 消息流式输出
- agent 显式切换
- 附件与上下文注入
- 会话重命名、删除、收藏
- 复杂 markdown、代码块、表格渲染

## 13. 测试重点

### 13.1 页面结构

- 顶部导航中可见 `学习助手`
- 点击后进入独立页面
- 不影响现有 `写作` 导航与写作主链路

### 13.2 会话栏

- 可新建会话
- 会话列表可切换
- 搜索可按标题或摘要基础筛选

### 13.3 聊天区

- 空态展示欢迎语和 starter
- starter 可正确填入输入框
- 发送后消息流正常显示
- 加载态与失败态正常工作

### 13.4 回归约束

- 不改动写作页右侧 `AI Chat`
- 不影响现有写作编辑器和面板链路
- 不影响现有 dashboard、个人中心和其他一级模块导航

## 14. 结论

本次设计应以“独立学习助手页”落地，而不是继续扩写写作页侧边聊天。

采用 `学习助手` 一级入口 + `左侧会话栏 + 右侧聊天主区` 的双栏结构，可以同时满足：

- 主流聊天产品的使用心智
- 英语学习产品的明确定位
- 与现有写作主链路解耦
- 为后续多 agent 编排保留前端容器

第一版前端只处理纯文本聊天体验，先把页面形态、导航结构和会话工作区建立起来，再进入后续实现与编排阶段。

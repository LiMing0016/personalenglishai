# 单词卡头部、连续浏览与发音设计

## 当前结论

单词卡详情页头部升级为可交互的学习入口，同时支持单词发音和按单词库当前条件连续浏览。用户点击单词或扬声器即可播放发音；工具栏右侧提供紧凑的上一张、当前位置和下一张控制，不在正文底部重复放置导航。

发音采用分层降级：卡片已有真人词典音频时直接播放；没有音频时由 Java 后端调用 Python Kokoro 服务生成并缓存；服务不可用时使用浏览器 Web Speech API 兜底。Kokoro 只负责语音合成，鉴权、卡片查询、缓存元数据和对外接口继续由 Java 后端负责。

本设计不修改 Markdown 正文格式，也不把音频写入主题内容。音标、词性和音频地址继续属于统一核心 JSON。

## 背景与问题

当前详情页头部只展示单词、音标、词性、状态和主题，信息完整但缺少可操作性。用户阅读完一张卡片后必须返回单词库才能打开下一张，连续学习被打断。

项目已经具备以下基础能力：

- 核心 JSON 的 `phonetics[].audioUrl` 字段可以保存真实发音地址。
- Oxford 词典解析器可以提取 `audioFile`。
- 搜索单词页已经实现“真实音频优先，浏览器语音兜底”的播放逻辑。
- 单词卡列表已有关键词、状态、来源、排序和分页参数。

因此本次应复用现有数据结构和播放习惯，不建立第二套音频字段或详情状态源。

## 目标

- 让单词卡头部具备明确的产品身份和学习操作感。
- 点击单词可立即播放默认发音，点击具体音标可播放对应英音或美音。
- 真人音频优先，缺失时可以免费本地生成，最终仍有设备级兜底。
- 用户按当前单词库筛选、排序和分页顺序连续浏览卡片。
- 返回单词库时恢复进入详情前的筛选和页码。
- 桌面、窄屏和手机均不出现工具栏重叠或横向溢出。
- 不引入新的前端状态库或持久化层。

## 非目标

- 本次不提供句子、Markdown 全文或跟读评分朗读。
- 本次不建立音色市场、语速设置或用户永久口音偏好。
- 本次不把 Free Dictionary API 作为生产环境唯一音源。
- 本次不修改单词卡核心 JSON schema、主题 Prompt 或 Markdown 协议。
- 本次不重构整个单词库列表和详情查询体系。

## 头部信息架构

头部保持与当前详情页相同的白底、绿色强调和紧凑工具栏，不建立新的视觉系统。

### 标题行

标题行从左到右包含：

1. 仅图标的返回按钮，使用现有图标库的向左箭头，tooltip 为“返回单词库”。
2. 可点击的单词标题。点击后播放默认发音，语义上使用按钮而不是给普通标题绑定点击事件。
3. 圆形扬声器按钮，使用现有图标库的 `Volume2` 图标；播放期间显示轻量状态，不改变按钮尺寸。
4. 单词下方先独立显示主音标，不再与词性拼接成一句。
5. 音标下方最多展示两个“词性 + 首条常见释义”摘要；中文释义优先，缺失时使用英文释义，避免头部为了补全中文而引入第二份数据源。
6. 状态、主题和版本使用当前紧凑元数据样式。

长单词允许换行，不缩放字号，不挤压返回和发音按钮。

### 音标交互

核心信息区继续展示所有可用音标。每个音标项都是独立按钮，例如“英 /rɪˈsiːv/”和“美 /rɪˈsiːv/”。

- 点击单词或主扬声器：播放核心 JSON 中第一个有音频的音标；都没有时优先请求 `en-GB`，再使用第一个可用音标的语言。
- 点击具体音标：按该音标的 `region` 播放，不改变卡片内容。
- 播放新的发音前停止当前音频，避免多个声音重叠。
- 再次切换卡片时停止旧卡片音频。
- 播放失败只在头部显示简短可恢复提示，不遮挡正文。

### 操作和连续浏览

粘性工具栏左侧保留阅读/编辑、重新生成、主题和删除等当前操作。右侧增加连续浏览控制：

```text
上一张词名    [左箭头]  3 / 48  [右箭头]    下一张词名
```

宽屏显示相邻词名；中等屏幕只显示箭头和位置；手机端只保留箭头，位置使用可访问名称提供。使用图标按钮并提供 tooltip，不使用字符箭头作为正式图标。

到达第一张或最后一张时禁用对应按钮。切换卡片时保持工具栏尺寸稳定，正文进入现有加载状态，避免整个页面闪回单词库。

## 连续浏览顺序

连续浏览严格继承用户打开详情时的单词库上下文：

- `keyword`
- `status`
- `sourceType`
- `sort`
- `page`
- `pageSize`

从列表打开详情时把这些参数写入详情路由 query。详情页使用同一组 `listVocabularyCards` 查询键读取当前页，并根据当前 `cardUid` 计算位置。

- 当前页中有上一张或下一张时直接切换路由。
- 位于页首且存在上一页时，预取上一页并跳到其最后一项。
- 位于页尾且存在下一页时，预取下一页并跳到其第一项。
- 显示位置按 `前序页数量 + 当前页索引 + 1` 计算，总数使用列表响应的 `total`。
- 返回单词库时把同一组 query 参数还原到列表路由。

直接打开不带列表上下文的详情链接时，不猜测用户之前的筛选条件。页面可以显示卡片内容和返回按钮，但隐藏位置数字与前后按钮；后续如需要“默认最近沉淀顺序”，应单独定义可定位当前卡片的服务端接口。

## 发音来源策略

### 优先级

1. **卡片核心 JSON 音频**：`core.phonetics[].audioUrl` 非空时直接播放，通常来自可信词典数据。
2. **服务端词典音频**：卡片字段为空时，Java 先查询已有本地词典发音记录。
3. **Kokoro 本地合成**：仍无音频时，Java 调用 Python 语音能力生成对应口音音频并缓存。
4. **浏览器兜底**：服务端超时、不可用或用户未登录时，前端使用 `SpeechSynthesisUtterance`。

第三方免费词典可以在授权和稳定性评估完成后增加为服务端词典适配器，但不进入首版关键链路。这样可以避免把商业产品绑定到没有 SLA 或授权边界不清晰的免费服务。

### Kokoro 定位

Kokoro 是 Python 侧的单一语音生成能力，不是新的 agent，也不进入通用 orchestrator。它应实现为结构化 service/tool：

- 输入：标准化单词、语言、口音、声音版本。
- 输出：音频二进制、MIME、时长、声音版本和 traceId。
- 副作用：只生成音频，不直接写业务数据库。
- 超时：由 Java 调用方统一控制。
- 幂等：相同缓存键生成结果等价。

Python 不接收 `cardUid`、用户身份、Markdown 或其他卡片内容。Java 根据已授权卡片提取标准化单词后再调用 Python。

## API 契约

当核心 JSON 没有可播放音频时，Web 调用：

```http
POST /api/vocabulary/cards/{cardUid}/pronunciations
Content-Type: application/json
Authorization: Bearer <access_token>
```

请求：

```json
{
  "language": "en",
  "accent": "en-GB"
}
```

响应：

```json
{
  "code": "0",
  "data": {
    "audioUrl": "/api/vocabulary/pronunciation-audios/pa_...",
    "source": "dictionary",
    "accent": "en-GB",
    "voiceVersion": null,
    "cacheHit": true,
    "traceId": "vocab-pronunciation-..."
  }
}
```

`source` 只能是 `dictionary` 或 `kokoro`。前端不根据供应商名称拼接 URL，也不直接访问 Python 服务。

生成接口只接受当前用户有权查看的 `cardUid`。单词由 Java 从卡片读取，客户端不能用该接口提交任意长文本，避免把它变成开放 TTS 代理。

## 缓存与存储

缓存键使用以下稳定输入的 SHA-256：

```text
normalizedTerm + \0 + language + \0 + accent + \0 + voiceVersion
```

- 相同键的并发请求合并为一次生成，其他请求等待同一结果。
- 音频文件不写入 Git、数据库 blob 或 Web 静态资源目录。
- Java 保存音频元数据，文件存储通过可配置目录适配；生产环境可以替换为对象存储而不改变 Web 契约。
- 对外只暴露不可推断文件路径的音频 UID。
- 首版设置总容量上限并使用最近最少使用清理；删除单张卡片不立即删除公共发音缓存。
- 日志只记录缓存键摘要、accent、source、耗时、大小和 traceId，不记录用户来源语境或 Markdown。

## 前端播放状态

详情组件只维护一次播放会话所需的局部状态：

- `idle`
- `loading`
- `playing`
- `failed`

使用一个可复用的发音 composable 管理 `HTMLAudioElement` 和浏览器语音实例。它负责停止旧播放、组件卸载清理和后端失败降级，不把播放状态写入 Pinia、localStorage 或 TanStack Query。

后端生成结果可以通过 TanStack Query 缓存到当前卡片和口音对应的查询键；音频元素本身不进入查询缓存。

## 状态与错误处理

- 已有词典音频：点击后立即播放。
- 首次 Kokoro 生成：按钮进入 loading，完成后自动播放。
- 生成超时：自动尝试浏览器语音，并提示当前使用设备语音。
- 浏览器禁止自动播放：保留可再次点击的按钮，不循环重试。
- 卡片切换：终止未完成的前端请求或忽略迟到结果，停止当前播放。
- 音频地址失效：清理该次前端缓存并请求后端刷新一次；仍失败后降级。
- 编辑模式：仍允许播放标题发音，但切换卡片前需要沿用现有未保存内容保护规则。

## 性能与可观测性

首版目标：

- 已有远程或缓存音频从点击到开始播放 P50 不超过 500ms。
- 本地 GPU 首次生成 P50 不超过 3 秒，P95 不超过 8 秒。
- Python 调用硬超时 10 秒，超时后不阻塞浏览器兜底。
- 同一单词、口音和声音版本只生成一次。

Java 记录 `traceId`、source、cacheHit、accent、耗时、结果和降级原因。产品事件只记录来源类型、是否缓存命中、耗时和播放结果，不记录单词文本。

## 可访问性

- 单词标题按钮的名称为“播放 receive 的默认发音”。
- 英音和美音按钮分别使用“播放英式发音”和“播放美式发音”。
- 播放状态使用 `aria-pressed` 或状态文本表达，不依赖颜色。
- 上一张和下一张按钮包含目标词名；目标不存在时按钮禁用。
- 键盘焦点在切换卡片后回到新卡片标题，屏幕阅读器播报词名和位置。
- 所有图标来自项目现有图标库并带 tooltip；不使用文本字符模拟扬声器和箭头。

## 分阶段实施

### 阶段一：头部交互与连续浏览

- 完成产品化头部、点击发音和播放状态。
- 使用现有 `audioUrl`，缺失时沿用浏览器语音兜底。
- 完成带列表上下文的跨页上一张/下一张导航。
- 保持返回时筛选、排序和页码。

### 阶段二：Kokoro 免费音频补全

- 增加 Python Kokoro 语音 service/tool 和最小 smoke test。
- 增加 Java 发音生成接口、鉴权、缓存和超时降级。
- Web 在核心 JSON 缺少音频时请求服务端补全。
- 增加缓存命中、生成耗时和降级日志。

分阶段可以先验证头部交互和连续学习是否有效，再引入模型运行时、音频存储和部署配置。

## 测试与验收

### 前端测试

- 点击单词、主扬声器和具体音标时使用正确的音源和口音。
- 新播放开始前停止旧音频，切换卡片和卸载组件时完成清理。
- `audioUrl` 失败时只降级一次，不产生请求循环。
- 同页、跨页、第一页和最后一页导航正确。
- 筛选、排序、页码和返回上下文保持一致。
- 不带上下文的直接详情链接不展示错误位置。
- 编辑模式有未保存内容时不会静默切换卡片。

### Java 测试

- 未授权卡片不能请求发音。
- 已有词典音频时不调用 Python。
- 相同缓存键并发请求只触发一次生成。
- Python 超时、非法音频和存储失败返回稳定错误并保留 traceId。
- 音频 UID 不暴露本地文件路径。

### Python 测试

- 输入 schema 只接受支持的语言、口音和单词长度。
- 输出 MIME、音频内容和声音版本通过契约校验。
- 相同输入生成稳定可播放的音频。
- 模型未安装、GPU 不可用和生成超时返回结构化错误。
- GPU 不可用时是否允许 CPU 降级由配置明确控制，不静默改变部署成本。

### 视觉验收

在 `1440x900`、`1024x768` 和 `390x844` 检查：

- 单词、发音、音标、状态和操作层级清晰。
- 头部和粘性工具栏不遮挡正文。
- 前后导航切换时尺寸不跳动。
- 长单词、长相邻词名和加载状态不产生横向溢出。
- 左侧应用栏和顶部导航保持现有图标、尺寸和布局，不随详情页改版。

## 发布与回滚

阶段一仅涉及 Web，可独立发布和回滚。阶段二新增 Python 模型依赖、Java 接口、缓存目录和部署配置，应通过独立功能开关控制；关闭后继续使用现有真人音频和浏览器语音，不影响单词卡阅读、编辑或导航。

## 外部方案说明

- Kokoro 项目与模型权重需要在落地时再次核对具体版本许可，并固定模型和 voice 版本。
- Free Dictionary API 可以用于开发验证，但生产启用前必须确认音频来源、再分发许可、限流和稳定性。
- Oxford 音频继续遵循当前账号、API 套餐和内容授权，不把它描述为免费音源。

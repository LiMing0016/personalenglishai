# 单词搜索聚焦浮层设计

## 结论

单词搜索页移除搜索框上方的 `Search / 搜索单词 / 查询、学习、一步到位` 标题区，并移除搜索框下方固定展示的热门搜索与最近搜索卡片。搜索页首屏只保留搜索框、查询状态和词典结果。

用户聚焦搜索输入框时，在搜索栏下方打开一个组合浮层：上方展示最近搜索，下方展示热门推荐。最近搜索为空时不展示空状态文案，只展示热门推荐。该方案复用现有会话级最近搜索数据，不新增接口、依赖或持久化状态。

## 方案比较

### 方案 A：组合聚焦浮层（采用）

- 最近搜索和热门推荐统一收进搜索框浮层。
- 页面最简洁，入口与用户当前动作直接关联。
- 无需引入自动补全接口，改动范围可控。

### 方案 B：仅最近搜索进入浮层

- 热门搜索继续固定在页面中。
- 改动最小，但页面仍保留一块与搜索框割裂的快捷卡片，精简效果有限。

### 方案 C：命令面板式全屏搜索

- 可以容纳历史、推荐、释义预览和键盘导航。
- 交互能力最强，但超出当前“先打磨查询入口”的范围，不在本次实现。

## 页面与视觉结构

搜索栏成为搜索页的第一个内容区，维持现有输入框、语言选择和搜索按钮结构。输入框聚焦时，浮层从搜索栏下缘展开：

- 白色背景、细边框、柔和阴影和 12px 圆角，与当前绿色主色一致。
- 最近搜索以紧凑行或标签展示，标题右侧保留 `清空`。
- 热门推荐使用现有词条标签，支持点击回填。
- 浮层宽度跟随搜索栏，不改变语言选择和搜索按钮布局。
- 搜索结果和空状态保持在浮层下方，浮层通过绝对定位覆盖，不推动页面跳动。

## 交互规则

1. 输入框获得焦点时打开浮层。
2. 点击最近搜索或热门推荐仅回填输入框，不自动发起查询，避免意外消耗请求。
3. 点击搜索按钮、按 Enter 提交、按 Escape 或点击搜索区域外部时关闭浮层。
4. 焦点在浮层内部移动时保持打开，保证 `清空` 和词条按钮可操作。
5. 清空最近搜索后保留浮层，只隐藏最近搜索分区。
6. 最近搜索继续使用 `vocabulary.recentSearches` 的 `sessionStorage` 数据，沿用现有去重、排序和最多 8 项规则。
7. 存储不可用时继续使用内存状态，不影响搜索。

## 组件与状态边界

本次继续由 `VocabularyView.vue` 编排搜索页，不新增全局状态：

- 新增一个仅控制浮层开合的组件内布尔状态。
- 使用搜索区域容器处理焦点进入、焦点离开和 Escape。
- 复用 `recentSearches`、`hotSearches`、`clearRecentSearches` 和 `query`。
- 不修改词典 API、查询缓存、最近查询恢复或单词沉淀链路。

如果后续加入远程联想搜索，再将浮层抽为独立组件并接入独立查询状态；当前不提前扩展。

## 可访问性

- 输入框通过 `aria-expanded` 和 `aria-controls` 描述浮层状态。
- 浮层使用具名区域，最近搜索与热门推荐保留清晰分组标题。
- 所有词条和清空操作继续使用原生按钮，可通过键盘聚焦。
- Escape 关闭浮层后焦点仍留在输入框。

## 测试与验收

按测试驱动方式先增加真实页面行为测试，覆盖：

- 页面不再显示旧标题区和固定快捷入口卡片。
- 输入框聚焦后显示搜索建议浮层和热门推荐。
- 完成一次查询后，重新聚焦输入框可看到最近搜索。
- 点击最近搜索或热门推荐可以回填输入框。
- Escape 可以关闭浮层。
- 清空最近搜索不会清除热门推荐。

实现后运行词汇页面目标测试和 `npm run build`，并在 `http://127.0.0.1:4173/app/vocabulary` 人工检查桌面宽度下的浮层定位、焦点行为和页面跳动。

## 文档与合并判断

该改动只调整现有搜索页布局和组件内交互，不改变架构、接口或持久化策略。除本文外无需更新 API 或部署文档。实现属于小范围前端改动，在目标测试、生产构建和浏览器验收通过后可以随当前词汇页面分支合并。

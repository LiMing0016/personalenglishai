# 学生助手首屏与窄屏体验升级设计

## 背景

当前学习助手首屏能提供四类任务入口，但输入框位于页面底部，推荐卡片只描述动作，没有说明完成后的学习收益；同时学生界面暴露了 `MarkText / Milkdown` 渲染术语。已有对话在窄屏下会同时显示固定的右侧学习卡片面板，使主对话区域过窄。

本设计采用已选定的第二套视觉方向：以“学习目标 + 主输入框”为首屏核心，并在窄屏下将学习成果面板改成按需打开的抽屉。

视觉参考：[方案 2](../../../output/design/student-assistant-option-2-2026-07-21/reference.png)

## 目标

1. 学生首次进入时，能在数秒内理解可以完成哪些学习任务，以及每项任务能获得什么结果。
2. 输入内容成为首屏最明确的主操作，而不是附着在窗口底部的次要操作。
3. 在 `1024px` 及以下宽度中，主对话优先获得完整阅读宽度，学习成果按需打开。
4. 保持现有 PEAI 白色、墨绿、浅薄荷色和安静学习工具的设计语言。

## 非目标

- 不修改助手 API、对话持久化或模型提示词。
- 不修复学习卡片保存接口和数据字段错误；该问题属于后续独立任务。
- 不增加新的路由、状态库、图标库或 UI 框架。
- 不重构完整的助手状态机或学习资产模型。

## 首次进入页

### 信息层级

空对话状态使用以下结构：

1. 页面级标题仍为“学习助手”，仅在内容顶部出现一次。
2. 主标题改为“今天想完成什么？”。
3. 说明文字改为“先选一个学习目标，再把内容发给我。”。
4. 四个学习目标以紧凑选择项呈现：
   - 检查句子
   - 润色表达
   - 设计练习
   - 讲解词句
5. 对话输入框位于目标选择项下方，成为首屏主操作。
6. 输入框下方展示三条示例任务，每条包含动作和结果：
   - 检查这句话是否自然 — 给出原因和改法
   - 帮我升级这段表达 — 保留原意，更地道
   - 设计一道写作练习 — 包含题目、思路和反馈

### 交互

- 点击学习目标只设置当前目标并将焦点移入输入框，不自动发送消息。
- 点击示例任务沿用现有 `applyStarter` 行为，只将对应文本放入输入框并等待学生确认发送，不自动创建远端对话。
- 目标选择使用可见选中态，并通过 `aria-pressed` 暴露状态。
- 空状态不显示 `MarkText / Milkdown`。现有渲染主题状态继续保留，但不作为学生主界面控件。
- 非空对话继续使用底部固定输入框，不将对话过程中的输入框移动到内容中间。

## 窄屏对话

### 响应式边界

- `> 1024px`：保留现有可调宽侧栏和学习资产画布能力。
- `<= 1024px`：左侧导航保持紧凑图标栏，主对话占据其余宽度；学习资产画布默认关闭。
- 窄屏下不同时常驻显示主对话和学习资产画布。

### 学习成果入口

- 在窄屏对话顶部增加“学习成果”按钮。
- 数量使用现有对话学习资产数据计算；没有可靠数量时只显示文字，不伪造计数。
- 点击后以覆盖式抽屉打开现有学习资产画布；抽屉提供明确关闭操作。
- 关闭后焦点返回“学习成果”按钮。
- 抽屉打开时锁定背景滚动，但不清除输入草稿和对话滚动位置。

### 对话内容重排

- 对话正文保持单列阅读流，正文最大阅读宽度在窄屏下取消桌面限制。
- Markdown 表格在窄屏下使用明确的横向滚动容器，避免压缩到不可读；不猜测动态表格字段并强制改造成卡片。
- 代码块、引用和长英文句子允许换行或局部横向滚动，不得撑宽页面。
- 底部输入框占据主对话可用宽度，并避开紧凑导航栏。

## 组件边界

### `AssistantPage.vue`

- 判断空对话与响应式状态。
- 控制学习资产抽屉在窄屏下的默认关闭和打开方式。
- 向空状态与顶部工具区域传递已有状态和事件，不新增持久化来源。

### `AssistantChatView.vue`

- 渲染新的空状态信息层级、目标选择项和示例任务。
- 复用现有提示选择事件，不直接操作远端对话状态。

### `AssistantComposer.vue`

- 支持空状态中的居中展示样式和目标选择后的聚焦。
- 保持非空对话的底部输入行为、附件和发送逻辑不变。

### `LearningAssetCanvas.vue`

- 复用现有内容和关闭能力。
- 仅调整窄屏容器表现，不复制学习资产数据或保存逻辑。

## 状态与数据流

- 学习目标是当前空对话的临时界面状态，不写入 `localStorage` 或服务端。
- 目标选择通过现有页面状态向输入组件传递，不新增 Pinia store。
- 学习成果数量从现有学习资产集合派生，不新增计数镜像。
- 打开或关闭窄屏抽屉不改变桌面端画布宽度设置。

## 错误处理

- 学习资产保存失败仍由现有画布展示；本需求不改变错误语义。
- 窄屏抽屉打开失败时保持主对话可用，不遮挡输入框。
- 学习资产数量不可用时隐藏数字，仅保留“学习成果”文字。

## 可访问性

- 学习目标使用按钮语义和 `aria-pressed`。
- “学习成果”按钮提供可读名称、展开状态和所控制抽屉的关联属性。
- 抽屉打开后焦点进入抽屉，关闭后返回触发按钮。
- 继续保持导航、文章、标题和表格的现有语义结构。
- 验证键盘 Tab 顺序、可见焦点、`200%` 缩放与 `768px` 重排。

## 验证

### 自动化

- 新增空状态文案、目标按钮和示例任务的契约测试。
- 新增 `1024px` 响应式边界和学习成果入口的契约测试。
- 保留现有助手侧栏、自适应布局和对话状态测试。
- 运行 `npm run build`。

### 浏览器回归

1. 桌面空状态与选定视觉参考对比。
2. 学习目标选择与输入框聚焦。
3. 示例任务触发现有提示行为。
4. 桌面非空对话与学习资产画布不受影响。
5. `1024px` 和 `768px` 下主对话保持完整宽度。
6. 窄屏学习成果抽屉可打开、关闭并恢复焦点。
7. 窄屏 Markdown 表格、代码块和长英文不撑宽页面。
8. 页面控制台无新增错误或警告。

## 完成标准

- 首屏视觉层级与选定方案 2 保持一致，同时沿用项目现有组件和品牌资产。
- 窄屏不再常驻右侧学习资产面板，主对话和输入框可舒适使用。
- 主要交互可用，自动化测试、生产构建和视觉设计 QA 全部通过。

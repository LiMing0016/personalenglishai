# 全站 AI 用量活动设计规格

## 背景

个人中心“订阅与用量”当前只展示当前额度、简单进度条、兑换码和套餐卡片，无法回答用户“过去一年什么时候使用了 AI、主要消耗在哪些产品能力、近期趋势如何”。现有后端已经拥有 `ai_token_usage_event` 原始事件账本、免费用户日聚合、订阅用户月聚合和订阅额度判断能力，但学习助手与部分词汇异步生成尚未完整写入账本。

本轮将个人中心升级为全站可计量 AI Token 的统一活动中心。设计复用现有事件账本和订阅能力，不接入正式支付，也不把 OCR、音频时长或图片数量等不同计量单位强行换算成 Token。

## 目标

1. 在当前权益、兑换码和套餐卡片之间加入可解释的全站 AI Token 活动视图。
2. 提供独立的用户用量查询接口，避免把历史活动塞入 `/api/subscription/me`。
3. 使用统一产品分类映射汇总写作、学习助手、翻译和词汇等用量。
4. 修正 Token 总量计算口径，优先采用供应商返回的 `total_tokens`。
5. 统一时间边界：数据库事件按 UTC 时刻解释，查询接口显式接收并返回展示时区。
6. 接入当前能够可靠获得 Token 数量但尚未归集的学习助手和词汇生成链路。
7. 保留未来正式计费所需的幂等、预占、重试、冲正和对账演进空间。

## 非目标

- 不接入支付、自动续费、退款或发票。
- 不在本轮实现并发额度预占与最终结算。
- 不在本轮实现 outbox、持久化重试或供应商对账。
- 不修改已经发生的历史明细，不根据现有业务记录反推 Token。
- 不把本地 PDF 解析、OCR、音频时长、图片处理次数混入 AI Token。
- 不将无法取得服务端 Token 明细的托管 ChatKit 写作教练伪装为已计量。

## 核心架构

### 原始账本与聚合

`ai_token_usage_event` 继续作为不可变的原始用量事实来源。每次 AI 调用使用稳定的 `usage_event_id` 幂等写入，保留：

- 用户
- 功能键 `feature_key`
- 供应商和模型
- 输入、缓存输入、输出、推理和总 Token
- trace ID
- 发生时间

`user_ai_token_usage_daily` 和 `user_ai_token_usage_monthly` 继续用于实时额度判断，不作为历史活动图的数据源。历史活动直接按用户和时间范围查询原始事件，避免免费/订阅聚合周期不同导致数据缺口。

### 查询接口边界

新增：

```http
GET /api/users/me/usage
  ?metric=ai_tokens
  &from=2025-07-27
  &to=2026-07-26
  &granularity=day
  &timezone=Asia/Shanghai
```

约束：

- 当前只接受 `metric=ai_tokens` 和 `granularity=day`。
- `from`、`to` 都是展示时区中的自然日，范围包含首尾日期。
- 最大查询跨度为 366 天。
- 默认时区为 `Asia/Shanghai`，接口原样返回实际采用的时区。
- 无事件的日期不由后端补零，前端使用稀疏 bucket 构造日历。
- `/api/subscription/me` 保持轻量，只负责当前套餐、周期和额度。

响应：

```json
{
  "metric": "ai_tokens",
  "unit": "token",
  "timezone": "Asia/Shanghai",
  "from": "2025-07-27",
  "to": "2026-07-26",
  "total": 328640,
  "buckets": [
    {
      "date": "2026-07-26",
      "total": 12680,
      "byProduct": {
        "assistant": 5200,
        "writing": 4600,
        "translation": 1880,
        "vocabulary": 1000,
        "other": 0
      }
    }
  ]
}
```

### 产品分类

不允许前端自行解析 `feature_key`。后端维护集中式分类器，把已知功能键映射为稳定的产品维度：

- `assistant`：学习助手与学习编排。
- `writing`：评分、语法、润色、改写等写作能力。
- `translation`：AI 翻译。
- `vocabulary`：词汇识别、导入分析和词汇卡生成。
- `other`：尚未登记或未来新增的功能键。

分类器使用显式规则和受控前缀，并由单元测试覆盖；API 产品键保持稳定，功能键可继续细分。

### Token 总量口径

记录用量时：

1. 供应商明确返回非负 `total_tokens` 时，以它为最终总量。
2. 缺少总量时，使用 `input_tokens + output_tokens` 回退。
3. `cached_input_tokens` 是输入 Token 的组成信息，不重复加总。
4. `reasoning_tokens` 作为输出明细保留，不在供应商已经给出总量时重复加总。
5. 所有负数和缺失值按零处理。

### 时间口径

- 事件时刻以 UTC 存储/解释。
- 查询根据请求时区把 `[from 00:00, to + 1 天 00:00)` 转成 UTC 边界。
- SQL 按 UTC 时间过滤，服务层根据展示时区计算 bucket 日期。
- 首版仅允许 IANA 时区名称，非法时区返回参数错误。
- 前端默认请求 `Asia/Shanghai`，并使用接口返回时区展示。

## 缺失链路归集

### 学习助手

Java 学习助手通过 Python orchestrator 获取同步响应或流式 `run.completed` 事件，其中已包含输入、缓存输入、输出和总 Token。完成一次 run 后：

- 使用 run ID 生成稳定 `usage_event_id`。
- `feature_key` 记为 `assistant.conversation`。
- 使用当前登录用户记录用量。
- 同步和流式路径共用同一个记录函数，依赖幂等避免重复。
- 调用前继续执行订阅额度检查；记录失败不破坏已生成的用户响应，但保留可排查日志。

### 词汇异步生成

词汇图片识别和导入分析已经携带并记录 usage。本轮补齐仍缺失的异步词汇卡生成：

- Python 响应契约返回 usage。
- Java worker 从词汇卡/任务取得 user ID。
- 使用 job/task ID 作为稳定幂等来源。
- `feature_key` 记为 `vocabulary.card-generation`。

如果某条异步生成链路当前无法可靠返回 usage，本轮保持不计量并记录明确日志，不猜测 Token。

### 已知不计量范围

- 托管 ChatKit 写作教练。
- 本地 PDFBox、Paddle/Tesseract OCR。
- 尚未上线的听力、口语能力。
- 没有调用 LLM 的本地检索和文档处理。

## 前端设计

### 页面顺序

1. 当前权益摘要。
2. 全站 AI Token 活动。
3. 兑换会员码。
4. Basic / Pro / Premium 套餐卡片。

### 每日视图

- 默认选中“每日”。
- 展示最近 365/366 天的 53 列 × 7 行日历热力图。
- 月份标签根据每月首个可见周定位。
- 今日有独立描边。
- 无使用为中性浅灰；非零日期根据非零日用量的分位数划分四档颜色，避免单日极值压扁其它日期。
- 鼠标悬停或键盘聚焦显示日期、总 Token 和产品构成。

### 每周视图

- 把同一份日 bucket 按展示时区周一至周日聚合。
- 展示最近 52 周柱状趋势。
- hover 显示周范围、总量与产品构成。

### 累计视图

- 把日 bucket 按自然月聚合。
- 展示最近 12 个月柱状趋势和总量。
- 不使用第二套后端统计接口，避免口径漂移。

### 用量构成

活动图下方展示紧凑产品构成：

- 写作
- 学习助手
- 翻译
- 词汇
- 其他

仅展示总量大于零的分类，并同时显示 Token 数和占比。没有历史记录时展示可执行空状态，不伪造活动。

### 响应式与可访问性

- 宽屏完整显示一年热力图。
- 窄屏允许活动图内部横向滚动，不压缩到无法辨认。
- 日期格支持键盘聚焦和可读 `aria-label`。
- 颜色不是唯一信息来源，tooltip 同时展示数字。
- 加载时保留卡片高度，失败时保留权益、兑换码和套餐能力，并提供重新加载活动的入口。

## 错误与兼容策略

- 查询参数非法返回统一业务参数错误。
- 用量接口失败不阻断订阅状态和兑换码加载。
- 未识别功能键全部进入 `other`，不丢失总量。
- 历史数据只展示自事件账本开始记录后的事实，不回填虚构数据。
- 新接口和 DTO 仅新增，不破坏已有订阅接口。

## 正式计费前必须补齐

1. **额度预占与结算：** 并发请求在调用模型前原子预占，完成后按真实用量结算或释放。
2. **可靠写入：** 使用 outbox 或等价持久化队列重试失败的用量事件。
3. **冲正与对账：** 通过独立调整事件修正，不直接修改原始流水；定期和供应商用量核对。
4. **ChatKit 计量：** 迁移到可控服务端推理或获得可信服务端账单明细后再纳入全站覆盖。
5. **多单位资源计量：** Token、音频秒数、图片次数等使用独立 metric 和 unit 展示。

## 测试与验收

### 后端

- 产品分类器覆盖所有已知功能键和未知键。
- Token 总量优先级覆盖供应商总量、回退计算、缓存和推理字段。
- 用量查询覆盖鉴权、日期边界、最大跨度、非法时区、无记录和跨日事件。
- mapper 查询覆盖时间范围和用户隔离。
- 学习助手同步/流式完成只写入一次。
- 词汇异步生成有 usage 时写入、无 usage 时安全跳过。

### 前端

- 日 bucket 正确构造 53 × 7 日历与空日期。
- 分位数强度不会被单个极值压扁。
- 周/月聚合总量与日 bucket 守恒。
- 未知分类进入“其他”。
- 加载、空状态、失败重试和移动端横向滚动可用。

### 验收

1. “订阅与用量”页仍能查看当前权益、兑换码和套餐。
2. 用户能在每日、每周、累计之间切换。
3. tooltip 能说明日期、总量和产品构成。
4. 学习助手产生的新用量能进入活动图。
5. 已有写作和词汇用量不因分类升级丢失。
6. 托管 ChatKit 和本地资源处理不被虚假计入。
7. 后端测试、前端测试、生产构建和浏览器回归通过。

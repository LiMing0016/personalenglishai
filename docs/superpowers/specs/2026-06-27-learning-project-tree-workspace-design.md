# 学习项目资源树工作台设计

## 背景

当前学习工作台已经具备 PDF 阅读、目录定位、锚点笔记、右侧 Agent 和学习资产雏形。问题在于左侧仍然像 PDF 阅读器目录，用户只能围绕当前 PDF 操作，难以形成一个可长期维护的学习项目。

本设计将工作台升级为白色调的学习 IDE：PDF、章节笔记、锚点笔记、学习资产、复习队列、题库和提示词都作为一个学习项目里的资源。用户不只是读 PDF，而是在维护一个可沉淀、可复习、可被 Agent 辅助整理的学习项目。

## 目标

1. 左侧从 PDF 目录升级为项目资源树，视觉参考白色版 VSCode / Obsidian 文件树。
2. PDF 仍是一等资源，可以打开、阅读、选区、创建锚点笔记。
3. Markdown 笔记、锚点笔记、学习资产可以作为项目节点打开到中间工作区。
4. 右侧 Agent 根据当前打开资源自动切换上下文，辅助提问、补充笔记和整理资产。
5. 保持白色主色调，避免回到深色 IDE 外壳。

## 非目标

1. 第一版不实现真实文件系统同步。
2. 第一版不实现完整 Obsidian 插件生态。
3. 第一版不实现跨项目知识图谱。
4. 第一版不改变现有 PDF 渲染和目录解析链路。
5. 第一版不新增前端框架或重型编辑器依赖。

## 推荐方案

采用“白色 VSCode 学习 IDE + 项目资源树”。

页面结构：

```text
顶部标题栏
  品牌 / 全局搜索 / 完成学习

左侧活动栏
  项目 / 笔记 / 资产 / 搜索 / Agent

左侧项目资源树
  数据结构学习项目
    资料
      数据结构C++版 第三版_邓俊辉.pdf
    PDF 目录
      第1章 绪论
        §1.1 计算机与算法
        §1.2 复杂度度量
    笔记
      第1章_绪论.md
      起泡排序.md
    锚点笔记
      P25 起泡排序复杂度
      P29 O(n²)复杂度
    学习资产
      O(n²)复杂度
      比较结构
    复习队列
    题库
    错题本
    提示词

中间工作区
  Tab: PDF / 第1章_绪论.md / O(n²)复杂度 / +
  内容: PDF 阅读画布或笔记编辑视图

右侧上下文面板
  Agent / 笔记工作台 / 笔记助手 / 资产整理
```

## 视觉方向

整体使用白色调：

- 页面背景：`#f3f6fa`
- 面板背景：`#ffffff`
- 面板弱背景：`#f8fafc`
- 分割线：`#d8e2ee`
- 正文：`#172033`
- 次级文本：`#68758a`
- 主强调：`#0f9b8e`
- 选中背景：`#e6fbf7`

左侧活动栏可以略深一点，但仍然是浅色，例如 `#edf3f8`，不使用黑色侧边栏。PDF 外侧阅读底色允许保留深灰边框，因为这是 PDF 画布本身的阅读容器，不代表产品主题。

## 左侧资源树设计

左侧固定为三层：

1. 活动栏：只放图标和少量计数，控制当前左侧主面板。
2. 项目头部：当前学习项目名称、页码/笔记数量、收起按钮。
3. 资源树：展示资料、目录、笔记、资产等项目节点。

资源树节点类型：

- `folder`：资料、笔记、锚点笔记、学习资产、复习队列。
- `pdf`：导入的 PDF 文件。
- `outline`：PDF 内置目录节点。
- `note`：独立 Markdown 笔记。
- `anchor-note`：绑定 PDF 页码和选区的锚点笔记。
- `asset`：沉淀后的知识点、短语、结构或概念。
- `review`：复习任务。
- `prompt`：用户保存的提示词。

首版只需要前端模拟这些节点，不要求持久化到后端。

## 中间工作区设计

中间工作区保留 Tab 结构：

- PDF tab：显示当前 PDF 阅读画布。
- Note tab：显示 Markdown 笔记编辑或预览。
- Asset tab：显示知识资产详情。
- Anchor note tab：显示锚点笔记详情，并可跳回 PDF 原文。

第一版可以先只真实打开 PDF tab，其他 tab 先展示前端静态内容或轻量编辑面板。这样能先验证产品结构和空间布局。

## 右侧 Agent 设计

右侧不再只是聊天区，而是上下文辅助面板：

- 打开 PDF 时：显示当前页、当前选区、解释段落、记笔记、整理资产。
- 打开锚点笔记时：显示来源 PDF、页码、选区原文、AI 补充候选。
- 打开独立笔记时：显示笔记结构建议、补充解释、生成复习卡。
- 打开学习资产时：显示相关锚点、关联笔记、复习建议。

关键规则：

1. Agent 默认不直接改写用户笔记。
2. AI 输出先进入候选区，用户确认后追加。
3. 任何锚点笔记都必须能回跳到 PDF 页码和选区上下文。

## 交互流程

### 从 PDF 做锚点笔记

1. 用户在 PDF 中选中文字。
2. PDF 浮层出现 `记笔记` 和 `问 Agent`。
3. 点击 `记笔记`。
4. 右侧切换到笔记工作台。
5. 用户写自己的理解，或让 Agent 生成候选补充。
6. 保存后左侧 `锚点笔记` 文件夹出现新节点。
7. 点击该节点可以回到笔记详情，并跳转到 PDF 原文。

### 从项目树打开资源

1. 用户点击 PDF 节点，中间打开 PDF tab。
2. 用户点击章节笔记，中间打开 Note tab。
3. 用户点击学习资产，中间打开 Asset tab。
4. 右侧 Agent 根据当前 tab 切换上下文。

### 新建学习内容

入口放在左侧项目树顶部或 Tab `+`：

- 导入 PDF
- 新建笔记
- 新建专题
- 新建提示词

第一版只做前端按钮和静态节点，后续再接真实创建流程。

## 响应式规则

桌面宽屏：

- 左活动栏 48px。
- 左资源树 280-360px，可拖拽。
- 中间工作区自适应。
- 右侧 Agent 320-420px，可收起。

窄屏浏览器：

- 左资源树自动变成抽屉。
- 右侧 Agent 默认收起为小标签。
- 中间 PDF 保持最小可读宽度，避免左侧和右侧挤压覆盖。

移动端：

- 底部使用三入口：资源、阅读、Agent。
- PDF 阅读为主屏，资源树和 Agent 使用全屏抽屉。

## 组件边界

后续实现建议拆分：

- `WorkspaceActivityBar`：左侧图标栏。
- `LearningProjectExplorer`：项目资源树。
- `LearningProjectTreeNode`：单个资源节点。
- `WorkspaceTabs`：中间打开资源标签。
- `WorkspaceEditorArea`：PDF / 笔记 / 资产容器。
- `ContextAgentPanel`：右侧上下文 Agent。
- `AnchorNoteWorkbench`：锚点笔记编辑区。

第一版可以先在 `TranslationWorkspacePage.vue` 内收敛实现，稳定后再拆组件。

## 验证标准

1. 页面整体是白色调，不能出现黑色 IDE 外壳。
2. 左侧展示的是学习项目资源树，而不是单一 PDF 目录。
3. PDF 目录仍可在项目树内展开和定位。
4. 资源树包含资料、笔记、锚点笔记、学习资产、复习队列、题库、提示词。
5. 顶部 tab 能表达 PDF 和笔记资源可以并行打开。
6. 右侧 Agent 能展示当前 PDF 或笔记上下文。
7. 浏览器缩小时左侧资源树不能压到中间 PDF 内容上。
8. `npm run build` 通过。

## 分阶段实现

### 第一阶段：前端视觉和结构

- 将左侧面板改为学习项目资源树。
- 保留 PDF 目录为资源树中的 `PDF 目录` 子树。
- 清理不必要的重复标题和阅读器式控件。
- 保持右侧 Agent 现有能力。

### 第二阶段：笔记资源打开

- 点击锚点笔记、独立笔记、资产节点时打开对应 tab。
- 中间增加轻量笔记视图。
- 右侧 Agent 根据 tab 类型切换说明和动作。

### 第三阶段：资产沉淀闭环

- 锚点笔记保存后进入资源树。
- Agent 候选内容确认后进入学习资产。
- 资产可加入复习队列或题库。

## 合并评估

该设计本身是文档变更，可以直接合并到 `main`。对应前端实现会改动核心学习工作台页面，建议继续在当前功能分支完成，通过构建和页面验证后再评估合并。

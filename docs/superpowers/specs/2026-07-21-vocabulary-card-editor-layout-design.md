# 单词卡编辑区扩展设计

## 背景

当前单词卡编辑态沿用阅读态的 `840px` 内容宽度，并且 Markdown 编辑器默认高度只有 `220px`。在桌面详情页中，大量可用空间被留空，长内容需要频繁横向换行和纵向滚动。

## 目标

- 编辑态使用详情页的可用宽度，形成完整的文档工作区。
- Markdown 编辑器在桌面端默认提供约 `520px` 的可视高度，并根据视口高度伸缩。
- 桌面端同步展示 Markdown 源码与严格模式渲染结果，编辑后立即更新预览。
- 移动端通过“源码 / 预览”切换使用同一份未保存草稿。
- 保留用户纵向拖拽调整编辑器高度的能力。
- 阅读态继续使用适合阅读的窄版内容宽度。
- 移动端保持单列布局，不产生横向滚动。

## 方案

1. 将 `.card-inspector__document` 和 `.card-inspector__editor-document` 的宽度规则拆开。
2. 阅读态继续保留 `840px` 最大宽度。
3. 编辑态取消固定最大宽度，使用 `width: 100%`，并保留现有页面内边距。
4. Markdown 文本框桌面端使用 `clamp(420px, calc(100vh - 430px), 720px)` 作为最小高度，最大高度继续允许到合理范围。
5. 小屏幕使用较低的最小高度，避免操作栏和保存按钮被推出首屏。
6. 编辑器右侧复用 `VocabularyMarkdownRenderer`，因此预览与阅读态执行同一套 HTML 转义、链接过滤和原始图片禁用规则。
7. 移动端不并排压缩两栏，而是显示“源码 / 预览”分段控制；切换只改变展示，不复制编辑状态。

## 内容格式

- 单词、音标、词性和释义继续使用统一的核心 JSON，供检索、去重、背词和统计使用。
- 例句、搭配、词根和主题化讲解继续使用 Markdown，供 AI 生成和用户编辑。
- 本次只调整 Markdown 编辑器的布局，不改变核心 JSON、Markdown 修订或保存协议。
- 阅读态负责渲染已保存 Markdown；编辑态左侧维护原始 Markdown，右侧实时渲染当前未保存草稿。

## 非目标

- 不引入富文本编辑器、第三方 Markdown 依赖或新的持久化状态。
- 不修改保存、冲突处理、主题切换和删除流程。
- 不修改单词卡 Markdown 数据结构或后端接口。

## 验收标准

- 约 `1400px` 宽桌面视口下，编辑区明显宽于当前 `840px` 限制。
- 桌面端编辑器默认可展示至少约 `520px` 高的内容区域。
- 桌面端修改源码后，右侧预览立即显示相同的标题、列表和强调格式。
- 阅读态内容宽度和排版不变。
- `390px` 宽移动视口无横向溢出，可在“源码 / 预览”之间切换，编辑内容不会丢失。
- 前端词汇测试与生产构建通过。

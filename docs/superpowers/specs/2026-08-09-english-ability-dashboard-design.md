# 英语能力画像与模块诊断设计规格

## 背景

个人中心已有“能力画像”页签，但当前页面只展示写作评测形成的雷达图，存在三个问题：

1. 页面把单项写作数据包装成了用户整体英语能力，产品含义不准确。
2. 雷达图与分值条信息重复、密度失衡，并且无法自然扩展到词汇、阅读、听力和口语。
3. 写作页面已经有 Dashboard 和真实统计接口，如果个人中心再建立独立统计逻辑，会形成两套口径。

产品当前先做好英语能力评价。第一阶段优先接入写作、词汇和学习助手已经具备的数据；阅读、听力和口语保留统一模块位置，但在没有证据时明确显示“待测”。

## 设计结论

1. 能力画像采用精简版“CEFR 能力驾驶舱”，不再使用雷达图。
2. 综合 CEFR 只有在多个能力模块都具有足够且经过校准的证据时才生成；第一阶段显示“待形成”。
3. 写作、词汇、阅读、听力、口语是固定能力模块。学习助手是诊断与证据来源，不是第六项英语能力。
4. 总览页只回答“当前整体状态、哪些模块已有证据、下一步做什么”三个问题。
5. 点击任一能力模块进入统一详情模板，详情页承载子能力、诊断、证据和历史。
6. 原写作 Dashboard 保留；个人中心写作详情复用同一数据库和接口，只复制展示，不复制数据或统计规则。
7. 前端不得把 Mock、模型即时推断或未校准的内部评分展示为正式 CEFR 结论。

实施状态（2026-08-09）：第一阶段前端底座已完成。个人中心能力总览与统一详情已接入；写作使用现有真实接口，词汇、阅读、听力和口语保持诚实待测状态；原写作 Dashboard 保留。综合 CEFR 与真实词汇等级仍受后端校准和持久化证据约束。

## 目标

- 用户能够快速理解自己的英语能力覆盖情况，而不是阅读一组缺少语境的分数。
- 用户能够进入写作或词汇模块查看可追溯的诊断依据。
- 新增阅读、听力、口语时只增加模块数据与子能力配置，不新增一套页面结构。
- 原写作 Dashboard 和个人中心能力详情并存期间保持同一数据口径。
- 数据不足、接口失败和尚未测评都有明确且诚实的页面状态。

## 非目标

- 第一阶段不宣称提供官方 CEFR 认证或与任何考试成绩等价。
- 第一阶段不建立完整的阅读、听力或口语测评系统。
- 第一阶段不根据单词收藏数推断用户词汇能力。
- 第一阶段不持久化学习助手互动题的掌握度；现有互动活动未持久化结果时不能进入能力计算。
- 不删除或重构原写作 Dashboard。
- 不把写作 Dashboard 的前端 Mock 数据迁移为真实用户数据。

## 能力结论规则

CEFR 在本产品中是能力结构和等级描述的参考框架，不是把内部 0–100 分直接换算成 A1–C2 的公式。Cambridge、EF SET、DET、GSE 和 ELSA 等产品只用于借鉴任务覆盖、信效度、细粒度反馈和模块组合方式，不复制其专有题库、评分算法或商业量表。

模块等级必须由后端的版本化评估规则生成，并至少携带量表版本、证据数量、可信度和更新时间。前端只展示结果与证据状态。

综合 CEFR 的产品级生成门槛固定为：

- 至少四个能力模块达到 `sufficient`。
- 已覆盖的模块中必须同时包含至少一个输入能力（阅读或听力）和至少一个输出能力（写作或口语）。
- 所有参与综合计算的模块使用兼容的量表版本。
- 综合等级由后端校准模型生成，不对模块等级做前端平均。

上述门槛是本产品的可信展示规则，不应描述为 CEFR 官方认证要求。第一阶段不满足门槛，因此综合结果固定为“待形成”。

## 信息架构

个人中心继续使用现有顶部页签。用户进入“能力画像”后看到能力总览；点击模块后在同一页签内进入详情。

建议使用可恢复的查询参数：

```text
/app/me?tab=profile
/app/me?tab=profile&module=writing
/app/me?tab=profile&module=vocabulary
```

浏览器返回应从模块详情回到能力总览。未知 `module` 值回落到总览，不显示空白页。

## 能力总览

### 视觉与密度

总览使用单一白色页面、深海军蓝文字、品牌绿色强调、浅薄荷色状态面和细分隔线。沿用个人中心现有头像区、顶部页签、字体、间距和 Lucide 图标。

页面仅保留四个区域：

1. 标题“英语能力画像”和次级入口“评估说明”。
2. 一条综合状态栏：综合 CEFR、证据覆盖、可信度。
3. 五个能力模块：写作、词汇、阅读、听力、口语。
4. 一条优先诊断行动和一条最近证据。

不在总览展示方法论长文、证据列表、历史图表、优势卡、弱项卡或重复解释。

### 综合状态栏

- `综合 CEFR`：第一阶段显示“待形成”。
- `证据覆盖`：统计至少存在一条可用于能力评估的有效证据的模块。`collecting` 和 `sufficient` 都计入覆盖，但单纯查词、收藏或浏览不计入。按照现有数据，第一阶段生产页面通常从写作 `1 / 5` 开始；词汇完成真实诊断后才增加覆盖。
- `可信度`：显示离散等级或圆点，不显示虚假的小数精度。
- 评估规则说明放入“评估说明”弹层或独立说明页。

### 能力模块

模块顺序固定为：写作、词汇、阅读、听力、口语。

每个模块在总览只展示：

- 模块名称与图标。
- CEFR 等级、等级区间或“待测/待校准”。
- 一条证据状态：有证据、收集中、无证据。
- 可点击的详情入口。

模块不展示段落说明。详情、证据数量和诊断依据在点击后展开。

### 当前行动

系统在已有证据中选择一个最高优先级动作，例如“优先补齐词汇证据”。总览只展示一个主行动按钮，例如“开始词汇诊断”。

如果所有模块都没有证据，主行动改为“开始首次能力评估”。如果推荐接口失败，保留模块入口，不生成伪造建议。

## 统一模块详情

写作、词汇、阅读、听力和口语共用同一详情骨架：

1. 返回英语能力画像。
2. 模块名称、等级或区间、证据状态、趋势状态。
3. 一句当前诊断。
4. 子能力列表。
5. 一个“下一步”训练建议和主操作。
6. “诊断 / 证据 / 历史”三个页签。

### 子能力列表

子能力使用纵向列表，不使用雷达图。每一行最多展示：

- 子能力名称。
- 等级、区间或内部参考分。
- 可信度状态。
- 简短进度或等级范围。

子能力数量由模块配置决定，但首屏最多显示六项。更多维度放入展开区域。

### 诊断页签

默认只展示两个结论：一个稳定优势和一个优先提升点。每条结论必须能够追溯到证据，不展示模型临时生成但未落库的判断。

### 证据页签

展示用于形成当前能力判断的评测或练习记录，包括来源、时间、结果摘要和进入原始记录的入口。证据记录必须区分：

- 评测证据。
- 练习证据。
- 学习助手诊断证据。
- 手动记录。

### 历史页签

展示同一评分口径下的长期变化。评分或量表版本发生变化时必须分段显示，不能把不同口径直接连成一条趋势线。

## 写作能力详情

### 真实数据复用

写作详情优先复用以下已有数据：

- `/api/users/me/profile/ability`：六项写作能力分、样本数、可信度和更新时间。
- `/api/writing/dashboard`：作文数、提交数、平均分、最高分、单篇得分趋势、得分分布、连续写作和建议。
- `/api/writing/stats`：任务完成、结构、词汇、语法、表达等聚合分，以及语法、拼写和词汇错误数量。
- `/api/writing/documents/{docId}/evaluations`：具体作文的评测证据。
- `/api/writing/dashboard/assets`：作文、词数、句数和平均语法错误，可用于证据补充，不进入 CEFR 计算。

写作详情的第一版子能力固定为：

- 任务完成。
- 连贯衔接。
- 语法准确。
- 词汇丰富。
- 篇章结构。
- 表达多样。

### Mock 数据边界

原写作 Dashboard 的以下内容目前来自 `writingDashboardMock.ts`，不能复制为真实结论：

- `B1+ → B2` 和升级进度。
- CEFR 能力成长曲线。
- 语法错误分类次数。
- 高级词占比、重复词比例、平均句长。
- 主题与体裁分布。

在后端提供真实数据前，新详情页不展示这些项目，或仅在明确的开发预览模式中标注“演示数据”。生产页面不得混合真实数据与无标识 Mock。

### CEFR 展示规则

设计稿中的 `B1` 只用于验证布局。生产页面必须遵守以下规则：

- 后端没有返回经过校准的 CEFR 结果时，显示“待校准”或内部参考分。
- 前端不根据 0–100 分自行映射 A1–C2。
- 后端返回等级时必须同时返回量表版本、证据数量、可信度和更新时间。
- 量表版本变化后，旧结果继续可追溯，但不得与新结果无提示混合。

### 与原写作 Dashboard 并存

- 原 `/app/writing/dashboard` 路由和页面保持不变。
- 个人中心写作详情不复制表、缓存或统计任务。
- 两个页面调用相同接口并共享规范化函数或可复用查询 composable。
- 个人中心只选择适合能力诊断的信息，不复制写作目标、主题推荐等完整 Dashboard 内容。
- 后续产品验证完成后，可以删除任一前端入口，不需要迁移数据。

## 词汇能力详情

现有词汇卡、来源、修订、查词状态和产品事件可以证明用户沉淀和使用过哪些词，但不能证明掌握程度。

第一阶段词汇模块显示“证据收集中”或“待测”，详情可展示：

- 已沉淀单词数量。
- 查词、收藏、最近使用等活动证据。
- 已经持久化的词汇卡来源。
- “开始词汇诊断”入口。

词汇子能力预留为：识别理解、主动回忆、语境运用。只有在正确率、题目难度、作答方式和复习间隔等结果持久化后，才能生成能力等级。

## 学习助手边界

学习助手不是能力模块。它承担三类作用：

- 发起诊断或针对性练习。
- 把写作、词汇等结果转换为可执行建议。
- 作为证据来源标记结果由何种活动产生。

现有对话和结构化学习块能够回放内容，但互动题结果尚未形成统一持久化链路。未持久化的回答结果不得进入能力画像。未来接入时，能力页只消费版本化、可追溯的学习事件，不读取对话文本猜测能力。

## 前端模块协议

能力总览和详情使用统一只读模型，避免各模块自行决定页面结构：

```ts
type AbilityModuleKey = 'writing' | 'vocabulary' | 'reading' | 'listening' | 'speaking'

type AbilityEvidenceState =
  | 'unmeasured'
  | 'collecting'
  | 'sufficient'
  | 'stale'
  | 'unavailable'

interface AbilityModuleSummary {
  key: AbilityModuleKey
  title: string
  levelLabel: string
  evidenceState: AbilityEvidenceState
  evidenceCount: number
  confidenceLabel: string
  trendLabel?: string
  updatedAt?: string
  primaryAction?: { label: string; to: string }
}

interface AbilitySubskill {
  key: string
  label: string
  levelLabel: string
  score?: number
  scoreMax?: number
  confidenceLabel: string
}

interface AbilityModuleDetail extends AbilityModuleSummary {
  diagnosis: string
  subskills: AbilitySubskill[]
  findings: Array<{ tone: 'strength' | 'focus'; text: string }>
  evidence: AbilityEvidenceItem[]
  history: AbilityHistoryPoint[]
}
```

前端只渲染后端或规范化适配器给出的状态，不在组件中计算 CEFR。第一阶段可以使用个人中心专用 composable 聚合现有接口；不新增全局 Pinia store，避免与现有写作状态源重叠。

## 数据流与状态

```text
已有写作/词汇/助手数据
  → 现有接口与服务
  → 个人中心能力适配器
  → 统一模块只读模型
  → 能力总览 / 模块详情
```

- 原写作 Dashboard 继续直接使用现有接口。
- 个人中心适配器只做字段规范化、状态映射和展示裁剪，不写回业务数据。
- 同一原始数据必须产生同一评分和趋势结果。
- 以后引入统一能力聚合接口时，只替换适配器实现，组件协议不变。

## 加载、空状态与错误处理

- 总览加载时保持五个模块的固定骨架，避免布局跳动。
- 单个模块接口失败时标记为“暂不可用”，其他模块继续展示。
- 没有证据时显示“待测”，并提供真实测评或练习入口。
- 数据时间超过后端设定的有效期时显示“需要更新”，前端不自行决定有效期。
- 写作详情的一个接口失败时，只隐藏依赖该接口的页签或区域。
- 错误重试必须针对失败查询，不整页刷新。
- 任何异常都不能回退到 Mock 数据。

## 响应式与可访问性

- 桌面端五个模块单行展示；窄屏改为横向滚动，不压缩文字。
- 模块入口、页签和主操作使用语义化按钮或链接。
- 状态不能只靠颜色表达，必须同时提供文本。
- 键盘焦点清晰；进入详情后标题获得可感知的页面上下文。
- 760px 以下详情页改为单列，“下一步”区域位于子能力之后。
- 趋势和范围需要文本替代，不依赖图形传达唯一信息。

## 测试策略

### 单元与契约测试

- 每种证据状态映射到正确文案和可用操作。
- 没有 CEFR 时不会从内部评分推断等级。
- 写作适配器正确映射六项能力、样本数、可信度和时间。
- 一个接口失败时其他模块和页签仍可使用。
- Mock 数据不会进入生产适配器。

### 组件与路由测试

- 总览能够进入五个模块详情。
- 未知模块查询参数回落到总览。
- 浏览器返回能从详情回到总览。
- 详情页签支持鼠标和键盘切换。
- 旧写作 Dashboard 路由保持可用。

### 浏览器验收

- 桌面、1024px、760px 和 390px 下无裁切与横向溢出。
- 总览首屏没有长段落或重复状态解释。
- 写作详情只展示真实接口数据或明确空状态。
- API 部分失败、无数据、数据过期和加载状态均可辨识。
- 前端类型检查、相关测试和生产构建通过。

## 分阶段实施

### 第一阶段：稳定前端底座

- 替换现有雷达能力页为精简 CEFR 能力驾驶舱。
- 建立统一模块协议、总览和详情组件。
- 写作详情接入已有真实数据。
- 词汇显示证据收集状态和真实活动摘要，不生成能力等级。
- 阅读、听力、口语显示待测与未来入口。
- 学习助手仅作为诊断行动和证据来源。
- 原写作 Dashboard 保留。

### 第二阶段：真实词汇能力

- 持久化题目、作答、正确率、难度、提示和复习结果。
- 建立词汇子能力的校准与版本规则。
- 在同一详情模板中启用词汇等级、诊断和历史。

### 第三阶段：扩展英语能力

- 阅读、听力和口语接入相同模块协议。
- 完成跨模块信效度验证后生成综合 CEFR。
- 根据证据质量和版本规则展示长期能力变化。

## 文档影响

实施时需要同步更新：

- 个人中心页面和路由说明。
- 英语能力模块只读协议。
- 写作 Dashboard 与能力详情的数据复用说明。
- 未来测评事件的版本、证据与校准规则。

## 验收标准

1. 能力总览不再使用雷达图，并保持精简信息密度。
2. 页面固定展示五项英语能力，数据不足时不伪造等级。
3. 综合 CEFR 在证据不足时显示“待形成”。
4. 点击写作模块可进入统一详情页并查看子能力、诊断、证据和历史。
5. 写作详情使用现有真实接口；Mock 数据不作为用户能力展示。
6. 原写作 Dashboard 完整保留，两套页面使用同一数据源。
7. 词汇只展示当前能够证明的活动和沉淀，不把收藏数当作掌握度。
8. 学习助手不会作为第六项能力，也不会用未持久化对话猜测等级。
9. 阅读、听力、口语可以通过相同协议接入，不需要新设计页面结构。
10. 加载、空状态、部分失败、过期和未知路由均有安全降级。

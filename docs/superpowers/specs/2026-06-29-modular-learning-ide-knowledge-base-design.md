# 模块化学习 IDE 与知识底座设计

## 背景

当前 PDF 学习工作台已经具备 PDF 阅读、目录定位、选区、Agent、笔记和学习产出雏形。前一版设计把页面向学习 IDE 靠拢，但仍偏向固定功能面板：用户看到的是系统预设好的学习区块，而不是可以按当前资料和学习目标自由组合的工作区。

本设计将工作台进一步收敛为“模块化学习 IDE”。中间保持 PDF/笔记/知识卡等主工作区，周围是可添加、可收起、可联动的学习工具。底层吸收 Obsidian 的知识组织能力，让笔记、知识卡、PDF 选区、错题、单词卡、练习之间形成可追踪的链接网络。

设计目标不是复制 Obsidian 或 IDE，而是组合两者优势：

- IDE 负责工作区、工具窗口、标签页和上下文操作。
- Obsidian 式知识底座负责双向链接、反向链接、块级引用、标签和知识关系。
- AI 负责围绕当前上下文解释、整理、生成和推荐模块。

## 设计目标

1. 让用户通过 `添加学习工具` 自行引入需要的能力，而不是选择固定学习阶段或模式。
2. 第一版覆盖 PDF 讲解、笔记、学习产出、单词卡、知识卡、错题本、题库练习、论文卡片。
3. 让 PDF 选区成为所有学习资产的共同入口：解释、写笔记、加入知识卡、加入错题本、生成练习、加入复习。
4. 支持 `[[知识卡]]` 双向链接，让笔记、错题、单词卡和 PDF 章节可以自动关联到知识卡。
5. 支持反向链接，让用户打开一个知识卡时能看到所有引用来源。
6. 支持块级引用，让每个学习产出都能回到原始 PDF 选区、题目、笔记段落或卡片。
7. 支持标签体系，用 `#数学/函数`、`#易错/符号判断`、`#待复习` 等标签跨模块组织内容。
8. 第一版只做当前知识点的局部关系图，不做复杂全局知识图谱。

## 非目标

1. 不做年龄、学段或考试类型的硬模式切换。
2. 不做真正开放插件市场，第一版仅做内置模块库。
3. 不做完整 Obsidian Markdown 编辑器和本地 vault 文件系统。
4. 不做高级查询语法、Dataview 类能力或插件生态。
5. 不做全局复杂知识图谱，只做当前知识卡的局部关系视图。
6. 不在第一版加入完整掌握度大盘、社交协作、课堂空间或学习社区。
7. 不引入新的前端框架或重型编辑器依赖。

## 产品定位

第一版定位为：

```text
PDF 学习工作台 + 可添加学习工具 + AI 上下文助手 + Obsidian 式知识底座
```

核心用户路径：

```text
打开 PDF
  -> 选中内容
  -> AI 解释
  -> 写笔记或生成学习资产
  -> 关联知识卡、错题、单词卡、练习
  -> 通过反向链接和标签复习
```

用户不是选择“我是小学生 / 高中生 / 研究生”，而是选择“我现在需要哪些学习工具”。同一个工作台可以用于教材、讲义、试卷、论文、英语材料和复习资料。

## 第一版模块范围

### 默认开启模块

默认开启 3 个模块，保证新用户进入后不被复杂功能压住：

| 模块 | 作用 | 默认位置 |
| --- | --- | --- |
| PDF 讲解 | 阅读 PDF、选区、AI 解释、定位原文 | 中间主工作区 |
| 笔记 | 从选区或当前页写学习笔记 | 左侧资源树 / 中间 tab |
| 学习产出 | 展示 AI 生成的结构化笔记、知识点、小测、闪卡候选 | 底部输出面板 |

### 可添加模块

用户通过顶部或左侧 `添加学习工具` 打开模块库后自行添加：

| 模块 | 典型使用场景 | 与知识底座关系 |
| --- | --- | --- |
| 知识卡 | 沉淀概念、公式、方法、定理 | 作为 `[[链接]]` 目标和图谱节点 |
| 单词卡 | 英语材料、生词、短语、例句 | 可链接到 PDF 选区和知识卡 |
| 错题本 | 题目、错因、弱点、订正 | 可引用题目块和关联知识卡 |
| 题库练习 | 从当前知识点或错题生成练习 | 可引用知识卡和错题 |
| 论文卡片 | 论文观点、方法、引用、结论 | 可引用 PDF 选区和相关知识卡 |

### 后续模块

后续可加入但不进入第一版实现范围：

- 公式库
- 闪卡复习独立模块
- 课堂笔记
- 口语/听力练习
- 代码/实验记录
- 全局知识图谱
- 复习计划大盘

## 信息架构

### 顶部菜单与模块入口

顶部使用 IDE 式菜单和模块入口：

```text
文件  编辑  视图  学习  工具  窗口  帮助     + 添加学习工具     搜索 Ctrl+K
```

`添加学习工具` 打开模块库下拉层。模块库按学习目的分组：

```text
模块库

基础工具
  PDF 讲解      AI 逐页讲解 PDF 内容
  笔记          记录与整理学习笔记
  学习产出      管理 AI 生成的输出

语言学习
  单词卡        记忆与复习单词
  知识卡        创建概念知识卡片

应试学习
  错题本        收集错题与薄弱点
  题库练习      刷题练习与模拟训练

高阶学习
  论文卡片      管理论文与文献笔记
```

规则：

1. 模块库只负责启用模块，不直接打断当前阅读。
2. 已启用模块显示为 `已添加` 或置灰。
3. 添加模块后，该模块出现在左侧资源树、底部面板或中间 tab 中。
4. AI 可以在右侧 `模块推荐` 中建议添加模块，但用户必须确认。

### 左侧资源区

左侧包含活动栏和资源树。

活动栏入口：

- 首页
- 学习空间
- 探索
- AI 工具箱
- 知识图谱
- 设置

资源树结构：

```text
学习资源
  教材封面
  高一数学 · 人教A版
  学习进度 66%

课本/PDF
  8.2.2 二次函数的性质
  PDF 目录

我的笔记
  课堂笔记
  章节笔记
  锚点笔记

学习产出
  AI 题型结果
  AI 讲解记录
  AI 生成题目

已添加工具
  知识卡
  单词卡
  错题本
  题库练习
  论文卡片

+ 添加学习工具
```

规则：

1. 左侧展示已启用工具，不展示全部工具。
2. 每个工具节点可以展开显示本项目中的资产。
3. 资源树节点点击后在中间主工作区打开 tab。
4. PDF 目录仍保留章节定位能力。

### 中间主工作区

中间主工作区使用 tab：

```text
课本/PDF | 笔记: 二次函数 | 知识卡 | +
```

可打开资源类型：

- PDF 阅读页
- 精读文本页
- 笔记编辑页
- 知识卡详情
- 单词卡详情
- 错题详情
- 题库练习页
- 论文卡片详情

规则：

1. 中间只显示当前 tab 的主要内容，不把所有模块堆在一屏。
2. PDF 读写动作尽量贴近选区完成。
3. 笔记和卡片编辑不默认被 AI 覆盖。
4. 未保存 tab 需要显示 dirty 状态。

### PDF 选区浮层

用户选中 PDF 文本或区域后，浮层显示可用动作：

```text
解释
写笔记
加入知识卡
加入错题本
生成练习
加入复习
更多
```

规则：

1. 已启用模块对应的动作直接可用。
2. 未启用模块对应的动作显示为 `添加并使用`，例如 `添加错题本`。
3. 点击 `解释` 走右侧 AI 讲解。
4. 点击 `写笔记` 创建锚点笔记，并带上 PDF 选区引用。
5. 点击 `加入知识卡` 可以选择已有知识卡，也可以创建新知识卡。
6. 点击 `加入错题本` 需要用户补充题干或使用当前选区作为题目来源。
7. 点击 `生成练习` 由 AI 基于当前选区和关联知识卡生成题目候选。

### 右侧 AI 上下文助手

右侧面板不是独立聊天框，而是跟随当前上下文变化的辅助区。

默认标签：

```text
讲解 | 笔记建议 | 生成练习 | 模块推荐
```

在 PDF tab 下：

- 展示当前页、当前选区、AI 讲解。
- 推荐相关知识卡和模块。
- 提供生成练习和写笔记入口。

在笔记 tab 下：

- 展示反向链接和关联知识卡。
- 提供改写、压缩、补充解释、生成知识卡入口。

在知识卡 tab 下：

- 展示反向链接列表。
- 展示局部知识图谱。
- 展示关联错题、练习、PDF 选区和标签。

规则：

1. AI 输出默认进入候选区，不自动写入用户笔记或卡片。
2. AI 讲解必须保留来源引用。
3. 模块推荐只给建议，不自动添加模块。

### 底部学习产出

底部是可收起输出面板：

```text
学习产出 | 结构化笔记 | 知识点 | 小测 | 闪卡 | 控制台
```

用途：

- 展示当前 PDF 页或当前选区生成的学习产出。
- 允许用户把产出转存为知识卡、单词卡、错题或练习。
- 显示同步状态和 AI 生成状态。

规则：

1. 底部面板是产出暂存区，不是长期资产库。
2. 用户确认后，产出才进入对应模块。
3. 产出需要保留来源引用。

## Obsidian 式知识底座

### 知识对象

所有学习内容统一抽象为知识对象：

| 类型 | 示例 | 是否可被链接 | 是否可被引用 |
| --- | --- | --- | --- |
| PDF 文档 | 高一数学教材.pdf | 是 | 是 |
| PDF 块 | Page 128 选区 | 是 | 是 |
| 笔记 | 二次函数课堂笔记 | 是 | 是 |
| 笔记块 | 笔记中的某段总结 | 是 | 是 |
| 知识卡 | 二次函数 | 是 | 是 |
| 单词卡 | sustainable | 是 | 是 |
| 错题 | 二次函数开口方向判断 | 是 | 是 |
| 练习题 | 生成练习 001 | 是 | 是 |
| 论文卡片 | Transformer 方法卡 | 是 | 是 |
| 标签 | #数学/函数 | 是 | 否 |

### 双向链接

用户在笔记、知识卡、错题解析、单词卡正文里输入：

```md
[[二次函数]]
```

系统行为：

1. 输入 `[[` 时弹出知识对象搜索。
2. 搜索结果优先展示知识卡，其次展示笔记、错题、PDF 章节。
3. 选择已有对象后插入链接。
4. 如果没有结果，提示创建新知识卡。
5. 保存内容时生成一条 link edge。

链接边包含：

```text
sourceObjectId
sourceBlockId
targetObjectId
linkText
createdBy: user | ai
createdAt
```

### 反向链接

打开任意知识卡时，显示反向链接区：

```text
引用了“二次函数”的内容

PDF 选区
  Page 128 · 8.2.2 二次函数的性质

笔记
  二次函数性质总结
  课堂笔记 06-29

错题
  忽略二次项系数符号

练习
  二次函数开口方向基础题

单词卡 / 其他
  无
```

规则：

1. 反向链接按来源类型分组。
2. 每条反链都能点击跳回来源位置。
3. PDF 选区需要跳回页码并高亮原选区。
4. 反向链接既包含用户手动链接，也包含 AI 建议后用户确认的链接。

### 块级引用

块级引用用于把学习产出绑定到最小证据单位。

支持引用：

- PDF 某页某个文本选区。
- PDF 某个区域选区。
- 笔记中的某个段落。
- 某一道错题。
- 某张知识卡。
- 某张单词卡。
- 某道练习题。

引用对象结构建议：

```ts
type KnowledgeObjectType =
  | 'pdf_document'
  | 'pdf_block'
  | 'note'
  | 'note_block'
  | 'knowledge_card'
  | 'vocabulary_card'
  | 'mistake'
  | 'exercise'
  | 'paper_card'
  | 'tag'

interface SourceReference {
  id: string
  objectType: KnowledgeObjectType
  objectId: string
  blockId?: string
  documentId?: string
  pageNumber?: number
  bbox?: string | null
  selectedText?: string
  excerpt?: string
  title: string
}
```

规则：

1. 从 PDF 选区创建的任何资产都必须自动带 `SourceReference`。
2. 从 AI 生成的内容需要继承当前上下文引用。
3. 用户点击引用时，必须能回到原始位置。
4. 引用不可替代正文，只作为证据和回跳能力。

### 标签体系

标签是跨模块组织方式，支持层级写法：

```text
#数学/函数
#易错/符号判断
#待复习
#考试重点
```

规则：

1. 标签可添加到笔记、知识卡、错题、单词卡、练习和论文卡片。
2. 标签支持输入补全。
3. 标签点击后打开该标签下的所有相关对象。
4. AI 可以推荐标签，但需要用户确认后写入。
5. 第一版不做复杂标签权限、颜色规则和高级筛选语法。

### 局部知识图谱

第一版只做当前知识点局部图谱。

打开知识卡 `二次函数` 时，图谱中心是该知识卡，周围显示：

- 相关 PDF 选区
- 相关笔记
- 相关错题
- 相关练习
- 相关标签
- 直接链接的知识卡

规则：

1. 默认最多显示 20 个节点，避免图谱过密。
2. 节点按类型使用不同颜色或图标。
3. 点击节点打开对应资源。
4. 第一版不支持复杂布局编辑。
5. 图谱为空时显示“还没有关联内容，从 PDF 选区或笔记链接开始”。

## 模块联动规则

### PDF 讲解到知识卡

1. 用户选中 PDF 文本。
2. 点击 `加入知识卡`。
3. 系统搜索或创建知识卡。
4. 知识卡正文加入该选区引用。
5. PDF 选区和知识卡形成链接边。

### PDF 讲解到笔记

1. 用户选中 PDF 文本。
2. 点击 `写笔记`。
3. 创建锚点笔记草稿。
4. 笔记自动带 PDF 选区引用。
5. 用户可在笔记中输入 `[[二次函数]]` 链接知识卡。

### PDF 讲解到错题本

1. 用户选中题目或知识点。
2. 点击 `加入错题本`。
3. 如果选区不像题目，系统要求用户补充题干。
4. 错题保存后带 PDF 引用和关联知识卡。
5. 错题可生成同类练习。

### 知识卡到题库练习

1. 用户打开知识卡。
2. 点击 `生成练习`。
3. AI 根据知识卡内容、反向链接和错题生成题目候选。
4. 用户确认后练习进入题库练习模块。
5. 练习题保留关联知识卡和来源引用。

### 单词卡与 PDF

1. 用户在英语 PDF 中选中单词或短语。
2. 点击 `加入单词卡`。
3. 单词卡保存原句、释义、例句和 PDF 引用。
4. 单词卡可以链接到知识卡或标签，例如 `#英语/阅读`。

### 论文卡片与 PDF

1. 用户选中论文中的方法、结论或引用段落。
2. 点击 `加入论文卡片`。
3. 论文卡片保留 PDF 选区、摘要、方法、结论和标签。
4. 后续可与知识卡或研究笔记建立链接。

## 状态与数据模型方向

### 前端状态

页面级核心状态：

```ts
interface ModularLearningWorkspaceState {
  enabledModuleIds: string[]
  openedTabs: WorkspaceTab[]
  activeTabId: string
  activeSidePanel: string
  activeBottomPanel: string
  activeSelection: SourceReference | null
  activeKnowledgeObjectId: string | null
}
```

模块注册信息：

```ts
interface LearningModuleDefinition {
  id: string
  name: string
  group: 'basic' | 'language' | 'exam' | 'advanced'
  description: string
  defaultDock: 'left' | 'right' | 'bottom' | 'center'
  selectionActions: SelectionActionDefinition[]
}
```

选区动作：

```ts
interface SelectionActionDefinition {
  id: string
  label: string
  requiredModuleId?: string
  targetObjectType?: KnowledgeObjectType
}
```

### 后端模型方向

建议后续统一抽象为三类表或实体：

1. `learning_object`：所有知识对象的基础信息。
2. `learning_object_link`：对象间链接和反向链接。
3. `learning_object_reference`：对象引用的来源证据。

概念字段：

```text
learning_object
- id
- user_id
- project_id
- type
- title
- content_markdown
- structured_payload
- tags
- created_at
- updated_at

learning_object_link
- id
- user_id
- project_id
- source_object_id
- source_block_id
- target_object_id
- link_text
- created_by
- created_at

learning_object_reference
- id
- user_id
- project_id
- object_id
- source_type
- source_object_id
- source_block_id
- document_id
- page_number
- bbox
- selected_text
- excerpt
- created_at
```

第一版可以先以前端状态和现有学习笔记接口验证交互，但数据结构需要按这个方向设计，避免后续返工。

## 权限与边界

1. 所有对象默认属于当前登录用户。
2. 第一版按单用户学习项目设计，不做协作权限。
3. AI 推荐的链接、标签和模块必须区分为建议状态，用户确认后才写入。
4. 删除知识对象时，不立即硬删引用；相关反向链接显示为“来源已删除”或在清理任务中处理。
5. PDF 文件无法访问时，引用仍保留 excerpt，便于用户理解来源。

## 空状态与错误处理

1. 模块库为空或加载失败时，保留默认模块并提示稍后重试。
2. 反向链接为空时，引导用户从 PDF 选区或 `[[链接]]` 开始关联。
3. 图谱为空时显示当前知识卡和可操作建议。
4. AI 生成失败时，不清空用户已写内容和已选引用。
5. PDF 引用跳转失败时，显示引用摘录和原页码。
6. 创建知识卡重名时，提示选择已有卡或创建同名新卡。

## 视觉与交互原则

1. 整体使用白色学习 IDE 风格，不使用深色 IDE 外壳。
2. 主色使用 teal/green，强调选区、当前模块和保存状态。
3. 卡片圆角不超过 8px，保持工具型产品气质。
4. 顶部 `添加学习工具` 是主要扩展入口，要明显但不喧宾夺主。
5. 模块库下拉层参考 IDE 菜单：密度高、分组清楚、描述简短。
6. PDF 选区浮层最多展示 6 个主要动作，更多动作放入 overflow。
7. 右侧 AI 面板以当前上下文为中心，不做无上下文闲聊入口。
8. 底部学习产出区可收起，避免抢占 PDF 阅读空间。

## 验收标准

设计完成后的第一版实现至少满足：

1. 用户能通过 `添加学习工具` 打开模块库。
2. 用户能启用知识卡、单词卡、错题本、题库练习、论文卡片中的至少一种模块。
3. 已启用模块能出现在左侧资源区或对应工作区入口。
4. PDF 选区浮层能根据已启用模块展示相关动作。
5. 从 PDF 选区创建笔记时，笔记保留页码、选区文本和引用信息。
6. 笔记或知识卡正文中能识别 `[[二次函数]]` 形式的知识卡链接。
7. 打开知识卡时能看到引用它的来源列表。
8. 学习对象能添加 `#数学/函数` 这类标签。
9. 打开知识卡时能展示当前知识点的局部关系视图或空状态。
10. AI 推荐模块、标签、链接时，需要用户确认后写入。
11. 浏览器缩小时，左侧、主工作区、右侧、底部面板不互相覆盖。
12. 前端构建通过。

## 分阶段实现建议

### 第一阶段：模块化工作台外壳

- 顶部加入 `添加学习工具` 和模块库下拉层。
- 左侧资源区显示默认模块和已启用模块。
- 中间保留 PDF tab、笔记 tab、知识卡 tab 的结构表达。
- 右侧 AI 面板增加 `模块推荐` 标签。
- 选区浮层支持“未启用模块时添加并使用”的状态。

### 第二阶段：知识对象与引用

- 建立统一 `SourceReference`。
- 从 PDF 选区创建笔记、知识卡、错题时写入引用。
- 资源详情页显示来源引用并支持回跳 PDF。
- 学习产出区转存资产时继承引用。

### 第三阶段：双向链接和标签

- 在笔记和知识卡正文中识别 `[[知识卡]]`。
- 支持知识卡搜索、选择和创建。
- 保存链接边，打开知识卡时展示反向链接。
- 支持标签输入、补全和标签聚合列表。

### 第四阶段：局部知识图谱

- 基于当前知识卡的链接、反向链接、引用和标签生成局部图谱。
- 支持点击图谱节点打开资源。
- 控制节点数量和空状态。

### 第五阶段：真实持久化和跨项目扩展

- 后端落地 `learning_object`、`learning_object_link`、`learning_object_reference`。
- 支持跨 PDF、跨学习项目的知识对象聚合。
- 增加更完整的复习、题库和论文场景。

# 单词沉淀导入对话框设计

## 当前结论

单词沉淀页采用“紧凑入口栏 + 居中任务对话框”的导入方式。页面常态只显示“导入单词”主操作、当前候选数量和图片快捷上传入口，不再长期占用大块空间展示空输入框、主题选择和候选区。

点击“导入单词”后打开宽对话框。文本录入、图片上传、主题选择、候选词确认、来源语境和生成卡片继续位于同一个任务流中。该调整只改变前端信息层级和容器，不修改图片识别、主题、候选词、卡片生成或服务端接口。

## 背景与目标

现有导入工作区在没有候选词时仍占用约半个首屏，压缩了已沉淀单词列表。文本录入和图片识别又以标签形式长期展示，使页面视觉重心停留在“输入”，而不是用户更常浏览的单词资产。

本次设计目标：

- 空闲时让单词列表成为页面主体。
- 把一次导入收敛为边界明确的任务。
- 保留文本、图片、主题、候选确认和来源语境的完整流程。
- 不让图片识别直接绕过候选确认。
- 不新增路由、服务端状态或第二份候选词状态。

## 页面常态

卡片列表上方显示一条紧凑导入栏：

- 左侧主按钮为“导入单词”，点击打开对话框，使用 Lucide `Plus` 图标配合文字。
- 主按钮旁显示候选摘要；没有草稿时不显示 `0 个候选词`，存在未提交候选时显示 `N 个待确认`。
- 右侧使用 Lucide `ImagePlus` 的仅图标图片上传快捷按钮，图标按钮必须提供 `aria-label="上传图片"` 和悬停提示。
- 点击图片快捷按钮时先打开对话框，再触发现有图片文件选择器；用户选择文件后进入图片模式。
- 导入栏不重复展示主题名称、空候选区和来源语境。

列表搜索、状态筛选、来源筛选、排序、分页和卡片行保持现状。

## 对话框结构

桌面端对话框宽度使用响应式约束 `min(800px, calc(100vw - 32px))`，最大高度为 `80vh`。标题区固定在顶部，操作区固定在底部，中间内容独立滚动，候选词增加时不推动整个页面。

对话框按以下顺序组织：

1. 标题“导入单词”和关闭按钮。
2. 文本录入、图片识别两个分段模式按钮。
3. 当前模式的输入区。
4. 生成主题选择和“管理主题”入口。
5. 候选词复核区，包含排序、全选、清空、编辑、拼写建议处理和删除。
6. 可折叠的来源语境。
7. 左侧状态或错误信息，右侧“生成卡片”主按钮。

不把候选确认拆成第二个弹窗或独立页面。图片上传、识别和纠错仍在同一个对话框完成，避免用户在多个容器之间来回切换。

### 候选词排序

候选词复核区标题右侧提供两段式排序控件：

- `录入顺序`：默认选项，按文本出现顺序或图片模型返回顺序展示；后续合并的候选词追加在末尾。
- `A–Z`：按候选词当前值执行不区分大小写的稳定升序排序；相同词形继续保持原录入顺序。

排序只改变展示顺序，不重排 `candidates` 单一真源，不修改候选 ID、来源批次、图片识别 metadata 或提交分组。用户在 `A–Z` 模式下编辑词条后，列表按新的词形立即重新排序；删除、选择、采用建议和保留原词继续通过候选 ID 定位。

排序选项只属于当前页面会话，不写入本地存储。关闭再打开对话框时保留当前排序模式，刷新页面后恢复为 `录入顺序`。

## 状态与关闭规则

`VocabularyCapturePanel` 继续作为候选词、主题、模式、来源语境、识别状态和提交状态的单一真源。对话框开关只是展示状态，不复制表单数据。

- 首次进入页面时对话框关闭。
- 点击页面导入按钮后，以文本模式打开。
- 点击图片快捷按钮后，以图片模式打开并触发文件选择。
- 用户关闭有未提交内容的对话框时保留当前页面会话中的草稿，并在紧凑导入栏显示待确认数量。
- 刷新页面后无需恢复草稿，沿用现有会话级状态规则。
- 所有选中候选成功提交后自动关闭对话框并刷新卡片列表。
- 部分提交失败、图片识别失败或存在未处理拼写问题时保持对话框打开，并保留可继续处理的内容。
- 识别或提交进行中禁止关闭对话框，避免请求仍在运行时造成状态不明确。

关闭按钮、遮罩点击和 `Escape` 使用同一套关闭判断。焦点打开后进入标题后的首个可操作控件，关闭后返回触发入口。对话框必须使用原生 `dialog` 或等价的可访问模态语义，并限制键盘焦点留在内部。

## 图片快捷上传

`VocabularyImageCapture` 增加供父组件调用的 `openFilePicker()` 方法；现有 `deactivate()` 保持不变。页面快捷按钮调用流程为：

1. 打开导入对话框。
2. 切换到图片识别模式。
3. 等待图片组件挂载完成。
4. 调用 `openFilePicker()` 打开系统文件选择器。

快捷按钮只负责缩短入口，不改变文件类型、10 MB 上限、单图识别、超时、候选去重或疑似拼写处理规则。移动端拍照入口继续保留在图片模式内部。

## 响应式规则

- 宽度大于 620 px：居中宽对话框，顶部和底部固定，中间滚动。
- 宽度不大于 620 px：对话框占满视口，不使用悬浮卡片外观；模式按钮、主题选择和主按钮适配单列布局。
- 桌面和移动端都不允许页面背景在模态打开时滚动。
- 长单词、长文件名、错误信息和候选来源必须换行或截断，不能撑破对话框。

## 错误与空状态

- 没有候选词时，对话框展示当前输入模式，不在页面常态展示大面积空状态。
- 主题加载失败时允许关闭对话框和浏览已有卡片，主题选择区就地显示错误。
- 图片识别失败时保留图片，继续提供重试和更换图片。
- 生成失败时保留未完成候选和错误信息，不自动关闭。
- 已成功生成的候选从列表移除；若仍有失败候选，页面入口栏显示剩余数量。

## 组件边界

- `VocabularyCapturePanel`：增加入口栏、模态开关、关闭判断和提交完成后的关闭行为；继续编排原有子组件。
- `VocabularyImageCapture`：只新增公开文件选择方法，不承担模态状态。
- `VocabularyTermReview`：增加排序控件所需的当前模式和切换事件；候选词操作事件仍使用候选 ID。
- `VocabularyTextCapture`、`VocabularyThemeSelect`：保持职责和数据契约不变。
- `VocabularyView`：继续组合导入面板和卡片列表，不保存导入草稿。

首版不抽取全局 Modal 组件。当前对话框只服务单词导入，先使用组件内结构和现有 CSS 变量；待第二个真实业务场景出现后再评估通用抽象。

前端新增 `lucide-vue-next` 依赖，并按图标组件单独导入，避免继续增加手写 SVG 或字符图标。

## 测试与验收

### 组件与静态测试

- 页面常态只显示紧凑导入栏，不渲染可见的大输入工作区。
- 点击“导入单词”后显示具有可访问名称的对话框。
- 点击图片快捷按钮后打开对话框、切换图片模式并调用文件选择器。
- 有草稿时关闭再打开，文本、候选词、主题和来源语境仍保留。
- `录入顺序`保留原顺序，`A–Z`执行不区分大小写的稳定排序，切换排序不改变提交顺序和来源信息。
- 在 `A–Z` 模式编辑词形后重新定位，删除和拼写处理仍命中原候选 ID。
- 提交全部成功后关闭；部分失败后保持打开。
- 请求进行中关闭按钮、遮罩关闭和 `Escape` 均不生效。

### 端到端测试

- 文本录入：打开、输入、选择主题、确认候选、生成卡片并返回列表。
- 图片识别：快捷上传、模拟识别、处理疑似拼写、生成卡片。
- 错误恢复：主题失败、识别失败、部分生成失败时对话框保留正确状态。
- 键盘：入口可聚焦，`Escape` 可关闭空闲对话框，关闭后焦点回到触发按钮。
- 响应式：桌面 1280 x 900 和移动 390 x 844 下无横向溢出、遮挡或文字覆盖。

## 非目标

- 不修改 Java、Python、Prompt、数据库或 API。
- 不增加多图、PDF、拖拽上传或剪贴板图片粘贴。
- 不持久化未提交导入草稿。
- 不改变主题定义、卡片 Markdown 结构或卡片详情页。
- 不重构卡片列表和筛选器。

## 文档影响

这是前端信息架构调整，不改变长期架构和接口。图片导入工作区设计文档已链接本设计；无需修改 API、部署或模型配置文档。

# 考试写作命题对话工作台设计规格

## 1. 目标

将当前 `ExamSetupPage` 从“单输入框 + 附件卡片 + 手动整理题单”的页面，升级为一个真正的命题对话工作台。

新的页面主目标是：

- 左侧像聊天窗口一样持续推进题目设计
- 右侧持续展示当前题单草稿
- 用户通过多轮对话、附件补充和系统追问，逐步把题目打磨完整

页面不再强调“一次性提交一个大表单”，而强调“多轮策划并实时出题单”。

## 2. 核心产品定义

### 2.1 左侧是命题对话，不是表单

左侧主区域改为命题对话流。

用户可以：

- 输入题目意图
- 继续补充限制条件
- 上传图片或材料
- 插入历年真题
- 纠正系统误解

系统会：

- 理解用户当前意图
- 主动追问缺失信息
- 给出命题建议
- 同步刷新右侧题单

### 2.2 右侧是当前题单草稿纸

右侧继续保留纸面题单风格，但语义调整为：

- 不是“最终成品”
- 而是“当前命题草稿”

右侧随左侧每轮对话自动刷新，并显示当前是否：

- 空白
- 草稿中
- 已整理完成

### 2.3 会话是临时的

本次设计明确不做长期会话管理。

规则：

- 只保留当前题目设计页的临时对话历史
- 进入写作后结束本次命题会话
- 不做跨页面恢复
- 不做历史命题会话列表

## 3. 方案选择结果

本次已确认采用：

- 方案：`命题对话工作台`
- 左侧交互角色：`对话策划师`
- 追问策略：`主动一次性追问多个关键维度`
- 右侧联动：`每轮对话后自动刷新`
- 对话保留：`仅当前设计页内有效`
- 附件表现：`作为独立消息插入对话流`

不采用：

- 轻量聊天壳
- 右侧可编辑题单草稿
- 历史命题会话体系

## 4. 页面结构

### 4.1 总体布局

页面保持左右双栏：

- 左侧：`命题对话区`
- 右侧：`题单预览区`

页面头部继续保留：

- 返回作文列表
- 模式切换（自由模式 / 考试模式）
- 开始写作按钮

### 4.2 左侧职责

左侧只负责命题过程，不负责最终题单的视觉纸面排版。

左侧包括：

- 消息历史区
- 底部输入区
- 附件入口
- 模型选择
- 发送按钮

### 4.3 右侧职责

右侧只负责展示当前题单结果，不承担自由对话行为。

右侧包括：

- 题单状态提示
- Directions 题面区域
- 附件渲染区域
- 草稿态/完成态提示

## 5. 左侧消息模型

左侧消息统一收敛为 4 类。

### 5.1 `user_text`

用户发送的文本需求，例如：

- 我想练一道考研英语二的看图作文
- 不要改我图片里的原题
- 再补一个材料

表现形式：

- 右对齐
- 用户气泡样式
- 保留原文，不做压缩总结

### 5.2 `user_asset`

用户添加的附件消息，作为独立消息插入时间流。

支持三类：

- 图片附件
- 材料文件
- 历年真题

#### 图片消息卡

包含：

- 缩略图
- 标签：`图片附件`
- 操作：`识别文字 / 更换图片 / 移除`

#### 材料消息卡

包含：

- 文件名
- 摘要文本
- 标签：`材料附件`

#### 真题消息卡

包含：

- 年份 / 卷别
- 题干摘要
- 标签：`历年真题`

### 5.3 `assistant_reply`

系统正式回复消息，固定使用三段结构：

1. `理解`
2. `追问 / 补全建议`
3. `当前整理动作`

系统不再只是输出一个题目结果，而是要像命题助手一样推进任务。

### 5.4 `assistant_status`

轻量状态提示，不作为正式回复。

例如：

- `正在整理题单...`
- `已根据新输入刷新右侧预览`
- `当前信息不足，已生成草稿态题单`

状态消息使用更轻的提示条，不应和正式系统回复混淆。

## 6. 左侧交互规则

### 6.1 用户交互主循环

每轮交互遵循固定流程：

1. 用户发送一条文本消息或插入一个附件消息
2. 左侧立即记录该条消息
3. 系统进入整理状态
4. 系统返回一条 `assistant_reply`
5. 右侧自动刷新为最新题单

### 6.2 系统追问策略

系统采用主动追问策略，而不是只追问一个点。

优先补全的信息包括：

- 学段
- 题型
- 体裁
- 字数
- 是否保留原题表述
- 是否需要材料 / 图片共同参与命题

系统追问必须和右侧当前缺口一致，避免左侧和右侧各说各话。

### 6.3 输入区形态

底部输入区改为标准聊天输入区，而不是大表单 textarea。

建议结构：

- 顶部：当前待发送附件状态
- 中间：可增长输入框
- 底部左侧：
  - 附件入口
  - 模型选择
- 底部右侧：
  - 发送按钮

输入框规则：

- 默认 2 行
- 最多扩展到 6-8 行
- 超出后内部滚动

### 6.4 附件入口

保留现有 `+` 菜单，但附件不再停留在输入框上方的静态卡片区，而是进入消息历史。

菜单项保持：

- `添加图片和文件`
- `历年真题`

## 7. 右侧题单状态设计

右侧题单区改为三态。

### 7.1 空白态

适用于：

- 页面初始状态
- 尚未开始任何命题对话

表现：

- 保留 `Directions:`
- 显示轻提示：请在左侧描述题目需求，或上传附件开始整理

### 7.2 草稿态

适用于：

- 左侧已有输入
- 但信息仍不完整

表现：

- 顶部显示状态条：`草稿中`
- 显示当前缺口，例如：
  - `待补充字数`
  - `待确认学段`
  - `待确认是否保留原题表述`
- 题单正文照常渲染当前可确定内容
- 缺失字段明确标识为 `待确认`

草稿态是本次设计的关键状态，目的是让用户在信息尚未完整时也能看到系统整理结果。

### 7.3 完成态

适用于：

- 当前题单已具备进入写作的最小必要信息

完成态判定的最小集合：

- 有题干方向
- 有题型
- 有基本写作要求
- 有字数或系统默认字数
- 有学段或系统默认学段

表现：

- 状态条显示 `已整理完成`
- 右侧显示完整题单
- 开始写作按钮可用

## 8. 左右联动规则

### 8.1 自动刷新

本次已确认右侧采用自动刷新。

规则：

1. 用户每提交一轮对话，右侧立即进入 `整理中`
2. 系统回复完成后，右侧自动刷新
3. 如果信息不足，刷新为草稿态
4. 如果信息足够，刷新为完成态

### 8.2 缺口同步

右侧状态条中显示的缺口，必须由左侧系统回复同步追问。

例如：

- 右侧显示 `待补充字数`
- 左侧系统回复中就必须明确追问字数要求

这样用户能清楚理解：

- 为什么右侧还没有完成
- 当前下一步应该补什么

## 9. 开始写作按钮规则

按钮状态与右侧题单状态绑定。

### 9.1 禁用状态

以下状态下禁用：

- 空白态
- 草稿态
- 整理中

### 9.2 可用状态

仅在完成态启用。

第一版不支持“草稿态强行进入写作”，避免把未定稿题目带入写作页。

## 10. 数据结构调整建议

当前 `ExamSetupPage` 主要是单输入值驱动，需要收敛为对话驱动状态。

建议新增页面级消息数组，例如：

- `messages: WorkbenchMessage[]`

消息结构建议包括：

- `id`
- `role`
- `kind`
- `text`
- `assetType`
- `assetPayload`
- `status`
- `createdAt`

其中：

- `role`: `user | assistant | system`
- `kind`: `text | asset | status`

注意：

- 这是页面内临时状态
- 本期不要求后端持久化会话

## 11. 非目标

本阶段明确不做：

- 多会话管理
- 历史命题会话恢复
- 右侧题单手工编辑
- 多版本题单对比
- 长期保存题目设计对话
- 多图并存上传

其中图片策略保持：

- 单图附件模型
- 允许反复更换当前图片

## 12. 实现优先级建议

建议分四步完成：

1. 将左侧状态从单输入框收敛为消息数组
2. 将图片 / 材料 / 真题接入消息流
3. 将系统回复改为多轮 assistant message
4. 将右侧改成空白态 / 草稿态 / 完成态三态自动刷新

## 13. 测试重点

后续实现时应重点验证：

- 文本对话能连续追加消息
- 附件能作为消息插入历史
- 每轮系统回复后右侧会自动刷新
- 信息不足时右侧进入草稿态
- 信息足够时右侧进入完成态
- 开始写作按钮只在完成态启用
- 更换图片后旧图片不会污染当前会话
- 模型选择会作用于审题与识图链路

## 14. 与现有能力的兼容要求

本次改造必须保留当前已有能力：

- 图片识别
- 历年真题插入
- 模型选择
- 右侧题单纸面预览
- 自由模式 / 考试模式切换

改动重点是交互形态和状态组织，不是推翻现有题单生成链路。

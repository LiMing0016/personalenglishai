# 单词卡笔记章节式全页详情设计

## 当前结论

单词卡详情采用独立全页的“笔记章节”布局。用户从单词库点击卡片后进入 `/app/vocabulary/cards/:cardUid`，页面不再同时展示批量录入、卡片列表和狭窄右侧详情栏。正文默认显示安全渲染后的 Markdown；只有进入编辑模式时才显示 Markdown 源码。

详情页保留现有核心 JSON、Markdown、来源、历史、重新生成、冲突处理和删除能力。本次只调整前端信息架构和展示组件，不修改数据库、后端 API 或卡片内容契约。

## 背景与问题

当前 `/app/vocabulary/cards/:cardUid` 仍复用单词卡中心的两列布局：左侧是批量录入和列表，右侧详情宽度被限制在 `230px` 至 `300px`。单词卡的主要学习内容因此被压缩到辅助区域。

`VocabularyMarkdownEditor` 在只读状态下仍使用 `textarea` 展示 Markdown 源码，导致用户需要阅读标记符号，长内容也缺少标题层级、段落节奏和章节导航。卡片内容已经生成成功，但阅读体验不像学习笔记，也无法承载后续更丰富的主题内容。

## 目标与非目标

### 目标

- 让单词卡正文成为详情页的主要内容。
- 默认渲染 Markdown，编辑时才显示源码。
- 使用章节导航组织不同主题产生的长短不一内容。
- 保留核心 JSON 的统一展示，不让 Markdown 重复承担单词身份字段。
- 保持现有生成、重试、主题切换、冲突处理、来源和历史行为兼容。
- 桌面、窄屏和手机均无内容重叠、横向溢出或按钮挤压。
- 不新增 Markdown 运行时依赖，复用现有安全解析能力。

### 非目标

- 修改主题 Prompt、生成质量或模型配置。
- 修改核心 JSON、Markdown、卡片版本或主题版本的数据结构。
- 新增个人笔记字段、章节拖拽、富文本编辑器或卡片皮肤。
- 把 Markdown 章节转换成专用业务组件。
- 在本次改动中重构整个 `VocabularyView.vue` 或单词沉淀状态层。

## 页面信息架构

### 单词库路由

`/app/vocabulary?tab=collection` 只展示单词沉淀工作区：主题选择、批量录入、过滤器和卡片列表。点击卡片进入详情路由，不在列表页继续渲染详情栏。

### 单词卡详情路由

当 `:cardUid` 是以 `card_` 开头的持久化卡片 ID 时，`/app/vocabulary/cards/:cardUid` 使用以下纵向结构：

1. 顶部工具栏：返回单词库、阅读/编辑模式、主题选择、重新生成、保存和更多操作。
2. 单词标题区：单词、音标、词性、状态和当前主题。
3. 左侧章节导航：核心信息、Markdown 二级标题、来源、历史。
4. 中间阅读正文：核心 JSON 摘要和主题 Markdown 内容。
5. 页面级状态：生成进度、部分成功、失败、冲突和删除确认。

详情正文最大宽度保持在适合阅读的范围内，而不是铺满超宽屏。左侧导航只承担定位功能，不与正文竞争视觉层级。

### 旧链接兼容

历史版本允许把普通单词放在 `/app/vocabulary/cards/:cardUid` 参数中，并把它解释为单词库关键词。这个行为继续保留：

- 参数以 `card_` 开头时进入全页详情。
- 参数不是持久化卡片 ID 时继续进入单词库，并由 `legacyVocabularyCardKeyword()` 写入列表关键词。
- 旧关键词链接不请求卡片详情，也不显示全页详情的加载或失败状态。
- 本次不删除兼容函数和现有路由测试；后续若要迁移为查询参数，需要单独设计链接迁移和重定向策略。

## 章节导航规则

章节导航由当前卡片内容动态生成：

- `核心信息` 始终存在。
- Markdown 中的 `##` 标题按原顺序成为主题章节。
- `来源` 在存在来源数据时显示。
- `历史` 在存在版本数据时显示。
- Markdown 为空时不生成主题章节，正文显示可执行的空状态。
- Markdown 中出现“个人笔记”等标题时自然成为章节；本次不新增独立个人笔记字段。

每个导航项对应稳定的页面锚点。Markdown 章节按出现顺序使用 `markdown-section-1`、`markdown-section-2` 等页面内 ID，因此两个同名的 `## 例句` 也会得到不同锚点。点击后滚动窗口到章节；页面滚动时使用 `IntersectionObserver` 观察正文标题并同步高亮当前章节，不创建独立滚动容器。锚点只存在于渲染结果中，不修改保存的 Markdown 源码。

桌面端左侧导航在内容滚动时保持可见。中等屏幕和手机端改为正文顶部的横向章节导航，避免固定侧栏压缩内容。

## 阅读与编辑模式

### 阅读模式

阅读模式是默认状态：

- 核心 JSON 渲染为单词、音标、词性和释义摘要。
- Markdown 渲染标题、段落、列表、引用、表格、代码块和强调文本。
- 不显示字符计数或“保留 Markdown 源码格式”等编辑提示。
- 原始 HTML 始终转义，包括 Markdown 中的 `<br>`；不执行脚本、事件属性或 iframe。
- 单词卡正文不自动加载 Markdown 图片；图片语法退化为可读替代文本。

### 编辑模式

点击“编辑”后，只把主题 Markdown 内容切换为源码编辑器：

- 核心 JSON 在本次仍保持只读。
- 顶部操作切换为“取消”和“保存”。
- 字符计数和 20,000 字限制仅在编辑模式显示。
- 取消编辑恢复当前活跃版本，不发请求。
- 保存沿用 `baseRevisionUid` 乐观并发契约。
- 保存成功后返回阅读模式并刷新章节导航。
- 保存发生版本冲突时继续使用现有冲突处理流程，不覆盖服务端新版本。

路由切换到另一张卡片或活跃版本变化时，继续使用现有草稿身份规则重置编辑内容，避免卡片间串稿。

## 操作区设计

顶部工具栏保持紧凑，按频率分层：

- 主操作：阅读/编辑切换、保存、重新生成。
- 次操作：主题选择、重试生成。
- 低频危险操作：删除，放入“更多”菜单或独立危险区。

更换主题或使用更新主题版本重新生成时，继续显示确认对话框。重新生成失败不清空当前可用正文。删除成功后返回单词库。

窄屏下主操作保留可见，主题切换和删除进入更多菜单；按钮使用现有项目的尺寸、边框、颜色和圆角，不建立新的视觉系统。

## 组件边界

### `VocabularyView.vue`

继续负责单词模块的路由编排和现有查询接线：

- 列表路由渲染捕获面板和卡片列表。
- 卡片路由只渲染全页详情状态和详情组件。
- 不在全页详情路由创建第二份卡片状态源。

### `VocabularyCardInspector.vue`

保留现有卡片、mutation 和冲突处理能力，但从“右侧检查器”调整为全页详情内容组件。当前未被使用的必填 `template` 和 `templates` props 移除，`selectedVocabularyTemplate` 不再作为详情渲染门槛。卡片详情可以在旧模板查询加载失败、模板已下线或 `templateKey` 无法匹配时正常显示；主题名称优先读取卡片详情中的主题快照，缺失时显示通用回退文案。内部拆出清晰区域，避免继续把标题、操作、核心内容、Markdown、来源、历史和对话框全部堆在单一模板中。

### `VocabularyMarkdownRenderer.vue`

新增只读渲染组件，职责仅为：

- 接收 Markdown 字符串。
- 输出安全 HTML。
- 提取二级标题和唯一锚点。
- 向父组件提供章节元数据。
- 处理空内容展示。

渲染工具的公开结果固定为：

```ts
interface VocabularyMarkdownDocument {
  html: string
  sections: Array<{
    id: string
    title: string
    level: 2
  }>
}
```

`sections` 只包含二级标题，`id` 按标题出现顺序生成，`title` 是移除 Markdown 强调和代码标记后的可读文本。

### `VocabularyMarkdownEditor.vue`

只在编辑模式使用，继续负责源码输入、字符计数和长度校验，不再承担只读展示。

### 共享 Markdown 工具

复用 `web/src/components/assistant/markdown.ts` 已有的转义和基础 Markdown 解析能力，并把需要的解析函数提取为可配置的共享边界。共享解析器增加显式选项，例如 `allowImages`、`allowHtmlBreaks` 和 `headingAnchors`：

- 现有 `renderAssistantMarkdown` 继续使用 `allowHtmlBreaks: true`，保持助手内容和已有 `<br>` 测试不变。
- 单词卡使用 `allowImages: false`、`allowHtmlBreaks: false` 和 `headingAnchors: true`。
- 严格模式下 `<br>` 只显示为转义文本，不重新转成 HTML 元素。

不得直接把未经转义的 AI 输出交给 `v-html`，也不新增 `marked`、`markdown-it` 等依赖。

## 数据流

1. 路由参数先区分持久化 `cardUid` 与旧关键词；只有持久化 ID 才进入详情数据流。
2. `useVocabularyCards` 继续加载卡片详情和版本历史，并在生成期间轮询。
3. 详情组件从 `core` 读取统一词典信息；旧卡片继续通过现有兼容投影读取。
4. Markdown 渲染器从 `markdown` 或兼容内容读取正文，生成安全 HTML 和章节元数据。
5. 页面合并固定章节与 Markdown 章节，驱动导航和滚动定位。
6. 编辑保存、重新生成、重试、删除和冲突解决继续调用现有 mutation。
7. mutation 成功后沿用 TanStack Query 失效策略刷新详情、历史和列表缓存。

不新增 Pinia store、storage key 或组件内详情镜像。服务端数据继续由 TanStack Query 管理，只有尚未保存的 Markdown 草稿保留在组件本地。

## 状态与错误处理

### 加载与不存在

- 详情加载中显示稳定尺寸的页面骨架，不回退到列表加空右栏，也不等待旧模板查询。
- 详情请求失败显示返回和重试操作。
- 卡片不存在或无权限时使用明确的不可用状态，不无限轮询。

### 生成状态

- `captured` / `generating`：标题区显示生成中，正文保留已有活跃版本；无活跃版本时显示生成占位。
- `ready`：展示完整核心信息和 Markdown。
- `needs_review`：在正文上方显示待确认原因，冲突候选仍通过现有对话框处理。
- `failed`：已有活跃版本时继续可读并提示本次生成失败；没有活跃版本时显示重试入口。
- Markdown 部分失败：核心信息保持可读，主题内容区显示“待完善”和重试操作。

### 交互错误

保存、重新生成、重试和删除失败继续使用现有 toast；需要用户决策的主题版本变化、删除和版本冲突使用对话框。技术错误码不直接占据正文主区域。

## 响应式与可访问性

- 桌面宽屏：左侧章节导航加居中正文，正文建议宽度 `760px` 至 `880px`。
- 中等屏幕：章节导航移动到正文顶部并允许横向滚动。
- 手机：标题、状态和操作自然换行；低频操作收入口；正文占满可用宽度。
- 标题、章节导航、模式切换和对话框使用语义元素和明确的可访问名称。
- 当前章节通过视觉状态和 `aria-current` 表达。
- 键盘用户可以遍历章节导航、模式切换、重新生成和保存。
- 内容加载、生成状态和保存结果使用合适的 `aria-live`，避免重复播报轮询。
- 所有固定尺寸均使用响应式约束，长单词、长主题名和长标题不得撑破容器。

## 测试与验收

### 单元与组件测试

- Markdown 原始 HTML 被转义，危险内容不执行。
- 标题提取、重复标题唯一锚点和无标题 Markdown 正确。
- 单词卡配置不自动加载 Markdown 图片。
- 阅读/编辑切换、取消、保存和长度限制正确。
- 活跃版本变化时草稿重置，当前未变化时不误重置。
- 不同生成状态显示正确，已有版本不会被失败任务遮蔽。
- 来源和历史为空时不出现空章节。

### 路由与查询测试

- 列表路由不渲染详情栏。
- 卡片路由不渲染捕获面板和卡片列表。
- 从列表进入详情、返回列表、直接刷新详情均正常。
- 生成轮询、保存失效、重新生成、重试、删除和冲突解决沿用现有查询键。

### 视觉验收

在 `1440x900`、`1024x768` 和 `390x844` 检查：

- 正文是页面主要视觉区域。
- Markdown 默认呈现为可读文档而不是 textarea。
- 章节导航不遮挡标题或正文。
- 长单词、长主题名、长章节标题和 20,000 字内容不造成横向溢出。
- 顶部操作不重叠，手机端主要动作可见。
- 来源、历史、确认对话框和冲突对话框仍可完整使用。

### 端到端验收

1. 从单词库打开已就绪的 `supposed`，确认进入独立全页详情。
2. 使用左侧章节导航定位核心信息和 Markdown 章节。
3. 切换编辑模式，修改 Markdown 并保存，返回阅读模式后章节同步更新。
4. 更换主题重新生成，确认旧内容在任务完成前仍可阅读。
5. 模拟 Markdown 生成失败，确认核心信息和重试入口仍可使用。
6. 打开来源和历史，确认当前数据完整。
7. 模拟版本冲突，确认保留当前、采用候选和字段合并流程不回归。
8. 在手机视口完成阅读、编辑、保存和返回。

## 发布与回滚

本次没有数据库或 API 变更，可随前端版本发布。回滚只需恢复旧详情布局和只读 Markdown 展示组件，不影响卡片、主题或版本数据。为降低回归风险，保留现有 mutation 接口和查询键，不并行维护新旧两套详情状态。

## 后续演进

本次阅读体验稳定后，再独立设计：

- 主题章节配置和排序。
- 个人笔记独立字段与版本策略。
- Markdown 章节到学习组件的映射。
- 朗读、标注、复习状态和间隔重复闭环。
